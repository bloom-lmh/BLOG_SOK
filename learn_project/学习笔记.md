## 注解

1. 注解本质：就是给类、方法、字段等添加元信息，让编译、运行时能够读取，从而产生副作用。同时正是因为有了注解才变成声明式驱动
2. 自定义方式：自定义其实就是接口前加一个@
3. 元注解：标注注解的注解，决定注解的行为和作用域

- @target决定注解能贴到什么地方
- @Retension决定注解元数据保留到什么时候：SOURCE 编译时丢弃（@Override），CLASS 保留到字节码但运行期不可见（Lombok 注解，给编译期处理器用），RUNTIME 全程保留、运行期反射可读（Spring 的 @Autowired，Spring 启动时靠反射扫它做注入）
- @Repeatable是否能够在同一位置重复标注多次

3. 注解成员的定义规则

- 成员是抽象方法：String value();，不能有参数、不能有方法体。
- 类型受限：只能是基本类型、String、Class、枚举、注解，以及这些类型的数组。
- value 是特殊成员：如果只有 value 一个成员，使用时可以省略名字，直接 @RequireLogin("需要登录")。
- 默认值用 default：int count() default 1;，有默认值的使用时可省略。

4. spring 中的@RestController

标记类是控制器，spring扫描到后注册成bean，注解本至只是标注，实际是spring容器来完成Bean 注册、依赖注入、路由映射

5. 注解的原理

```js
源码 @Xxx
   │
   ▼ 编译（SOURCE 注解在此被丢弃）
字节码 .class（CLASS 注解保留到这里，运行期丢弃）
   │
   ▼ 运行（RUNTIME 注解一路保留，可反射读）
JVM 运行时
```

6. 使用注解

- 编译时注解Processor，处理抽象语法树注入信息，比如lombok注入getter setter
- 反射读取注解的底层

## 异常

1. 自定义业务异常，异常类基础runtimeException，异常类有两个属性，message和code，也就是异常消息和错误码
2. 全局异常handler：统一处理Controller抛出的异常，本至是AOP切面实现的。spring会把controller封装为代理
