渲染策略：
虚拟节点就是一个中间层，渲染器是平台无关的，vue 内置了浏览器的渲染器，本质上就是在操作 DOM（CRUD）

`vue`将虚拟节点划分为文本节点、元素节点、组件节点、`Fragment` 节点等四种类型（ShapFlags），在`patch`方法中根据位运算来区分不同类型从而做不同的操作，本质上是策略模式的体现。

如果孩子节点都是数组则进行 diff 算法比对更新，在 diff 更新的时候做了优化

1. 双端指针确定最小操作边界
2. 最大限度复用 DOM 节点
3. 最长递增子序列确定不用移动的元素

组件：

1. 组件也是一个虚拟节点，会有 render 方法和 setup 方法。也有状态 data 和生命周期。以及能接受外界传递的属性。
2. 传入组件的属性会进行筛选，defineProps 放入组件实例的 props 属性，其余放入 attrs 中
3. 插槽就是组件的孩子节点，放在组件的 children 属性上

组件更新时，会将更新任务放入任务队列，`queueJob` 主要做了三个工作：

1. 去重：确保相同任务不会重复加入队列；
2. 防重入：通过 `isFlushing` 标志避免在 `flush` 过程中重复调度微任务；
3. 异步批处理：利用 `Promise.resolve().then()` 将任务执行延迟到当前宏任务结束后的微任务阶段，实现高效的批量更新。

这样可以保证，虽然一个组件中触发了多次状态变更，但组件只更新了一次，且使用的是最终状态值。这样就保证了组件的异步的批量的更新

当组件不是首次挂载时，更新操作由以下两种情况触发：

1. 外部驱动：父组件重新渲染，导致传入的 `props` 或 `children`（插槽）发生变更；
2. 内部驱动：组件自身的响应式状态（如 `data、ref、reactive` 等）发生变化，触发其 `render effect` 的重新执行。

所谓的生命周期钩子函数其实就是 patch 递归调用时执行的钩子函数队列

`setup`函数实际上是组件的初始化函数或者说入口函数，它接受两个参数

1. 组件的`props`：外界传来的所声明要接受的属性
2. `setup`上下文对象：
   - 父组件传来的未声明接受的额外属性`attrs`
   - 父组件传来的插槽`slots`
   - `emit`事件派发函数
   - `expose`组件实例要暴露的值

然后它的返回值也有两种情况：

1. 返回渲染器函数：这个函数会将组件对应的虚拟节点渲染出来，其优先级大于组件的`render`函数
2. 返回一般对象：这个对象会作为组件的`setupState`属性

插槽是 Vue 组件的一种扩展机制，它允许子组件的部分内容在父组件中决定。对于插槽的实现而言，正是有了`setup`函数，才让实现插槽变得简单。在源码中其实就是做了两件事情：

1. 将要插入内容作为子组件的孩子（children）属性传入即可，
2. 子组件通过`setup`上下文对象访问父组件传来的插槽内容，然后渲染出来。

emit 事件派发函数其实也是通过 setup 函数上下文对象实现的

对于内置组件：其实所谓的内置组件就是在`patch`的时候将一些底层渲染方法交给这些组件，让其自己决定渲染逻辑

1. teleport：首先根据 to 选择器找到目标元素，然后调用 mountChildren 方法将子节点渲染到目标元素上，如果是更新就是调用 patchChildren 方法更新子节点，如果 to 发生了变化则，则重新获取 to 对应的目标元素，然后将元素移动到新的位置。

模板引用的原理：其实就是在 patch 后（挂载后）将真实的 dom

生命周期原理:

1. 生命周期钩子的本质：从本质来讲，生命周期是对发布订阅模式的一种应用。这些函数通过对应的生命周期注册函数注册到对应的实例上，然后在`patch`特定的阶段进行执行。
2. 生命周期注册器：生命周期注册器，采用了函数柯里化（工厂方法模式）根据不同的生命周期名称，返回不同的注册函数。
