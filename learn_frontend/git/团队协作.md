# 团队协作

## 查看远程仓库信息

> 用于了解当前配置了哪些远程仓库及其状态。

```bash
# 显示所有远程仓库（简略：名称 + URL）
git remote -v

# 显示某个远程仓库的详细信息（如分支跟踪状态、HEAD 指向等）
git remote show [remote]
```

## 管理远程仓库配置

> 添加、修改或删除远程仓库的引用（本地记录的远程地址）。

```bash
# 添加一个新的远程仓库，并指定简称（如 origin, upstream）
git remote add [shortname] [url]
# 修改远程仓库的 URL
git remote set-url [shortname] [new_url]
# 删除远程仓库的引用
git remote rm/remove [shortname]
```

## 从远程获取更新（不自动合并）

> 安全地拉取远程数据到本地，但不改变工作区。

```bash
# 下载远程仓库的所有最新变动（更新远程跟踪分支，如 origin/main）
git fetch [remote]
```

> 只更新 `.git/refs/remotes/`，不影响你当前分支代码，安全可靠。即只会改变远程分支指向，并没有和本地分支合并

## 拉取并合并远程更新（fetch + merge）

> 获取远程变更并立即合并到当前分支。

```bash
# 等价于 git fetch + git merge
git pull [remote] [branch]
```

> 注意：`pull` 是“有副作用”的操作，可能引发冲突，建议理解其本质是 `fetch + merge`（或 `fetch + rebase`，若配置了 `pull.rebase`）。

`git pull`后远程分支会直接与本地的对应分支进行关联，并自动合并。

## 推送本地变更到远程

> 将本地提交上传到远程仓库。

```bash
# 推送本地某分支到远程对应分支
git push [remote] [branch:remote-branch]

# 强制推送（覆盖远程历史，慎用！）
git push [remote] --force
# 更安全的强制推送（仅当你的提交是远程提交的直接后代时才允许）
git push [remote] --force-with-lease

# 推送所有本地分支到远程
git push [remote] --all
```

> 补充：
>
> - 首次推送新分支常用：`git push -u origin branch-name`（设置上游跟踪）
> - 删除远程分支：`git push origin --delete branch-name`
> - 推送的简写形式为`[branch]`，实际上是`[branch:remote-branch]`也就是，将本地哪个分支推送到远程哪个分支

## 总结

| 类别                 | 目的                   | 命令                               |
| -------------------- | ---------------------- | ---------------------------------- |
| **查看远程信息**     | 了解远程仓库配置和状态 | `git remote -v`, `git remote show` |
| **管理远程配置**     | 添加/删除远程仓库地址  | `git remote add`                   |
| **获取更新（安全）** | 下载远程数据但不合并   | `git fetch`                        |
| **拉取并合并**       | 获取并整合远程变更     | `git pull`                         |
| **推送变更**         | 上传本地提交到远程     | `git push`, `--force`, `--all`     |
