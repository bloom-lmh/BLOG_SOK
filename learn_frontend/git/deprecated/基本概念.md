# 基本概念

## 何为版本控制

版本控制是一种记录文件内容变化的系统，能追踪每次修改、回退到任意历史版本，并支持多人协作开发而不互相覆盖。

## 两种版本控制的系统

### 集中式版本控制系统

集中式版本控制是指所有数据都集中存储在一个中心服务器或数据中心。用户通过网络连接到这个中心位置，进行数据的访问、修改和共享。这种方式要求服务器具有高度的可靠性和稳定性，以确保数据的完整性和安全性。

![集中式版本控制](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251211194358836.png)

集中式版本控制，用户需要下载集中式管理服务器上的文件在本地修改后再上传，这种方式必然会导致许多的问题

1. 丢失修改问题：当多个用户同时操作一个文件时后面的用户修改的内容会覆盖前面的用户所修改的内容，比如下面`lisi`提交的文件会覆盖`zhangsan`修改的文件，`wangwu`提交的文件会覆盖`lisi`修改的文件，最终文件以`wangwu`修改为准

![丢失修改问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251211194520934.png)

2. 同步效率低下的问题：为了解决丢失修改的问题，集中式版本管理工具 vss 为版本控制引入了锁的概念，将文件变为了临界资源。这样虽然能够解决丢失修改的问题，但是又带来了新的问题，即对文件的修改是同步的，降低了软件开发的并发性，影响了软件开发的效率

![同步效率低下的问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212085028105.png)

3. 无法解决多人开发问题：为了解决这一问题，集中式版本管理工具 `cvs` 和 `svn` 允许不同的用户同时修改同一个文件，但是会事先规定用户能修改的部分。这样确实提高了开发的效率，但不能解决多个用户修改同一文件同一部分的问题

![法解决多人开发问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212085106808.png)

4. 服务器宕机问题：并且无论是什么样的集中式版本管理软件都无法规避一台中央服务器宕机带来的影响。所以我们提出来分布式版本控制

![服务器宕机问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212085214185.png)

### 分布式版本控制

上面说到了集中式版本控制并不能很好的解决服务器宕机和文件协同开发的问题，于是提出了分布式版本控制，分布式版本控制就是指数据存储在多个位置，每个位置都有其独立的副本或分片。用户可以直接访问本地存储的数据，无需每次都通过中心服务器。这种方式增加了数据的冗余性，提高了系统的容错能力。比如下图用户将中央服务器的文件资料复制到本地仓库，用户通过客户端直接修改的是本地仓库的数据而不是中央服务器的数据，这样即便中央服务器宕机也不影响实际的开发进度，等到中央服务器恢复又可以将数据合并同步到中央服务器
![分布式版本控制](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212085327890.png)

## GIT 分布式版本控制系统

### 基本概念

`Git` 是目前最流行且强大的版本控制系统之一。它最初是为管理 `Linux` 内核开发而设计的，现在已经被广泛应用于各种规模的软件开发项目。`Git` 采用分布式版本控制，每个开发者都可以在自己的本地仓库中独立工作，然后再将更改推送到远程仓库，或者从远程仓库拉取最新的更改。`Git` 支持强大的分支和合并功能，使得并行开发和代码协作变得更加容易。

### 工作区、暂存区和版本库

![工作区、暂存区和版本库](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251210215309579.png)

1. 工作区：就是你本地写代码的地方
2. 暂存区：暂存区就是存储你将要提交的文件。英文叫 `stage` 或 `index`。一般存放在 `.git` 目录下的 `index` 文件（`.git/index`）中，所以我们把暂存区有时也叫作索引（`index`）
3. 版本库：工作区有一个隐藏目录 `.git`，这个不算工作区，而是 `Git` 的版本库，就是存放版本记录的地方，里面存放了所有提交过的版本。
4. 远端库：比如`github`等远程的仓库

工作目录的文件通过 `git add` 进入暂存区，再通过 `git commit` 进入 `Git` 仓库。
