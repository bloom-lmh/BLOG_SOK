# 分支管理

## 基本概念

分支就是基于某个版本来进行开发的路径，不同路径相互隔离。

## 创建分支

```shell
# 新建一个分支，但依然停留在当前分支
$ git branch [branch-name]
# 新建一个分支，并切换到该分支
$ git checkout -b [branch]
# 新建一个分支，指向指定commit
$ git branch [branch] [commit]
# 新建一个分支，与指定的远程分支建立追踪关系
$ git branch --track [branch] [remote-branch]
```

## 查看分支

```bash
# 列出所有本地分支
$ git branch
# 列出所有远程分支
$ git branch -r
# 列出所有本地分支和远程分支
$ git branch -a
```

## 切换分支

```shell
# 切换到指定分支，并更新工作区
$ git checkout [branch-name]
# 切换到上一个分支
$ git checkout -
```

## 合并分支

```shell
# 合并指定分支到当前分支
$ git merge [branch]
# 选择一个commit，合并进当前分支
$ git cherry-pick [commit]

```

## 删除分支

```shell
# 删除分支但要与主分支先合并

$ git branch -d [branch-name]

# 强制删除分支即便还没有进行合并

$ git branch -D [branch-name]

# 删除远程分支

$ git push origin --delete [branch-name]
$ git push origin :[branch-name]
$ git branch -dr [remote/branch]
```

## 远程同步

```shell
# 建立追踪关系，在现有分支与指定的远程分支之间
$ git branch --set-upstream [branch] [remote-branch]
```

## 代码冲突

两个分支对同一文件的同一区域（或相互依赖的区域）做了不同的修改，且 Git 无法自动判断应该保留哪一边的改动，就会出现代码冲突。此时需要手动解决冲突。

比如在`repo_branch_v1`分支和`repo_branch_v2`分支下都有一个`common.txt`文件且两个文件在同一区域有不同的内容，若进行合并会导致自动合并失败（展示`master|MERGING`标志），也就是说两个分支在合并时出现了冲突，需要手动进行合并。
