# 基本概念

## 何为版本控制

版本控制是一种记录文件内容变化的系统，能追踪每次修改、回退到任意历史版本，并支持多人协作开发而不互相覆盖。

## 两种版本控制的系统

### 集中式版本控制系统

集中式版本控制是指所有数据都集中存储在一个中心服务器或数据中心。用户通过网络连接到这个中心位置，进行数据的访问、修改和共享。这种方式要求服务器具有高度的可靠性和稳定性，以确保数据的完整性和安全性。

![集中式版本控制](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251211194358836.png)

集中式版本控制，用户需要下载集中式管理服务器上的文件在本地修改后再上传，这种方式必然会导致许多的问题

1. 丢失修改问题：当多个用户同时操作一个文件时后面的用户修改的内容会覆盖前面的用户所修改的内容，比如下面`lisi`提交的文件会覆盖`zhangsan`修改的文件，`wangwu`提交的文件会覆盖`lisi`修改的文件，最终文件以`wangwu`修改为准

![丢失修改问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251211194520934.png)

### 分布式版本控制

### 与 SVN 的区别

![与 SVN 的区别](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/image-20220907110331660.png)

- `SVN`：`SVN`是集中式版本控制系统，版本库是集中放在中央服务器的，工作的时候先要从中央服务器得到最新的版本，然后工作，完成工作后，需要把自己的代码推送到中央服务器。集中式版本控制系统是必须联网才能工作。
- `Git`： `Git`是分布式版本控制系统，没有中央服务器，每个人的电脑就是一个完整的版本库，工作的时候不需要联网了，因为版本都在自己电脑上，可以离线工作。

### 文件追踪

只要一个文件曾经被提交过，它就会被`Git`所追踪。除非你显式地用 `git rm` 把它从 `Git` 中删除。

## 基本使用

### 设置用户签名

> 签名的作用就是用来标识用户，以区分不同的开发人员。

```shell
git config --global user.email "you@example.com"
git config --global user.name "Your Name"
```

### 初始化本地库

如果我们希望一个文件夹拥有版本控制的能力，就需要让该文件夹被 `git` 接管，这个过程叫做**git 初始化**，在该文件下输入命令：`git init`，即可完成初始化。此时该文件夹下会出现一个 `.git` 的隐藏文件夹，里面存放着版本控制的相关信息。
