# 版本区管理

## 提交版本

我们使用 `git commit` 这个指令提交暂存区的内容到历史区。所谓的提交文件到版本区（仓库/历史区），就是说记录了文件的快照，为文件创建了版本号。比如：

可以看到 `git add` 操作后，`refs` 文件中个 `heads` 文件夹为空，这是因为文件只是在暂存区但是并没有被提交到仓库
![`git add` 操作后](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212151945997.png)

当我们提交文件后我们可以看到 `HEAD` 文件指向了 `refs/heads` 下的 `master` 文件，而 `master` 文件内容指向了一个 `54` 开头的版本号，这个版本号指向最新一次提交的信息文件

![提交后](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212152541406.png)

也就是说当只有一个分支时，`master` 和 `HEAD` 指针默认指向最新一次提交。
![ master 和 HEAD 指针](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251211104704632.png)

有关提交的命令如下：

```shell
# 提交暂存区到仓库区
$ git commit -m [message]
# 提交暂存区的指定文件到仓库区
$ git commit [file1] [file2] ... -m [message]
# 提交工作区自上次commit之后的变化，直接到仓库区
$ git commit -a
# 提交时显示所有diff信息
$ git commit -v
# 使用一次新的commit，替代上一次提交
# 如果代码没有任何新变化，则用来改写上一次commit的提交信息
$ git commit --amend -m [message]
# 重做上一次commit，并包括指定文件的新变化，不需要再提交暂存区
$ git commit --amend [file1] [file2] ...
```

## 版本回退

### git reset

1. 回退到某个版本：我们使用 `git reset --hard 版本编号` 进行历史版本号的回退。所谓的回滚版本就是让`HEAD`指针移动指向不同的版本。此时工作区文件会发生变化

```shell
# 回退到上一次提交的版本
$ git reset --hard HEAD^

# 回退到上上次提交的版本
$ git reset --hard HEAD^^
$ git reset --hard HEAD~2

# 回退到指定版本
$ git reset --hard 版本编号
```

2. 回退到暂存区：使用 `git reset --soft 版本编号` 指令可以将某个版本回退暂存区。此时工作区文件不会发生变化

::: tip 意义
比如我第一次提交了 `A` 功能代码，此时产生了一次版本。然后我又去开发 `B` 功能，此时发现 `A` 功能有 `BUG` 于是我又修复了 `A` 功能的代码，此时我又提交了一次版本。这时 `A` 功能就提交了两次。然而我们希望只提交一次版本，所以我们就可以把第一次提交的 `A` 功能代码撤回到暂存区，然后修复了`BUG`后把修复`BUG`的版本提交暂存区，最后一次性提交。这样就可以只保留最后一次提交的 `A` 功能代码。也就是说，暂存区的作用就是用来暂存我们即将提交的修改，直到最后一起提交到版本库。
:::

### git revert

![git revert](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251211112610423.png)

- `git reset` 是回滚到对应的 `commit-id`，相当于是删除了 `commit-id` 以后的所有的提交，并且不会产生新的 `commit-id` 记录，如果要推送到远程服务器的话，需要强制推送`-f`
- `git revert` 是做撤销其中的 `commit-id`，然后重新生成一个 `commit-id`。本身不会对其他的提交 `commit-id` 产生影响，如果要推送到远程服务器的话，就是普通的操作 `git push` 就好了

## 查看版本

当我们想要查看某个版本信息可以使用`git cat-file -p 文件名（版本号）`。比如我输入`git cat-file -p 898b7d33ddbd96440449094fcac11e09a2e75b79`，信息展示为：

```shell
#
tree 748e2b696508e2ff557acebb030b83d59c7a5b81
# 上次提交的版本号
parent 705601e50daf250232034a89110fc4a37c74e93e
# 提交者信息
author bloom_lmh <1357526355@qq.com> 1765521857 +0800
committer bloom_lmh <1357526355@qq.com> 1765521857 +0800
# 提交信息
提交test02.txt

```

在 Git 内部，每个提交（`commit`）并不直接存储文件内容，而是通过以下对象模型组织数据：

`blob`：存储文件内容（二进制大对象）
`tree`：存储目录结构，记录文件名、类型（文件/子目录）、权限以及对应的 `blob` 或子 `tree` 的 `SHA-1 哈希`
`commit`：包含作者、时间、提交信息，以及指向一个 tree 对象 的指针（即该次提交的根目录快照）
