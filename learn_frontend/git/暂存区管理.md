# 暂存区管理

暂存区存放的是未来将要提交到仓库的文件的变化，它是 Git 版本控制系统的核心。

## 查看暂存区状态

`git status` 主要用于查看工作区和暂存区相对于当前 `HEAD` 提交的状态，主要能够查看以下状态：

1. 已追踪文件发生了哪些变化，但这些变化还没有提交到暂存区
2. 工作区有哪些还没有被追踪
3. 哪些已跟踪文件的改动或新文件已被暂存（`staged`），准备提交

> 比如我在工作区添加三个新文件，`test01.txt`、`test02.txt` 和 `test03.txt`
>
> 1. 提交`test01.txt`到版本库，然后工作区修改`test01.txt`文件
> 2. 将`test02.txt`文件添加到暂存区
> 3. `test03.txt`不采取任何操作

此时输入`git status`可以看到如下的信息：

```shell
# 在master分支上
On branch master
# 添加到暂存区的新文件test02.txt
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   test02.txt
# 被追踪文件test01.txt发生了修改，但还没有提交到暂存区
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
        modified:   test01.txt
# 未被追踪的文件列表test03.txt
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        test03.txt
```

## 添加文件到暂存区

常用命令：

```shell
# 添加指定文件到暂存区
$ git add [file1] [file2] ...
# 添加指定目录到暂存区，包括子目录
$ git add [dir]
# 添加当前目录的所有文件到暂存区
$ git add .
# 添加当前目录的所有文件到暂存区
$ git add --all
# 添加每个变化前，都会要求确认
# 对于同一个文件的多处变化，可以实现分次提交
$ git add -p
```

当使用 `git add` 添加文件到暂存区后，暂存区的文件会和最近一次提交的文件进行比较，若没有发生变化则从暂存区移除，发生了变化才留在暂存区等待提交到仓库

比如当创建了新文件（以往没有提交过） `test02.txt，.git\objects` 文件下的内容如下:

![.git\objects](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251212095618590.png)

查看`git status`可以看到文件并没有添加到暂存区

```bash
$ git status
On branch master
# 没有被追踪的文件列表（代表以外没有提交过）
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        test02.txt

nothing added to commit but untracked files present (use "git add" to track)
```

输入`git add`，可以看到一个文件已经被添加到了暂存区

```bash
BLOOM@BLUECAT MINGW64 ~/Desktop/Git/repo_v1 (master)
$ git add test02.txt

BLOOM@BLUECAT MINGW64 ~/Desktop/Git/repo_v1 (master)
$ git status
On branch master
# 发生改变且将要被提交的文件列表（也就是在暂存区种的文件列表）
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        new file:   test02.txt
```

可以看到`objects`文件中多了个`e6`文件，这个文件就是暂存区的文件，若提交后则变为真实的文件

## 撤销暂存区文件

撤销暂存区文件有两种方案：

1. `git reset HEAD [file]`：撤销暂存区文件，但是会保持追踪，该文件会保留在工作区

2. `git rm --cached [file]`：撤销暂存区文件，并添加`deleted`变化到暂存区，该文件会保留在工作区

比如我上次提交了 test01.txt 文件，现在变更 test01.txt 文件，并添加变更到暂存区，此时`git status`显示：

```bash {3}
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        modified:   test01.txt
```

如果我们使用了`git rm --cached test01.txt`，此时`git status`显示：

```bash {3,7}
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
        deleted:    test01.txt

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        test01.txt
```

这似乎很矛盾，为什么显示`test01.txt`产生了`deleted`变化（表示实际被追踪），却又显示未被追踪呢？其实 `Git` 的逻辑是：表示如果你现在提交，这个文件会被从仓库中删除，从而导致最新的提交中没有包含这个文件，进而失去追踪。所以你要让文件真正的失去追踪，就需要提交一次。

::: tip git status
`git status` 本质上展示的是，你下一次提交后，会发生什么变化。比如下次提交后：

1. 会删除`test01.txt`
2. `test01.txt`会失去追踪

:::
