## pnpm self-update

将 `pnpm` 更新为最新版本或指定版本。
用法示例：

```bash
pnpm self-update
pnpm self-update 10
pnpm self-update next-10
pnpm self-update 10.6.5
```

## pnpm publish

### 基本介绍

将包发布到注册表。基本语法如下：

```bash
pnpm [-r] publish [<tarball|folder>] [--tag <tag>]
     [--access <public|restricted>] [options]
```

::: tip 注册表
所谓的注册表，就是一个 `npm` 镜像，它可以是官方 `npm` 镜像，也可以是私有 `npm` 镜像，甚至可以是公司内部的 `npm` 镜像。
:::

### 执照

在 `pnpm` 管理的多包项目（`workspace`）中，如果一个包自己没有定义 `LICENSE`文件，发布时会自动使用项目根目录的许可证文件，确保每个包都包含合法的许可证信息。

### 发布时覆盖原有的配置

你可以在发布前使用 `package.json` 中的 `publishConfig` 字段覆盖某些字段。你还可以使用 `publishConfig.directory` 自定义发布的子目录（通常使用第三方构建工具）。
常见用途 ​：

1. 指定注册表 ​：比如你的包要发布到公司私有的注册表，而不是公共的 `npm`。

```json
"publishConfig": {
  "registry": "https://company-private-registry.com/"
}
```

2. 自定义发布子目录：当你使用像 `Webpack`、`Vite`、`Tsup` 这样的构建工具时，源代码（`src`）会被打包编译到一个输出目录（如 `dist`或 `lib`）。而你只需要发布编译后的、精简的代码（`dist`目录），而不是整个源代码。此时可以使用 `publishConfig.directory`告诉 `pnpm`：“请把 `dist`目录当作包的根目录来发布”。

```json
"publishConfig": {
  "directory": "dist"
}
```

这样，`pnpm publish`就会发布 `dist`文件夹里的内容，而不是整个项目文件夹。

### 选项

### `pnpm publish` 命令选项

| 选项               | 缩写 | 描述                                                             | 示例或备注                                   |
| :----------------- | :--- | :--------------------------------------------------------------- | :------------------------------------------- |
| `--recursive`      | `-r` | 发布工作区中的所有包。                                           | 在 monorepo 根目录执行，发布所有有更新的包。 |
| `--json`           |      | 以 JSON 格式显示输出信息。                                       | 便于被其他程序解析。                         |
| `--tag`            |      | 发布带有给定标签的包，默认标签是 `latest`。                      | `pnpm publish --tag next`                    |
| `--access`         |      | 指定包是公开的（`public`）还是受限制的（`restricted`，即私有）。 | 首次发布公共包时需要。                       |
| `--no-git-checks`  |      | 跳过 Git 检查（如分支、工作区是否干净、是否与远程同步）。        | 用于非标准工作流。                           |
| `--publish-branch` |      | 设置用于发布的主要分支名。默认是 `master` 和 `main`。            | `pnpm publish --publish-branch develop`      |
| `--force`          |      | 即使当前版本已存在于注册表中，也强制发布。                       | 覆盖发布时使用。                             |
| `--report-summary` |      | 将已发布的包列表保存到 `pnpm-publish-summary.json` 文件。        | 用于集成其他发布报告工具。                   |
| `--dry-run`        |      | 模拟发布过程，但不实际执行发布。                                 | 用于测试和验证发布流程。                     |
| `--otp`            |      | 为启用了双因素认证（2FA）的账户提供一次性密码。                  | `pnpm publish --otp 123456`                  |
| `--filter`         |      | 仅发布与给定选择器匹配的包。                                     | `pnpm publish --filter ./packages/utils`     |

### 配置

你还可以在 `pnpm-workspace.yaml` 文件中设置 `gitChecks`、`publishBranch` 选项。

1. 禁用发布时的 `Git` 检查：默认情况下，`pnpm publish`命令会执行一系列 `Git` 安全检查，比如，检查当前分支是否是配置的发布分支（如 `main`, `master`）检查工作区是否干净（没有未提交的更改）检查本地分支是否与远程分支同步。设置 `gitChecks: false` 会跳过所有这些检查，允许你在非标准情况下发布包（比如在非发布分支上发布，或者有未提交的更改时）。

2. 设置发布分支：默认的发布分支是 `master`和 `main`。设置 `publishBranch`: `production`会将发布分支改为 `production`分支。

## pnpm pack

### 基本介绍

从包创建 `tarball` 文件。

::: tip 小技巧
从包创建 `tarball` 文件后，​ 完全可以本地安装这个 `.tgz` 文件来测试包。这是一种非常常见且可靠的测试方法，可以让你在不将包发布到公共/私有注册表（如 `npmjs.com`）的情况下，验证包的安装过程和功能是否正常。
当然还可以使用`link`
:::

### 选项

| 选项                 | 缩写 | 描述                                                                         | 添加版本 | 示例或备注                                                                                        |
| :------------------- | :--- | :--------------------------------------------------------------------------- | :------- | :------------------------------------------------------------------------------------------------ |
| `--recursive`        | `-r` | 打包工作区中的所有软件包。                                                   | v10.11.0 | 在 monorepo 根目录执行，打包所有包。                                                              |
| `--out`              |      | 自定义 tarball 的输出路径和文件名。可使用占位符 `%s` (包名) 和 `%v` (版本)。 | -        | `--out %s.tgz` (生成 `foo-pkg.tgz`)<br>`--out ./dist/%s-%v.tgz` (生成 `./dist/foo-pkg-1.0.0.tgz`) |
| `--pack-destination` |      | 指定保存 tarball 的目录。默认是当前工作目录。                                | -        | `--pack-destination ./pkg-tarballs`                                                               |
| `--pack-gzip-level`  |      | 指定 Gzip 压缩级别。                                                         | -        | 数值通常为 1-9，控制压缩比和速度。                                                                |
| `--json`             |      | 以 JSON 格式输出日志信息。                                                   | -        | 便于被其他程序解析结果。                                                                          |
| `--filter`           |      | 仅打包与给定选择器匹配的包。                                                 | v10.11.0 | `pnpm pack --filter ./packages/utils`                                                             |

## pnpm store

### 基本介绍

管理 `pnpm` 本地存储。

### :star: 命令

- `pnpm store status`：检查存储中是否有修改过的软件包,如果包的内容与解包时相同，则返回退出代码 0
- `pnpm store add <tarball>`：功能与 `pnpm add` 相同，不同之处在于它直接将新包添加到存储，而不修改存储外部的任何项目或文件。也就是不修改`package.json`或`lockfile`，仅仅将没有的包添加到本地存储。
- `pnpm store prune`：从存储中删除未引用的包。未引用的包是系统上任何项目都未使用的包。在大多数安装操作之后，例如当依赖变得多余时，包可能会变得不受引用
- `pnpm store path`：返回活动存储目录的路径。

::: tip 最佳实践
运行 `pnpm store prune` 没有害处，并且对你的项目没有副作用。如果将来的安装需要删除的软件包，`pnpm` 将再次下载它们。
最佳实践是偶尔运行 `pnpm store prune` 来清理存储，但不要太频繁。
:::

## pnpm config

### 基本介绍

别名：`c`。管理配置文件。

::: tip 两种配置文件

配置文件的格式为 `INI`（全局）和 `YAML`（本地）。
本地配置文件位于项目根目录下，名为 `pnpm-workspace.yaml.conf`。
全局配置文件位于以下位置之一：

- 如果设置了 `$XDG_CONFIG_HOME` 环境变量，则 `$XDG_CONFIG_HOME/pnpm/rc`
- 在 `Windows` 上：`~/AppData/Local/pnpm/config/rc`
- 在 `macOS` 上：`~/Library/Preferences/pnpm/rc`
- 在 `Linux` 上：`~/.config/pnpm/rc`

:::

### 命令

- `pnpm config get <key>`：获取指定键的值。
- `pnpm config set <key> <value>`：设置指定键的值。
- `pnpm config delete <key>`：删除指定键。
- `pnpm config list`：列出所有键值对。

### 选项

| 选项             | 描述                                                                                                                                                                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--global`, `-g` | 在全局配置文件中设置配置。                                                                                                                                                                                                                               |
| `--location`     | 默认情况下，`--location` 设置为 `global`。<br>当设置为 `project` 时，将使用最接近 `package.json` 处的 `.npmrc` 文件。如果目录中没有 `.npmrc` 文件，则该设置将写入 `pnpm-workspace.yaml` 文件。<br>当设置为 `global` 时，性能与设置 `--global` 选项相同。 |
| `--json`         | 让 `get` 和 `list` 以 JSON 格式显示所有配置设置，并让 `set` 将值解析为 JSON。                                                                                                                                                                            |
