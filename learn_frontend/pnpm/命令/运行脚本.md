# 运行脚本

[[toc]]

## pnpm run

### 基本介绍

别名：`run-script`，运行包的清单文件中定义的脚本。

假设你在 `package.json` 中配置了 `watch` 脚本，如下所示：

```json
"scripts": {
    "watch": "webpack --watch"
}
```

你现在可以使用 `pnpm run watch!` 运行该脚本。很简单，对吧？对于那些喜欢节省击键次数和时间的人来说，需要注意的另一件事是，所有脚本都会以 `pnpm` 命令的别名存在，因此最终 `pnpm watch` 只是 `pnpm run watch` 的简写（仅适用于与现有 `pnpm` 命令不共享相同名称的脚本）。

### 运行多个脚本

你可以使用正则表达式而不是脚本名称来同时运行多个脚本。

```bash
pnpm run "/<regex>/"
```

运行所有以 `watch:` 开头的脚本：

```bash
pnpm run "/^watch:.*/"
```

## pnpm start

别名：`run start`
运行在其 `scripts` 对象的包的 `start` 属性中指定的任意命令。如果在 `scripts` 对象上未指定 `start` 属性，它将尝试默认运行 `node server.js`，如果两者都不存在，则会失败。
该属性的预期用途是指定启动程序的命令。
比如：

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "scripts": {
    "start": "node server.js"
  }
}
```

运行 `pnpm start` 将运行 `node server.js`。

## pnpm test

别名：`run test`、`t`、`tst`
运行在其 `scripts` 对象的包的 `test` 属性中指定的任意命令。该属性的预期用途是指定为你的程序运行单元或集成测试的命令。

## :star: pnpm exec

### 基本介绍

在项目范围内执行 `shell` 命令。

::: tip 当安装了 pnpm 包的时候会发生什么？
当您通过 `pnpm`（或 `npm/yarn`）安装一个依赖包时，如果这个包包含了一个可以在命令行中运行的工具（我们称之为 `​CLI` 工具 ​ 或 ​ 二进制可执行文件），那么这个可执行文件的符号链接 ​ 就会被创建或链接到您项目的 `node_modules/.bin`目录下。
:::

`pnpm exec`命令会在执行时，​ 临时地将 `node_modules/.bin`这个目录的路径添加到系统的 `PATH`环境变量中，因此 `pnpm exec` 允许执行依赖的命令。

### 示例

如果你的项目有 `Jest` 依赖，则无需全局安装 `Jest`，只需使用 `pnpm exec` 运行即可：

```bash
pnpm exec jest
```

当该命令与内置 `pnpm` 命令不冲突时，`exec` 部分实际上是可选的，因此你也可以运行：

```bash
pnpm jest
```

::: tip 理解
其实就是类似于 `npm run jest` 的作用
:::

## 选项

`exec` 命令的任何选项都应列在 `exec` 关键字之前。`exec` 关键字后面列出的选项将传递给执行的命令。

```bash
pnpm -r exec jest
```

好的，这是根据您提供的 `pnpm exec` 命令选项说明整理的 Markdown 表格。

### `pnpm exec` 命令选项

| 选项                        | 缩写 | 描述                                                                                                                 | 示例                                                               |
| :-------------------------- | :--- | :------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------- |
| `--recursive`               | `-r` | 在工作区的每个包（项目）中递归执行指定的 shell 命令。执行时，当前包的名称可通过 `PNPM_PACKAGE_NAME` 环境变量获取。   | `pnpm -r exec rm -rf node_modules` (删除所有包的 node_modules)     |
| `--no-reporter-hide-prefix` |      | 当并行运行命令时，不禁用输出前缀。默认情况下，并行执行的输出会进行优化，此选项可关闭该优化。                         | `pnpm -r exec --no-reporter-hide-prefix echo "hello"`              |
| `--resume-from`             |      | 从指定的包开始恢复执行。这对于大型工作区中希望从中间某个包重新开始构建而不必重头开始的场景非常有用。                 | `pnpm -r exec --resume-from my-package build`                      |
| `--parallel`                |      | 完全忽略任务的并发顺序和拓扑依赖关系，立即在所有匹配的包中并行运行命令。适用于长时间运行且相互独立的进程（如构建）。 | `pnpm -r exec --parallel build`                                    |
| `--shell-mode`              | `-c` | 在系统 shell 中运行命令（UNIX 为 `/bin/sh`，Windows 为 `\cmd.exe`）。这允许使用 shell 特性，如环境变量扩展。         | `pnpm -rc exec pnpm view \$PNPM_PACKAGE_NAME` (查看所有包的包信息) |
| `--report-summary`          |      | 生成命令执行的摘要报告。                                                                                             | `pnpm -r exec --report-summary echo "done"`                        |
| `--filter`                  |      | 仅在与给定选择器匹配的包中执行命令。                                                                                 | `pnpm exec --filter my-app jest`                                   |
