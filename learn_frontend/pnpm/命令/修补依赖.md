# 修补依赖

[[toc]]

## `pnpm patch <pkg>`

修补指定包的依赖。

1. 准备一个用于修补的包，例如 `lodash`。在项目的根目录下打开终端，输入命令

```bash
pnpm patch <包名>@<版本号>
# 例如，你想改装 lodash 的 4.17.21 版本：
# pnpm patch lodash@4.17.21
```

命令行会打印出一个临时文件夹的路径，比如 `/private/var/folders/...`。这个路径就是你的“临时改装车间”，里面放着那个包最原始的代码。

2. 在“车间”里动手改装，比如修复一个你认为的 bug，或者加一些调试的 `console.log`

3. 生成“改装图纸”并备案，修改满意后，回到终端，运行这个命令：

```bash
pnpm patch-commit <临时文件夹的路径>
# 例如，把上面的路径粘贴过来：
# pnpm patch-commit /private/var/folders/...那个长路径...
```

这个命令会自动完成两件大事：

1. 生成图纸：​​ 它会比较你修改后的代码和原始代码，把所有的不同之处生成一个 `.patch` 格式的补丁文件（这就是“改装图纸”），并保存在你项目里。
2. 更新备案：​​ 它会自动在你项目的 `package.json` 文件里添加一个 `patchedDependencies` 字段，记录下“哪个包用了哪个图纸”。

```json
{
  "patchedDependencies": {
    "lodash@4.17.21": "./patchesDir/lodash-4.17.21.patch"
  }
}
```

::: tip 完成后的效果
以后，你或者你的队友在这个项目下执行 `pnpm install`安装依赖时，`pnpm`会智能地：

1. 从网上下载原始的那个包。
2. 然后自动应用你生成的那个 `.patch`文件（“改装图纸”），把包变成你修改后的样子。
3. 这样就大功告成了！简单说就是：`​patch`开门，改代码，`patch-commit`备案。​

:::

::: warning 注意事项
如果你只是想让这辆车换一个更好的轮胎（也就是修改这个包所依赖的其他包），别用 `pnpm patch` 去硬改它的 `package.json` 文件。
正确做法是：用 `pnpm` 提供的更高级的“全局指令”（`overrides`​ 或 ​ 钩子 `hooks`）来直接指定换哪个轮胎。因为硬改 `package.json` 很容易出错，而且不专业。
:::

## `pnpm patch-commit <path>`

此命令将比较 `path`下已经修改的包和它要修补的包的更改，生成补丁文件，将补丁文件保存到 `patchesDir`（可通过 `--patches-dir` 选项自定义），并向 `patchedDependencies` 添加条目。

> path 是补丁目标包的修改副本的路径，它通常是 pnpm patch 生成的临时目录。

## `pnpm patch-remove <pkg...>`

删除 `patchedDependencies` 中现有的补丁文件和设置。

```bash
pnpm patch-remove foo@1.0.0 bar@1.0.1
```
