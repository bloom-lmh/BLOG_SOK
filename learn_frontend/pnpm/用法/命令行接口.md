# 命令行接口

[[toc]]

## 与 npm 的差异

与 `npm` 不同，`pnpm` 验证所有选项。例如，`pnpm install --target_arch x64` 将失败，因为 `--target_arch` 不是 `pnpm install` 的有效选项。

> npm 像个“好说话的老好人”​​：它会忽略掉它不认识的命令选项（比如 --target_arch），只执行它认识的部分（install）。虽然命令有点小问题，但它还是会尽力帮你把事办成。

::: warning 注意
虽然 `pnpm` 的严格检查是好事，但有时会遇到一个历史遗留的“兼容性”问题：

某些古老的第三方依赖包，在安装时（比如它需要编译）会去读取一个名为 `npm_config_xxx`的环境变量。
在 `npm` 中，当你输入 `npm install --target_arch x64`时，`npm` 会悄悄地创建一个叫 `npm_config_target_arch`的环境变量，并把值设为 `x64`，这样那个依赖包就能读到了。
但 `pnpm` 因为不认识 `--target_arch`这个选项，所以它根本不会去创建这个环境变量。这就会导致那个依赖包在安装过程中因为读不到变量而失败。
:::

## 命令

`pnpm` 提供了与 `npm` 类似的命令行接口。有关更多信息，请参阅各个 CLI 命令的文档。以下是方便你入门的 `npm` 等效项列表：
| npm 命令 | 等值 pnpm |
|----------------|-----------------|
| `npm install` | `pnpm install` |
| `npm i <pkg>` | `pnpm add <pkg>`|
| `npm run <cmd>`| `pnpm <cmd>` |

当使用未知命令时，`pnpm` 将搜索具有给定名称的脚本，因此 `pnpm run lint` 与 `pnpm lint` 相同。如果没有指定名称的脚本，则 `pnpm` 将作为 `shell` 脚本执行该命令，因此你可以执行类似 `pnpm eslint` 的操作

## 选项

`pnpm` 支持使用选项来控制命令的行为。

- `-C <path>`, `--dir <path>`：运行时就好像 `pnpm` 是在 `<path>` 中启动的，而不是在当前工作目录中启动。
- `-w, --workspace-root`：运行时就好像 `pnpm` 是在 `workspace` 的根目录而不是当前工作目录中启动的。

## 环境变量

`pnpm`有环境变量的概念，一些与 `pnpm` 无关的环境变量可能会改变 `pnpm` 的行为：

- `XDG_CACHE_HOME`
- `XDG_CONFIG_HOME`
- `XDG_DATA_HOME`
- `XDG_STATE_HOME`
