# pnpm、Yarn、npm 功能对比一览表

| 功能                                 |         pnpm          |              Yarn               |           npm            | 功能解释                                                                                    |
| :----------------------------------- | :-------------------: | :-----------------------------: | :----------------------: | :------------------------------------------------------------------------------------------ |
| **工作区支持**                       |          ✔️           |               ✔️                |            ✔️            | 支持在单个代码仓库（`monorepo`）中管理多个相互关联的包。                                    |
| **隔离的 node_modules**              |       ✔️ (默认)       |               ✔️                |            ✔️            | 创建严格的依赖树，避免“幽灵依赖”（即代码访问未在`package.json`中声明的包）。                |
| **提升的 node_modules**              |          ✔️           |               ✔️                |        ✔️ (默认)         | 将依赖提升到`node_modules`根目录，是 npm 和 Yarn 的经典结构，可能导致幽灵依赖。             |
| **即插即用 (Plug'n'Play)**           |          ✔️           |               ✔️                |            ✖️            | 取代传统的`node_modules`文件夹，通过一个静态映射表来解析依赖，可以大幅提升安装和启动速度。  |
| **自动安装对等依赖**                 |          ✔️           |               ✖️                |            ✔️            | 在安装一个包时，自动安装其所需的`peerDependencies`，简化依赖管理。                          |
| **零安装 (Zero-Installs)**           |          ✖️           |               ✔️                |            ✖️            | 将缓存依赖（如`.yarn/cache`）提交到版本控制，克隆项目后无需运行`install`即可运行。          |
| **修补依赖**                         |          ✔️           |               ✔️                |            ✖️            | 允许在不直接 fork 的情况下，临时修改某个依赖包的代码以修复 bug 或添加特性。                 |
| **管理 Node.js 版本**                |    ✔️ (`pnpm env`)    |               ✖️                |            ✖️            | 内置工具可以轻松下载、安装和切换项目所需的 Node.js 版本。                                   |
| **自我版本管理**                     |          ✔️           |               ✖️                |            ✔️            | 可以通过包管理器自身（如`npm install -g npm`）来更新到新版本。                              |
| **拥有锁文件**                       | ✔️ (`pnpm-lock.yaml`) |        ✔️ (`yarn.lock`)         | ✔️ (`package-lock.json`) | 生成锁文件以确保在不同环境中安装完全一致的依赖树，保证可靠性。                              |
| **覆写支持 (overrides/resolutions)** |          ✔️           |      ✔️ (称为 resolutions)      |            ✔️            | 强制将依赖树中某个包（包括嵌套依赖）的版本锁定为指定版本，解决依赖冲突和安全问题。          |
| **内容可寻址存储**                   |          ✔️           | ✔️ (当`nodeLinker`设为`pnpm`时) |            ✖️            | 磁盘上同一版本的依赖只存储一份，通过硬链接共享，极大节省磁盘空间。                          |
| **动态包执行**                       |    ✔️ (`pnpm dlx`)    |         ✔️ (`yarn dlx`)         |        ✔️ (`npx`)        | 无需预先安装，直接下载并运行 npm 注册表中的软件包。                                         |
| **副作用缓存**                       |          ✔️           |               ✖️                |            ✖️            | 缓存构建工具（如`esbuild`）的构建结果，避免重复构建，进一步提升安装和构建速度。             |
| **配置依赖**                         |          ✔️           |               ✔️                |            ✔️            | 支持在`package.json`中声明对配置包（如`eslint-config-xxx`）的依赖。                         |
| **JSR 注册表支持**                   |          ✔️           |               ✔️                |            ✔️            | 支持从新兴的 **JSR** (JavaScript Registry) 注册表安装包，而不仅仅是传统的 npm 注册表。      |
| **运行脚本前自动安装**               |          ✔️           |   ✔️ (通过 PnP 确保依赖最新)    |            ✔️            | 在运行`package.json`中定义的脚本（如`build`, `test`）前，自动检查并安装缺失的依赖。         |
| **钩子 (Hooks)**                     |          ✔️           |               ✔️                |            ✔️            | 提供生命周期钩子（如`preinstall`, `postinstall`），允许在安装过程的不同阶段执行自定义脚本。 |
| **列出许可证**                       |          ✔️           |               ✔️                |            ✔️            | 提供命令来列出项目所有依赖及其开源许可证，方便进行许可证合规检查。                          |
