# npm 配置文件(package.json)

[[toc]]

## 基本介绍

包的清单文件（`package.json`）是 `Node.js` 包管理器的核心文件（除了 `npm`）。它记录着本包的所有信息，包括依赖列表、标题、作者等。这是所有主要 `Node.js` 包管理器（包括 `pnpm`）中保留的标准。
除了传统的 `package.json` 格式外，`pnpm` 还支持 `package.json5`（通过 `json5`）和 `package.yaml`（通过 `js-yaml`）。

## engines

`engines` 字段指定了运行该包所需的 `Node.js` 版本。

```json
{
  "engines": {
    "node": ">=10",
    "pnpm": ">=3"
  }
}
```

在本地开发期间，如果 `pnpm` 的版本与 `engines` 字段中指定的版本不匹配，则它将始终失败并显示错误消息。

## 发布时配置-publishConfig

### 基本介绍

`publishConfig` 字段可以配置发布包时使用的配置。在打包包之前，可以覆盖清单中的某些字段。以下字段可以被覆盖：

```bash
main
exports
types 或 typings
module
browser
esnext
es2015
unpkg
umd:main
typesVersions
cpu
os
```

例如，以下 `package.json`：

```json
{
  "name": "foo",
  "version": "1.0.0",
  "main": "src/index.ts",
  "publishConfig": {
    "main": "lib/index.js",
    "typings": "lib/index.d.ts"
  }
}
```

将发布为：

```json
{
  "name": "foo",
  "version": "1.0.0",
  "main": "lib/index.js",
  "typings": "lib/index.d.ts"
}
```

### 额外的可执行文件-executableFiles

在 `npm/yarn` 包管理中，​ 默认只有 `bin`字段中列出的文件会被标记为可执行。`executableFiles`字段允许你额外指定其他需要设置可执行权限（`+x`）的文件。比如：
在 `package.json` 中配置

```bash
{
    "publishConfig": {
        "executableFiles": [
            "./dist/shim.js",
            "./scripts/init.sh"
        ]
    }
}
```

然后运行:`npm run shim`

### 发布子目录-directory

你还可以使用字段 `publishConfig.directory` 自定义相对于当前 `package.json` 的已发布子目录。这样，发布包时，`dist` 目录下的内容将被发布到 `npm` 仓库。

```bash
{
  "name": "foo",
  "version": "1.0.0",
  "publishConfig": {
    "directory": "dist"
  }

```

### 符号链接-linkDirectory

当设置为 `true` 时，项目将在本地开发期间从 `publishConfig.directory` 位置进行符号链接。例如：

```bash
{
  "name": "foo",
  "version": "1.0.0",
  "publishConfig": {
    "directory": "dist",
    "linkDirectory": true
  }
}
```

::: tip 理解
在本地开发期间，系统会自动创建一个符号链接 ​（可以理解为“快捷方式”），让你的项目看起来就像是直接从 dist 目录运行的。
:::
