# 多进程模型

## 介绍

Electron 采用的是多进程模型，这意味着 Electron 程序启动的时候会启动不同的进程负责不同的任务。

::: tip 多进程的好处
![进程模型](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251223224212449.png)

- 隔离性：进程之间相互隔离互补影响，同时提供安全性
- 并发性：多个进程同时运行，提高处理效率

:::

## 进程类型

### 主进程

主进程的任务主要如下：

1. 负责创建窗口（BrowserWindow）

```js
const { BrowserWindow } = require('electron');

// 创建窗口
const win = new BrowserWindow({ width: 800, height: 1500 });
win.loadURL('https://github.com');

const contents = win.webContents;
console.log(contents);
```

2. 管理应用生命周期：主进程通过 Electron 的`app`模块控制着您的应用程序的生命周期。这使得你可以以编程方式退出应用程序、修改应用程序的停靠栏，或显示关于面板等。

```js
// 在非macos平台上没有打开窗口时退出应用程序
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit();
});
```

3. 调用原生 API：直接调用 Node.js API 和系统原生功能（如文件系统、菜单等）。

### 渲染进程

每个窗口（BrowserWindow 实例）对应一个渲染进程。渲染进程负责渲染 HTML/CSS、执行前端 JavaScript、处理用户交互。默认情况下，渲染进程是一个沙盒，只能使用浏览器相关 API，它无法直接访问 Node.js API 。

::: tip 关于 BrowserWindow 模块
BrowserWindow 模块本质上是一个`EventEmitter`（事件发送者）,而你写的脚本其实就是各种事件的处理程序。您可以为各种用户事件添加处理程序（例如，最小化或最大化您的窗口）
:::

同时当一个 BrowserWindow 实例被销毁时，其对应的渲染进程也会随之终止。

### 实用程序进程

由主进程创建，用于托管一些额外任务（如不受信任的服务、CPU 密集型任务或容易崩溃的组件等）。在 Electron 中，常用于通过 utilityProcess 模块运行独立的 Node.js 脚本，与渲染进程通信。
