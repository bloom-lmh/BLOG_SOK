# 进程通信

## 何为进程通信

在 Electron 中主进程和渲染进程承担着不同的职责，并且他们之间相互隔离。如果想要实现一些复杂的功能，就必须要他们相互通信协作，即进程间通信（IPC）。

在 Electron 中进程通过开发者定义的通道与模块之间传递消息进行通信。而这个通道就是预加载脚本。

## 进程通信的几种模式

有了预加载脚本我们就能很容易的实现进程通信了，Electron 进程通信有机制模式：

### 模式 1：渲染器到主（单向）

> 一句话概述就是主进程订阅一个事件，预加载脚本暴露这个触发该事件的方法，渲染进程调用这个暴露的方法触发这个事件，主进程接收到事件后执行相应的操作。

从渲染器进程向主进程发送单向 IPC 消息调用主进程 API，通常需要三步：

1. 订阅事件：主进程中通过 `ipcMain.on API` 订阅事件。
2. 预加载脚本暴露发布事件方法：预加载脚本中定义通过 `ipcRenderer.send API` 发送消息的方法，然后将这个方法暴露给渲染进程
3. 渲染进程使用预加载脚本暴露的方法触发事件

::: code-group

```js [main.js] {21-22}
const { app, BrowserWindow, ipcMain } = require('electron/main');
const path = require('node:path');

function handleSetTitle(event, title) {
  const webContents = event.sender;
  const win = BrowserWindow.fromWebContents(webContents);
  win.setTitle(title);
}

function createWindow() {
  const mainWindow = new BrowserWindow({
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
    },
  });

  mainWindow.loadFile('index.html');
}

app.whenReady().then(() => {
  // 订阅消息
  ipcMain.on('set-title', handleSetTitle);
  createWindow();

  app.on('activate', function () {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});

app.on('window-all-closed', function () {
  if (process.platform !== 'darwin') app.quit();
});
```

```js [预加载.js] {3-4}
const { contextBridge, ipcRenderer } = require('electron/renderer');

// 将API暴露给渲染器进程
contextBridge.exposeInMainWorld('electronAPI', {
  setTitle: (title) => ipcRenderer.send('set-title', title),
});
```


### 模式 2：渲染器到主进程（双向）

双向 IPC 的常见应用是从渲染器进程代码调用主进程模块并等待结果。通常也需要三步实现：

1. 主进程通过 `ipcMain.handle` 订阅事件
2. 预加载脚本暴露发布事件方法`openFile`其内部调用 `ipcRenderer.invoke`
3. 渲染进程调用预加载脚本暴露的方法，并等待结果

::: code-group

```js [main.js] {21-22}
const { app, BrowserWindow, ipcMain, dialog } = require('electron/main');
const path = require('node:path');

async function handleFileOpen() {
  const { canceled, filePaths } = await dialog.showOpenDialog();
  if (!canceled) {
    return filePaths[0];
  }
}

function createWindow() {
  const mainWindow = new BrowserWindow({
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
    },
  });
  mainWindow.loadFile('index.html');
}

app.whenReady().then(() => {
  // 订阅dialog:openFile消息
  ipcMain.handle('dialog:openFile', handleFileOpen);
  createWindow();
  app.on('activate', function () {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});

app.on('window-all-closed', function () {
  if (process.platform !== 'darwin') app.quit();
});
```

```js [preload.js]
const { contextBridge, ipcRenderer } = require('electron/renderer');

// 暴露触发函数
contextBridge.exposeInMainWorld('electronAPI', {
  openFile: () => ipcRenderer.invoke('dialog:openFile'),
});
```

### 模式 3：主控到渲染器

当从主进程向渲染器进程发送消息时，您需要指定接收消息的渲染器。其实现过程也为三步：

1. 主进程通过 `mainWindow.webContents.send` 发送消息
2. 预加载脚本暴露订阅事件方法`onUpdateCounter`，其内部调用 `ipcRenderer.on`订阅事件
3. 渲染进程调用`onUpdateCounter`订阅事件，并等待主进程发布事件并执行相应的操作

消息必须通过其实例发送到渲染器进程

::: code-group

```js [main.js]
const { app, BrowserWindow, Menu, ipcMain } = require('electron/main');
const path = require('node:path');

function createWindow() {
  const mainWindow = new BrowserWindow({
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
    },
  });

  const menu = Menu.buildFromTemplate([
    {
      label: app.name,
      submenu: [
        {
          click: () => mainWindow.webContents.send('update-counter', 1),
          label: 'Increment',
        },
        {
          click: () => mainWindow.webContents.send('update-counter', -1),
          label: 'Decrement',
        },
      ],
    },
  ]);

  Menu.setApplicationMenu(menu);
  mainWindow.loadFile('index.html');

  // Open the DevTools.
  mainWindow.webContents.openDevTools();
}

app.whenReady().then(() => {
  ipcMain.on('counter-value', (_event, value) => {
    console.log(value); // will print value to Node console
  });
  createWindow();

  app.on('activate', function () {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});

app.on('window-all-closed', function () {
  if (process.platform !== 'darwin') app.quit();
});
```

```js [preload.js]
const { contextBridge, ipcRenderer } = require('electron/renderer');

contextBridge.exposeInMainWorld('electronAPI', {
  onUpdateCounter: (callback) => ipcRenderer.on('update-counter', (_event, value) => callback(value)),
  counterValue: (value) => ipcRenderer.send('counter-value', value),
});
```

```html [index.html]
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8" />
    <!-- https://developer.mozilla.org/en-US/docs/Web/HTTP/CSP -->
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'" />
    <title>Menu Counter</title>
  </head>
  <body>
    Current value: <strong id="counter">0</strong>
    <script src="./renderer.js"></script>
  </body>

```

```js [renderer.js]
const counter = document.getElementById('counter');

window.electronAPI.onUpdateCounter((value) => {
  const oldValue = Number(counter.innerText);
  const newValue = oldValue + value;
  counter.innerText = newValue.toString();
  window.electronAPI.counterValue(newValue);
});
```

### 模式 4：渲染器到渲染器

在 Electron 中，使用 `ipcMain` 和 `ipcRenderer` 模块无法直接在渲染器进程之间发送消息。要实现这一点，您有两种选择：

- 将主进程用作渲染器之间的消息代理。这涉及从一个渲染器向主进程发送消息，然后由主进程将该消息转发给另一个渲染器。
- 将一个 MessagePort 从主进程传递到两个渲染器。这将在初始设置完成后允许渲染器之间直接通信。

## 对象序列化

Electron 的 IPC 实现使用了 HTML 标准的结构化克隆算法来序列化进程间传递的对象，这意味着只有特定类型的对象才能通过 IPC 通道进行传递。DOM 对象、Node.js 对象（例如 process.env, 某些成员 Stream）等都不能通过 IPC 通道进行传递。
