# 流程模型

Electron 继承了来自 Chromium 的多进程架构，这使得此框架在架构上非常相似于一个现代的网页浏览器。 本指南将扩展教程中使用的概念。

## 进程模型

`Chrome`浏览器主要采用多进程模型：每个标签页都是一个进程。单个浏览器进程控制这些标签页进程，以及整个应用程序的生命周期，如下所示：

![进程模型](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251223224212449.png)

为什么要采用多个进程呢？ 主要原因有两个：

1. 安全性：每个标签页都在自己的进程中运行，这意味着它们不能访问其他标签页的内存或文件系统。 这就保证了用户的隐私和安全。
2. 并发性：每个进程都有自己的线程，这些线程负责处理用户交互、网络请求、JavaScript 运行时、渲染、插件等。 线程之间共享进程的内存空间，但每个线程都有自己的栈和局部变量。

Electron 应用程序的结构非常相似。作为应用开发者，你将控制两种类型的进程：主进程 和 渲染器进程。这类似于上文所述的 Chrome 的浏览器和渲染器进程

## 主进程

每个 Electron 应用都有一个单一的主进程，作为应用程序的入口点。 主进程在 Node.js 环境中运行，这意味着它具有 require 模块和使用所有 Node.js API 的能力。

### 窗口管理

主进程的首要目的是使用 `BrowserWindow` 模块创建和管理应用程序窗口。

`BrowserWindow` 类的每个实例创建一个对应的应用程序窗口，且在单独的渲染器进程中加载一个网页。您可以在主进程中用 `window` 的 `webContents` 对象与网页内容进行交互。

```js
const { BrowserWindow } = require('electron');

const win = new BrowserWindow({ width: 800, height: 1500 });
win.loadURL('https://github.com');

const contents = win.webContents;
console.log(contents);
```
