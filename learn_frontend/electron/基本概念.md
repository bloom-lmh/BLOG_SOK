# 基本概念

## 介绍

### 什么是 Electron？

Electron 是网页应用 (web apps) 的一个原生包装层，在 Node.js 环境中运行。

> 你可以理解为 electron 应用程序其实等价于 web 页面+chrome 内核+node.js 环境+v8 引擎，就是一个网站的桌面版本。

### 为什么要用 Electron？

Electron 通过将最新版本的 Chromium、V8 和 Node.js 直接与应用程序二进制文件打包在一起，在所有目标平台（macOS、Windows、Linux）上提供出色的体验，虽然打包的程序很大，但是是有好处的：

1. 打包 Chromium 和 V8，让每个应用都是一个定制浏览器，可以完整的运行 web 项目，也就是说你可以把任何 Web 应用打包成一个 Electron 应用。
2. 主进程（Main Process）拥有完整的 Node.js API，让其可以操作操作系统。渲染进程默认也开启 nodeIntegration（旧版本），可直接调用 Node.js ，但这不安全
3. 由于 Chromium 和 Node.js 本身是跨平台的，electron 提供的原生 JavaScript API 也做了不同平台的抽象（兼容性处理），且构建时为每个平台生成独立二进制包，所以 electron 程序也可以运行在 Windows、Mac、Linux 等平台上
4. 稳定性好，因为应用绑定固定版本的 Chromium/Node.js（它的程序不是运行在浏览器上），不会因用户升级 Chrome 或系统 WebView 而 break。
5. 性能好，Chromium 支持 GPU 加速、多进程架构、V8 高性能 JS 引擎。

### 什么时候不需要 Electron？

1. 在内存、算力或磁盘极为有限的场景中不适合
2. Electron 允许编写原生代码，比如在 windows 上使用 WinUI，当你需要开发纯原生应用时，可以考虑使用原生技术
3. 如果您正在开发需要复杂实时 3D 图形的高性能游戏或应用，Unity、虚幻引擎、DirectX/OpenGL 等原生框架可以提供更出色的性能，并能更直接地访问图形硬件

## 创建项目

### 所需环境

Electron 基于 Node.js 开发，因此需要安装 Node.js 环境。

### 初始化 npm 项目

Electron 应用基于 npm 搭建，以 `package.json` 文件作为入口点。 首先创建一个文件夹，然后在其中执行 `npm init` 初始化项目。

::: warning 其它包管理器与扁平化的 `node_modules` 文件夹

Electron 的打包工具链要求 `node_modules` 文件夹必须以 npm 安装 Node 依赖项的方式实际存在于磁盘上。因此，如果你使用这些包管理器，必须在 Yarn 中设置 `nodeLinker: node-modules`，或在 pnpm 中设置 `nodeLinker: hoisted`。

> 也就是说如果用 pnpm 必须要将依赖提升到 node_modules 下，并且不能采用软连接形式，需要依赖直接存在于项目 node_modules 中（无论是硬链接还是真实复制）；

:::

然后，将 Electron 安装为您项目的 `devDependencies`，即仅在开发环境需要的额外依赖。

::: tip 为什么不是生成环境依赖
您的应用需要运行 Electron API，因此这听上去可能有点反直觉。在底层，Electron 的 JavaScript API 会绑定到一个包含其实现代码的二进制文件。Electron 的打包步骤会自动处理该二进制文件的捆绑，因此无需将其显式指定为生产依赖项。
:::

```bash
npm install electron --save-dev
```

::: warning 注意不要忽略安装后的脚本

为了正确安装 Electron，你需要确保其 postinstall 生命周期脚本能正常运行。这意味着在使用 npm 时应避免使用 `--ignore-scripts` 标志，并在其他包管理器中将 Electron 加入允许运行构建脚本的白名单。

:::

## 运行 Electron 应用

Electron 应用的入口点是 package.json 文件中的 main 字段，它指定了应用的入口文件。同时为了方便启动 electron 应用，你需要配置运行脚本，在 scripts 字段中添加 start 启动命令（因为 Electron 包含 NodeJS，其主进程就是一个 Node.js 运行时，所以你可以直接用 electron 命令运行任意的 Node.js 代码，这相当于使用 node 命令）

```json
{
  "name": "my-electron-app",
  "version": "1.0.0",
  "description": "Hello World!",
  "main": "main.js",
  "scripts": {
    "start": "electron .",
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "author": "Jane Doe",
  "license": "MIT",
  "devDependencies": {
    "electron": "23.1.3"
  }
}
```

然后输入 npm run start 就可运行 electron 应用了。

## 将网页装载到 BrowserWindow

### 准备页面

在 Electron 中，每个窗口展示一个页面，这个页面可以来自本地的 HTML，也可以来自远程 URL。 在本例中，您将会装载本地的文件。 在您项目的根目录中创建一个 index.html 文件，并写入下面的内容：

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8" />
    <!-- https://developer.mozilla.org/en-US/docs/Web/HTTP/CSP -->
    <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self'" />
    <meta http-equiv="X-Content-Security-Policy" content="default-src 'self'; script-src 'self'" />
    <title>Hello from Electron renderer!</title>
  </head>
  <body>
    <h1>Hello from Electron renderer!</h1>
    <p>👋</p>
  </body>
</html>
```

### 加载页面

现在您有了一个网页，您可以将其加载到一个 Electron 的 `BrowserWindow` 上了。 将 `main.js` 中的内容替换成下列代码。

```js
// 导入模块（支持esm）
const { app, BrowserWindow } = require('electron');
// 创建窗口
const createWindow = () => {
  // 创建浏览器窗口，传入窗口配置
  const win = new BrowserWindow({
    width: 800,
    height: 600,
  });

  win.loadFile('index.html');
};
// app 准备就绪后创建窗口
app.whenReady().then(() => {
  createWindow();
});
```

在第一行中，我们使用 CommonJS 语法导入了两个 Electron 模块：

- `app`，这个模块控制着您应用程序的事件生命周期。
- `BrowserWindow`，这个模块创建和管理 `app` 的窗口。

在 Electron 中，只有在 app 模块的 `ready` 事件（event）触发后才能创建 `BrowserWindows` 实例。事实上 Electron 的许多核心模块都是 Node.js 的事件触发器。

此时，运行 start 命令应该能成功地打开一个包含您网页内容的窗口！

::: tip 渲染器
您应用中的每个页面都在一个单独的进程中运行，我们称这些进程为渲染器 (renderer)。渲染进程使用与常规 Web 开发相同的 JavaScript API 和工具，例如使用 webpack 来打包和压缩您的代码，或使用 React 构建用户界面
:::

## 管理应用的窗口生命周期

electron 可以允许你根据不同的平台自行的管理窗口的行为

::: tip 支持的平台

electron 支持三种平台：win32 (Windows), linux (Linux) 和 darwin (macOS) 。你可以通过 `process.platform` 来获取当前平台的名称。
:::

### 关闭所有窗口时退出应用(Windows & Linux)

在 Windows 和 Linux 上，我们通常希望在关闭一个应用的所有窗口后让它退出。要在您的 Electron 应用中实现这一点，您可以监听 app 模块的 `window-all-closed` 事件，并在判断用户不使用 macOS 后调用 `app.quit()` 来退出您的应用程序。

```js
app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit();
});
```

### 如果没有窗口打开则打开一个窗口 (macOS)

与前二者相比，即使没有打开任何窗口，macOS 应用通常也会继续运行。 在没有窗口可用时调用 app 会打开一个新窗口。要实现这一特性，可以监听 app 模组的 activate 事件，如果没有任何打开（open）的 `BrowserWindow`，调用您已有的 `createWindow()` 方法新建一个。

```js
app.whenReady().then(() => {
  createWindow();

  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow();
  });
});
```

## 使用 VS Code 调试

你可以使用 vscode 来调试 electron 应用，首先在根目录下创建`.vscode` 文件夹，然后在在文件中创建调试配置文件 `launch.json`文件， 并配置调试参数。

```json
{
  "version": "0.2.0",
  "compounds": [
    {
      "name": "Main + renderer",
      "configurations": ["Main", "Renderer"],
      "stopAll": true
    }
  ],
  "configurations": [
    {
      "name": "Renderer",
      "port": 9222,
      "request": "attach",
      "type": "chrome",
      "webRoot": "${workspaceFolder}"
    },
    {
      "name": "Main",
      "type": "node",
      "request": "launch",
      "cwd": "${workspaceFolder}",
      "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron",
      "windows": {
        "runtimeExecutable": "${workspaceFolder}/node_modules/.bin/electron.cmd"
      },
      "args": [".", "--remote-debugging-port=9222"],
      "outputCapture": "std",
      "console": "integratedTerminal"
    }
  ]
}
```

保存后，当您选择侧边栏的 “运行和调试”，将会出现一个 "Main + renderer" 选项。然后您便可设置断点，并跟踪主进程和渲染器进程中的所有变量。
