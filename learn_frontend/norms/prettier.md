# prettier 使用

[prettier 在线网站](https://prettier.io/)

## 简介

`Prettier` 是一款代码格式化工具，它会移除所有原始样式，并确保所有输出的代码都符合一致的风格。也就是在团队开发中保持代码风格的一致性。

## 基本使用

### 配合命令行使用

prettier 配合命令行使用就三步：

1. 下载 prettier 到项目：`npm install --save-dev --save-exact prettier`
2. 配置 prettier：在项目根目录下创建 `.prettierrc`和 `.prettierignore` 文件，并配置相关选项。
3. 使用 prettier：运行 `npx prettier --write "src/**/*.{js,jsx,ts,tsx,json,md,css,scss,less}"`，prettier 会自动格式化所有匹配的文件。

::: tip npx 命令
`npx` 随附 `npm` 并允许您运行本地安装的工具。如果您忘记先安装 Prettier，`npx` 将临时下载最新版本然后执行。在使用 Prettier 时，这可不是个好主意，因为我们在每次发布时都会更改代码的格式化方式！因此，在您的 `package.json` 中锁定 Prettier 的特定版本非常重要。而且它还更快。
:::

同时还要注意`--write`会格式化并覆盖原文件，如果不想覆盖，仅仅展示哪些文件需要格式化，可以使用`--check`参数(这通常才 CI 流程中进行使用)

### 配合编辑器使用

通过命令行来进行格式化是一种使用方式。但是它在开发完成后再进行格式化显然就无法享受良好的开发体验了，推荐在编写代码的过程中就进行格式化，这需要编译器的支持。这里以 vscode 为例。在 vscode 中使用 prettier 进行代码格式化，步骤如下：

1. 安装 prettier 插件：在 vscode 插件市场搜索 prettier 并安装。
2. 配置 vscode 格式化选项：在 vscode 的设置中搜索 `format on save` 并开启。
3. 保存文件时自动格式化：保存文件时，prettier 插件会有限读取你当前文件所在项目的 `.prettierrc` 文件，并自动格式化代码。如果没有 `.prettierrc` 文件，则会使用 vscode 中的全局配置和默认配置。

这样你就能做到在代码文件保存的时候进行格式化了

::: tip 编辑器不支持如何使用呢？
如果您的编辑器不支持 Prettier，您可以改用文件监视器运行 Prettier.比如：

```bash
npx onchange "**/*" -- npx prettier --write --ignore-unknown {{changed}}
```

:::

### 配合 ESLint 使用

如果您使用 ESLint，请安装 `eslint-config-prettier` 以使 ESLint 和 Prettier 相互兼容。它会关闭所有不必要的或可能与 Prettier 冲突的 ESLint 规则。Stylelint 也有类似的配置：`stylelint-config-prettier`

### 配合 Git 钩子使用

除了通过命令行运行 `Prettier()`、在 CI 中检查格式以及从编辑器中运行 Prettier 之外，许多人还喜欢将 Prettier 用作提交前的钩子。这样可以确保所有提交都已格式化，而无需等待 CI 构建完成。例如，您可以在每次提交前运行 Prettier，同时注意提交前的钩子有很多但是这里介绍一下最常用的两个：

1. 安装 `husky` 和 `lint-staged`:

```bash
npm install --save-dev husky lint-staged
npx husky init
node --eval "fs.writeFileSync('.husky/pre-commit','npx lint-staged\n')"
```

2. 将以下内容添加到您的 package.json:

```json
{
  "lint-staged": {
    "**/*": "prettier --write --ignore-unknown"
  }
}
```

## 忽视内容

### 忽视文件

对于某一些文件，我们并不希望使用`prettier`来进行格式化，这时候就可以使用`.prettierignore`以完全忽略（即不重新格式化）某些文件和文件夹。示例：

```bash
# Ignore artifacts:
build
coverage

# Ignore all HTML files:
**/*.html
```

默认情况下，Prettier 会忽略版本控制系统目录中的文件（`.git`、`.jj`、`.sl`、`.svn`和`.hg`）以及 `node_modules` 目录。
如果 Prettier 在其运行的同一目录中发现`.gitignore`文件，它还会遵循该文件中指定的规则。

```bash
**/.git
**/.svn
**/.hg
**/node_modules
```

::: tip 如果没有`.prettierignore` 文件
如果 Prettier 与运行它的目录位于同一位置且存在 `.gitignore` 文件，则 Prettier 将遵循该 `.gitignore` 中指定的规则。甚至您还可以基于 `.eslintignore`（如果您有的话）来设置您的 `.prettierignore`。
:::

::: tip 一次性命令
当然你还可以使用命令行，对于一次性命令，当您想排除某些文件而不将其添加到`.prettierignore`中时，负模式会派上用场：

```bash
prettier . "!**/*.{js,jsx,vue}" --write
```

:::

### 忽视代码

`pretter`不仅仅可以忽视文件，还可以做到更加精细化的控制，比如忽视某些代码段，你只要在代码前加上某些注释即可：

:::code-group

```js
matrix(1, 0, 0, 0, 1, 0, 0, 0, 1);

// prettier-ignore
matrix(
  1, 0, 0,
  0, 1, 0,
  0, 0, 1
)
```

```jsx
<div>
  {/* prettier-ignore */}
  <span     ugly  format=''   />
</div>
```

```html
<!-- prettier-ignore -->
<div         class="x"       >hello world</div            >

<!-- prettier-ignore-attribute -->
<div (mousedown)="       onStart    (    )         " (mouseup)="         onEnd      (    )         "></div>

<!-- prettier-ignore-attribute (mouseup) -->
<div (mousedown)="onStart()" (mouseup)="         onEnd      (    )         "></div>
```

```css
/* prettier-ignore */
.my    ugly rule
{

}
```

```md
<!-- prettier-ignore -->
Do   not    format   this
```

:::

当然我们还可以范围性的进行忽略：

```bash
<!-- prettier-ignore-start -->
<!-- SOMETHING AUTO-GENERATED BY TOOLS - START -->

| MY | AWESOME | AUTO-GENERATED | TABLE |
|-|-|-|-|
| a | b | c | d |

<!-- SOMETHING AUTO-GENERATED BY TOOLS - END -->
<!-- prettier-ignore-end -->
```

## 插件

插件是向 Prettier 添加新语言支持或格式化规则的方式。Prettier 自身对所有语言的实现均采用插件 API 表达。核心 prettier 软件包内置了 JavaScript 以及其他以 Web 为中心的语言。若要使用其他语言，您需要安装相应的插件。

### 加载插件

您可以使用以下方式加载插件：

1. 命令行:

```js
prettier --write main.foo --plugin=prettier-plugin-foo
```

2. API, 通过选项：

```js
await prettier.format('code', {
  parser: 'foo',
  plugins: ['prettier-plugin-foo'],
});
```

3. 配置文件:

```json
{
  "plugins": ["prettier-plugin-foo"]
}
```

### 官方插件

具体看[官网](https://www.prettier.cn/docs/plugins#using-plugins)

### 开发插件

具体看[官网](https://www.prettier.cn/docs/plugins#using-plugins)

## 命令行

使用 `prettier` 命令从命令行运行 Prettier。

```bash
prettier [options] [file/dir/glob ...]
```

::: info 运行命令
要运行您本地安装的 Prettier 版本，请在命令前加上 `npx`, `yarn exec`, `pnpm exec`, 或 `bunx`, 例如：`npx prettier --help`, `yarn exec prettier --help`, `pnpm exec prettier --help`, 或 `bunx prettier --help`.
:::

### --write

此命令会格式化对应目录及其子目录中 Prettier 支持的所有文件。比如：

```bash
prettier docs package.json "{app,__{tests,mocks}__}/**/*.js" --write --single-quote --trailing-comma all
```

::: tip 文件模式
`{app,__{tests,mocks}__}/**/*.js`其实就是采用的`glob`模式，可以匹配多种文件类型。

| 通配符       | 含义                                                                                                                                   |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `*`          | 匹配任意数量的字符（不包括 `/`），即匹配单层目录下的文件或文件夹名。例如：`*.js` 匹配 `index.js`、`app.js`，但不匹配 `src/index.js`。  |
| ``           | 匹配任意层级的子目录（包括零层）。例如：`src//*.js` 会匹配 `src/index.js`、`src/utils/helper.js`、`src/components/ui/button.jsx` 等。  |
| `?`          | 匹配任意单个字符（不包括 `/`）。例如：`file?.txt` 匹配 `file1.txt`、`fileA.txt`，但不匹配 `file10.txt`。                               |
| `[abc]`      | 字符集合：匹配括号内的任意一个字符。例如：`file[123].js` 匹配 `file1.js`、`file2.js`、`file3.js`。                                     |
| `[a-z]`      | 字符范围：匹配指定范围内的任意字符。例如：`test-[a-c].js` 匹配 `test-a.js`、`test-b.js`、`test-c.js`。                                 |
| `{a,b,c}`    | 大括号扩展（Brace Expansion）：匹配逗号分隔的任意一项。例如：`{src,test}/*.js` 相当于 `src/*.js` 和 `test/*.js`。                      |
| `!(pattern)` | 排除模式（需支持 extglob）：匹配不满足 pattern 的内容。例如：`!(*.spec).js` 排除以 `.spec.js` 结尾的文件（注意：并非所有工具都支持）。 |

:::

### --check

当您想检查文件是否已格式化时，可以使用标志（或）运行 Prettier。如果存在未格式化的文件，这将输出一条便于人类阅读的消息以及未格式化文件的列表。

```bash
prettier . --check
```

如果所有文件均已格式化，控制台输出：

```bash
Checking formatting...
All matched files use Prettier code style!
```

如果某些文件需要重新格式化，控制台输出：

```bash
Checking formatting...
[warn] src/fileA.js
[warn] src/fileB.js
[warn] Code style issues found in 2 files. Run Prettier with --write to fix.
```

## 配置

### 配置文件

最好使用配置文件来指定格式化选项,而不是通过 CLI 标志传递。这样，Prettier CLI、编辑器集成以及其他工具都能了解您使用的选项。你可以通过以下方式来配置 Prettier（按顺序查找，找到即停）

| 文件名                                     | 格式说明                                                      |
| ------------------------------------------ | ------------------------------------------------------------- |
| `.prettierrc.mjs` 或 `prettier.config.mjs` | ESM 模块，使用 `export default`                               |
| `.prettierrc.cjs` 或 `prettier.config.cjs` | CommonJS 模块，使用 `module.exports`                          |
| `.prettierrc.mts` 或 `prettier.config.mts` | TypeScript + ESM（需支持）                                    |
| `.prettierrc.cts` 或 `prettier.config.cts` | TypeScript + CommonJS（需支持）                               |
| `.prettierrc.toml`                         | TOML 格式（Prettier 3.0+ 支持）                               |
| `.prettierrc.json`, `.prettierrc.json5`    | JSON / JSON5 格式                                             |
| `.prettierrc.yml`, `.prettierrc.yaml`      | YAML 格式                                                     |
| `.prettierrc`                              | 可以是 JSON、YAML 或 JS（根据内容自动推断，但不推荐，易混淆） |

::: tip 寻找配置文件的策略
配置文件将从正在格式化的文件所在位置开始解析，并向上遍历文件树，直至找到（或未找到）配置文件。
:::
当然我可以指定配置文件的路径：

```bash
prettier --config ./path/to/config.json
```

对于 js 类型的配置文件你可以有类型提示（通过`jsdoc`注释）:

```js
// prettier.config.js, .prettierrc.js, prettier.config.cjs, or .prettierrc.cjs

/**
 * @see https://prettier.io/docs/configuration
 * @type {import("prettier").Config}
 */
const config = {
  trailingComma: 'es5',
  tabWidth: 4,
  semi: false,
  singleQuote: true,
};

module.exports = config;
```

### 共享配置

所谓的共享配置就是发布一个`npm`包，然后其他项目可以依赖这个包，并在`package.json`中指定`prettier`为对等依赖。

首先，创建一个新软件包。我们建议创建一个带有作用域的软件包,名称为`@username/prettier-config`.

一个最小化软件包应至少包含两个文件。一个用于软件包配置，另一个用于存放共享的 Prettier 配置对象：

```json
prettier-config/
├── index.js
└── package.json
```

示例`package.json`:

```json
{
  "name": "@username/prettier-config",
  "version": "1.0.0",
  "description": "My personal Prettier config",
  "type": "module",
  "exports": "./index.js",
  "license": "MIT",
  "publishConfig": {
    "access": "public"
  },
  "peerDependencies": {
    "prettier": ">=3.0.0"
  }
}
```

`index.js` 是您放置共享配置的地方。此文件仅导出一个常规的 Prettier 配置，采用相同的语法和相同的选项：

```js
const config = {
  trailingComma: 'es5',
  tabWidth: 4,
  singleQuote: true,
};

export default config;
```

一个示例共享配置存储库可在此处获取。然后发布这个共享库

```js
npm publish
```

使用时，您首先需要安装已发布的配置，例如：

```bash
npm install --save-dev @username/prettier-config
```

然后，您可以在您的 `package.json`:

```json
{
  "name": "my-cool-library",
  "version": "1.0.0",
  "prettier": "@username/prettier-config"
}
```

如果您不想使用`package.json`,您可以使用任何受支持的扩展程序来导出字符串，例如：`.prettierrc`:

```json
"@company/prettier-config"
```

## 在 CI 上进行集成

要从 `GitHub Actions` 为 `Prettier` 应用自动修复功能，请执行以下操作：

1. 安装`autofix.ciGitHub` 应用程序。
2. 请确保您的仓库中已安装固定版本的 Prettier。
3. 使用以下内容创建：`.github/workflows/prettier.yml`

```yaml
name: autofix.ci
on:
  pull_request:
  push:
permissions: {}
jobs:
  prettier:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: |
          yarn
          yarn prettier . --write
      - uses: autofix-ci/action@v1
        with:
          commit-message: 'Apply Prettier format'
```
