# 基本概念

[[toc]]

## 概述

`Rollup`是一个采用 ES6 模块化语法进行打包的模块化打包工具。它允许你使用新的模块系统（ES6 模块化）编写代码，然后将其编译回现有支持的格式，例如 `CommonJS` 模块、`AMD` 模块和 `IIFE` 样式脚本。这意味着你可以编**写面向未来的代码**，并且你还可以获得的巨大好处。

## 安装

`Rollup` 有两种安装方式：

- 全局安装：`npm install --global rollup`
- 局部安装：`npm install --save-dev rollup`

## 基本使用

`Rollup` 有两种使用方式具体参见对应章节：

- 命令行/配置文件形式：`Rollup` 可以通过具有可选配置文件的命令行接口来完成打包工作。
- Javascript API：`Rollup` 也可以通过 `Javascript API` 调用，并传入配置对象

## 树摇优化

除了允许使用 `ES` 模块之外，`Rollup` 还会静态分析你正在导入的代码，并排除任何未实际使用的代码。这使你可以在现有工具和模块的基础上进行构建，而无需添加额外的依赖或扩大项目的大小

例如，对于 `CommonJS`，必须导入整个工具或库。

```javascript
// import the entire utils object with CommonJS
const utils = require('./utils');
const query = 'Rollup';
// use the ajax method of the utils object
utils.ajax(`https://api.example.com?search=${query}`).then(handleResponse);
```

使用 `ES` 模块，我们可以只导入我们需要的一个 `ajax` 函数，而不是导入整个 `utils` 对象：

```javascript
// import the ajax function with an ES6 import statement
import { ajax } from './utils';
const query = 'Rollup';
// call the ajax function
ajax(`https://api.example.com?search=${query}`).then(handleResponse);
```

由于 `Rollup` 包含最低限度的内容，因此它会产生更轻、更快且不太复杂的库和应用。由于这种方法可以利用显式的 `import` 和 `export` 语句，因此它比简单地运行自动压缩器来检测编译的输出代码中未使用的变量更有效。

::: tip 理解
`Tree-Shaking`（树摇优化）的核心机制确实是建立在 ES6 模块语法（`import/export`）的静态结构特性上的
:::

## 兼容性

### 导入 CommonJS

> 情形：你正在用 `Rollup`（一个擅长处理 ES 模块的工具）打包你的项目。你的项目想使用一个别人写的、但只用 `CommonJS` 语法发布的 npm 包

`Rollup`本身不能直接理解`CommonJS`语法，但可以通过一个插件 ​（最常用的是`@rollup/plugin-commonjs`）来帮你把 `CommonJS`的代码转换成`Rollup`能理解的`ES` 模块代码，然后再进行打包

::: tip 理解
也就是说 `es` 模块化项目种如果你想使用 `commonjs`包那么打包时则需要用到`Rollup`插件处理。
这就像你（`ES`模块项目）只会说普通话，但你想引用一本英文书（`CommonJS`模块）里的内容。你需要一个翻译插件，先把整本英文书翻译成中文，然后你才能流畅地阅读和引用
:::

### 发布 ES 模块

> 情形：你用 ES 模块语法写好了一个很棒的库，想发布到 npm 上给别人用。你希望你的库既能被支持新语法的工具（如 Rollup、Webpack 2+）使用，也能被只认识旧语法的工具（如老版本 Node.js）使用

用 `Rollup` 打包两份代码 ​:

- 一份保持为原始的 `ES` 模块格式（`.mjs`或 `.js`文件），性能最好。
- 另一份编译成兼容性更好的 `​UMD` 或 `CommonJS`​ 格式（`.cjs`或 `.js`文件）。

在 `package.json` 文件中正确配置:

- `main`字段 ​：指向你编译好的 `​CommonJS` 版本。这是给所有不认识 `module` 字段的旧工具（如 `Node.js`、老 `Webpack`）使用的默认入口。
- `​module`字段 ​：指向你原始的 `​ES` 模块版本。像 `Rollup` 和 `Webpack 2+` 这种聪明的工具，如果看到这个字段，就会优先使用 `ES` 模块版本，这能带来更好的摇树优化`（Tree-shaking）`，最终让用户的项目体积更小。

::: tip 理解
假设你发布了一个库 `awesome-lib`，它的 `package.json`如下：

```json
{
  "name": "awesome-lib",
  "main": "dist/awesome-lib.cjs", // CommonJS 版本（旧环境用）
  "module": "dist/awesome-lib.mjs" // ES 模块版本（新环境优先用）
}
```

用户`A`：用 `Vite`（现代工具）构建

- `Vite` 会优先读取 `module`字段，加载 `awesome-lib.mjs`（ES 模块）。
- 最终打包 ​：只包含 `awesome-lib.mjs`，并进行 `Tree-shaking` 优化。

用户 `B`：用老版本 `Node.js（v10）`运行

- `Node.js` 不认识 `module`，所以会读取 `main`字段，加载 `awesome-lib.cjs（CommonJS）`。
- 运行结果 ​：能正常使用，但没有 `Tree-shaking`。

:::
