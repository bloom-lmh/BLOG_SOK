# 插件

## @rollup/plugin-bable

### 介绍

作用：这个插件主要是用来做语法降级和兼容的，底层依赖`babel`
安装：`npm install @rollup/plugin-babel --save-dev`

### 基本使用

#### 输入时转义

你可以在输入文件中使用该插件进行转义

```js
import { babel } from '@rollup/plugin-babel';

const config = {
  input: 'src/index.js',
  output: {
    dir: 'output',
    format: 'es',
  },
  plugins: [
    babel({
      // 这里是babel的配置项
    }),
  ],
};

export default config;
```

#### 输出时转义

也可以对生成的代码块上使用 babel 进行转义

1. 全局转义：下面将会对所有的输出块进行转义

```js
// rollup.config.js
import { getBabelOutputPlugin } from '@rollup/plugin-babel';

export default {
  input: 'main.js',
  plugins: [
    getBabelOutputPlugin({
      presets: ['@babel/preset-env'],
    }),
  ],
  output: [
    { file: 'bundle.cjs.js', format: 'cjs' },
    { file: 'bundle.es.js', format: 'es' },
  ],
};
```

2. 局部转义：你还可以对某些特定的输出进行转义，而不是全部输出进行转义

```js
// rollup.config.js
import { getBabelOutputPlugin } from '@rollup/plugin-babel';

export default {
  input: 'main.js',
  output: [
    { file: 'bundle.js', format: 'es' },
    {
      file: 'bundle.es5.js',
      format: 'es',
      plugins: [getBabelOutputPlugin({ presets: ['@babel/preset-env'] })],
    },
  ],
};
```

### 配置项

| 配置项             | 类型                                               | 默认值                                   | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | -------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| exclude            | `String \| RegExp \| Array<String \| RegExp>`      | —                                        | 指定在构建过程中应忽略的文件（不进行 Babel 转译）。当使用外部 Babel 配置文件（如 `.babelrc`）时，此选项仅用于额外排除文件，不能覆盖 Babel 配置中已有的包含/排除规则。                                                                                                                                                                                                                                                                          |
| include            | `String \| RegExp \| Array<String \| RegExp>`      | —                                        | 指定插件应处理的文件。注意：如果某个文件已被 Babel 配置文件（如 `babel.config.js`）显式排除，则即使在此 include 中匹配，也不会被处理。                                                                                                                                                                                                                                                                                                         |
| filter             | `(id: string) => boolean`                          | —                                        | 自定义过滤函数，用于精确控制是否对某个模块 ID 进行转译。通常通过 `createFilter(include, exclude)` 生成（来自 `@rollup/pluginutils`）。                                                                                                                                                                                                                                                                                                         |
| extensions         | `Array<String>`                                    | `['.js', '.jsx', '.es6', '.es', '.mjs']` | 指定哪些文件扩展名应被 Babel 转译。若需支持 TypeScript，必须手动添加 `'.ts'` 和 `'.tsx'`。                                                                                                                                                                                                                                                                                                                                                     |
| babelHelpers       | `'bundled' \| 'runtime' \| 'inline' \| 'external'` | `'bundled'`                              | 控制 Babel 辅助函数（helpers）的注入方式：<br>• `'bundled'`：将辅助函数打包进输出 bundle（推荐用于应用）<br>• `'runtime'`：从 `@babel/runtime` 导入（推荐用于库，需配合 `@babel/plugin-transform-runtime` 并将 `@babel/runtime` 设为依赖，同时在 Rollup 中设为 external）<br>• `'inline'`：每个文件内联辅助函数（不推荐，会导致重复代码）<br>• `'external'`：引用全局 `babelHelpers` 对象（高级用法，需配合 `@babel/plugin-external-helpers`） |
| skipPreflightCheck | `Boolean`                                          | `false`                                  | 是否跳过插件启动时的预检（preflight check）。该检查用于验证 Babel 配置是否有效，但在大型项目中可能拖慢构建速度。若你确信配置正确，可设为 `true` 以提升构建性能。                                                                                                                                                                                                                                                                               |

### Babel 配置文件

除了直接传入 Babel 配置项以外，你还可以通过加载配置文件的形式。但`getBabelOutputPlugin(...)`不会自动搜索 Babel 配置文件，所以你需要指定配置文件的路径：

```js
getBabelOutputPlugin({
  configFile: path.resolve(__dirname, 'babel.config.js'),
});
```

::: tip 关于 bable 配置文件
Babel 配置文件可以是 `.babelrc` 或 `babel.config.js`，具体取决于你使用的是 `Babel 7` 还是 `Babel 6`。
:::

### 插件执行顺序

需要注意将`@rollup/plugin-commonjs`需要在`@rollup/plugin-node-resolve`之前进行使用，因为`@rollup/plugin-node-resolve`会将`commonjs`模块转换成`ES6`模块，而`@rollup/plugin-babel`需要转译新生成的 ES 模块中的代码（可能含新语法）。

| 插件                      | 作用                                                                                                          |
| ------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `@rollup/plugin-commonjs` | 将 CommonJS 模块（如 `module.exports`、`require()`）转换为 ES 模块（`import`/`export`），以便 Rollup 能处理。 |
| `@rollup/plugin-babel`    | 使用 Babel 转译 ES 模块中的现代 JavaScript 语法（如 JSX、TypeScript、箭头函数等）为兼容性更好的代码。         |

```js
// 先转换 CJS → ES，再用 Babel 转译语法
plugins: [
  commonjs(),        // 第一步：把 require/module.exports 变成 import/export
  babel({ ... })     // 第二步：转译新生成的 ES 模块中的代码（可能含新语法）
]
```

### 使用 ES 模块或 CommonJS 以外的格式

Rollup 默认输出格式是 ES 模块或 CommonJS。但如果你要输出 UMD、IIFE 等格式，而同时又在输出阶段使用 Babel（通过 `getBabelOutputPlugin`），就需要特别注意——因为 Babel 的某些插件会修改导入/导出语句或添加新变量，这可能破坏目标格式的语义（比如在 IIFE 中意外创建全局变量）。解决方案如下：

方案 1：让 Rollup 输出为 es 或 cjs，然后用 Babel 的 preset 将代码进一步转成 UMD/IIFE。

```js
presets: [['@babel/preset-env', { modules: 'umd' }]];
```

方案 2：如果你坚持在 `bundle.generate({ format: 'iife' })` 时使用 `getBabelOutputPlugin`，则必须显式开启：

```js
getBabelOutputPlugin({
  allowAllFormats: true, // ← 允许对非 es/cjs 格式使用 Babel 输出插件
  // ...
});
```

否则插件会报错或行为异常。

### 注入的辅助函数

Babel 在转译某些语法（如 `class`、`async/await`）时，会生成辅助(`helper`)函数（如 `_classCallCheck`、`_asyncToGenerator`）。

问题：如果多个 `chunk` 都用了 `class`，每个都会重复插入 `_classCallCheck`，导致代码膨胀。而且在输出阶段（`generate`），Rollup 已完成模块合并，无法跨 `chunk` 去重。

解决方案：使用 `@babel/plugin-transform-runtime`。该插件会让 Babel 从 `@babel/runtime` 包导入 `helpers`，而不是内联。

```js
rollup.rollup({...})
.then(bundle => bundle.generate({
  format: 'es',
  plugins: [getBabelOutputPlugin({
    presets: ['@babel/preset-env'],
    plugins: [['@babel/plugin-transform-runtime', { useESModules: true }]]
  })]
}))
```

打包后：

```js
// input
export default class Foo {}

// output
import _classCallCheck from '@babel/runtime/helpers/esm/classCallCheck';

var Foo = function Foo() {
  _classCallCheck(this, Foo);
};

export default Foo;
```

## @rollup/plugin-terser

### 介绍

这个插件主要用于压缩生成的`bundle`

### 基本使用

安装：

```bash
yarn add rollup-plugin-terser --dev
# Or with npm:
npm i rollup-plugin-terser --save-dev
```

1. 用作输入插件使用：

```js
import { rollup } from 'rollup';
import { terser } from 'rollup-plugin-terser';

rollup({
  input: 'main.js',
  plugins: [terser()],
});
```

2. 用作输出插件使用：

```js
// rollup.config.js
import { terser } from 'rollup-plugin-terser';

export default {
  input: 'index.js',
  output: [
    { file: 'lib.js', format: 'cjs' },
    { file: 'lib.min.js', format: 'cjs', plugins: [terser()] },
    { file: 'lib.esm.js', format: 'esm' },
  ],
};
```

### 配置项

| 配置项              | 类型                | 默认值      | 说明                                                                                |
| ------------------- | ------------------- | ----------- | ----------------------------------------------------------------------------------- |
| `ecma`              | `number`            | `undefined` | 指定输出 JS 的 ECMAScript 版本（如 `5`, `2015`, `2020`）。设为 `5` 可兼容旧浏览器。 |
| `compress`          | `boolean \| object` | `{}`        | 启用代码压缩。可传对象进行细粒度控制（如 `drop_console: true`）。                   |
| `mangle`            | `boolean \| object` | `{}`        | 启用变量名混淆（如 `a`, `b`, `c`）。可配置保留名（`reserved: ['myVar']`）。         |
| `format` / `output` | `object`            | `{}`        | 控制输出格式（如是否保留注释、引号类型等）。Terser v5+ 推荐用 `format`。            |
| `keep_fnames`       | `boolean`           | `false`     | 是否保留函数名（对 `Function.prototype.name` 有影响，调试或某些库需要）。           |
| `module`            | `boolean`           | `false`     | 设为 `true` 表示输入是 ES 模块（启用模块优化，如移除顶层 `"use strict"`）。         |
| `safari10`          | `boolean`           | `false`     | 修复 Safari 10 的语法兼容性问题（如 `let` 在循环中的作用域 bug）。                  |
| `toplevel`          | `boolean`           | `false`     | 允许在顶层作用域进行变量/函数压缩和混淆（适用于 IIFE 或模块打包）。                 |
