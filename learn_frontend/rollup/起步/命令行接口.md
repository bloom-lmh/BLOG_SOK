## 配置文件

### 配置文件与命令行

`Rollup` 通常应该从命令行使用。但你可以提供可选的 `Rollup` 配置文件来简化命令行使用并启用高级 `Rollup` 功能。要将 `Rollup` 与配置文件一起使用，请传递 `--config` 或 `-c` 标志

```bash
# pass a custom config file location to Rollup
rollup --config my.config.js

# if you do not pass a file name, Rollup will try to load
# configuration files in the following order:
# rollup.config.mjs -> rollup.config.cjs -> rollup.config.js
rollup --config
```

`Rollup` 配置文件是可选的，但它们功能强大且方便，因此推荐使用。

### 多种配置文件类型

配置文件是一个 ES 模块,通常，它称为 `rollup.config.js` 或 `rollup.config.mjs`，位于项目的根目录中,它导出带有所需选项的默认对象：

```js
export default {
  input: 'src/main.js',
  output: {
    file: 'bundle.js',
    format: 'cjs',
  },
};
```

::: tip 使用`commonJS`模块的配置文件
如果你想使用 `require` 和 `module.exports` 将配置编写为 `CommonJS` 模块，则应将文件扩展名更改为 `.cjs`
:::

::: warning 注意
除非使用 `--configPlugin` 或 `--bundleConfigAsCjs` 选项，否则 `Rollup` 将直接使用 `Node` 来导入文件。
:::

### 多输入和输出

你可以从配置文件中导出一个数组，以便同时从多个不相关的输入构建打包包，即使在监视模式下也是如此。要使用相同的输入构建不同的包，你需要为每个输入提供一组输出选项:

```js
// rollup.config.js (building more than one bundle)

export default [
  {
    input: 'main-a.js',
    output: {
      file: 'dist/bundle-a.js',
      format: 'cjs',
    },
  },
  {
    input: 'main-b.js',
    output: [
      {
        file: 'dist/bundle-b1.js',
        format: 'cjs',
      },
      {
        file: 'dist/bundle-b2.js',
        format: 'es',
      },
    ],
  },
];
```

### 异步配置

如果你想异步创建配置，`Rollup` 还可以处理解析为对象或数组的 `Promise`。

```js
// rollup.config.js
import fetch from 'node-fetch';

export default fetch('/some-remote-service-which-returns-actual-config');
```

同样，你也可以这样做：

```js
// rollup.config.js (Promise resolving an array)
export default Promise.all([fetch('get-config-1'), fetch('get-config-2')]);
```

::: tip 使用场景

- 配置上云（云端配置管理）​​
- 多配置并行获取

:::

### 配置智能感知

由于 `Rollup` 附带 `TypeScript` 类型，因此你可以利用 IDE 的 Intellisense 和 JSDoc 类型提示：

```js
// rollup.config.js
/**

 * @type {import('rollup').RollupOptions}
 */
const config = {
  /* your config */
};
export default config;
```

或者，你可以使用 `defineConfig` 辅助程序，它应该提供 Intellisense，而不需要 JSDoc 注释：

```js
// rollup.config.js
import { defineConfig } from 'rollup';

export default defineConfig({
  /* your config */
});
```

或者，直接使用 `TypeScript` 配置文件

```ts
import type { RollupOptions } from 'rollup';

const config: RollupOptions = {
  input: 'src/index.js',
  output: {
    file: 'dist/bundle.js',
    format: 'es',
  },
};

export default config;
```

### 运行配置中使用`CommonJS`语法`--bundleConfigAsCjs`

此选项将强制将你的配置转换为 `CommonJS`。这允许你在配置中使用 `CommonJS` 习惯用法，例如 `__dirname` 或 `require.resolve`，即使配置本身是作为 ES 模块编写的。

### 指定导入属性关键字`--configImportAttributesKey <with | assert>`

控制 `Rollup` 在配置文件中用于导入属性的关键字。

```bash
rollup --config rollup.config.ts --configPlugin typescript --configImportAttributesKey with
```

此选项仅在使用 `--configPlugin` 或 `--bundleConfigAsCjs` 选项时可用。

```js
import json from './data.json' with { type: 'json' };
```

::: tip 提示
这个选项主要为了解决不同 `JavaScript/TypeScript` 版本间 `import` 属性语法的兼容性问题，让开发者可以明确指定 `Rollup` 使用哪种语法来解析配置文件中的模块导入。
:::

### 设置配置文件处理插件`--configPlugin <plugin>`

正常情况下，`Rollup` 的配置文件是 `JavaScript` 文件（`rollup.config.js`）。但有了 `--configPlugin`，你可以：

- 用 `​TypeScript`​ 写配置文件（`rollup.config.ts`）
- 用其他语言或格式写配置
- 让插件在 `Rollup` 读取配置之前先处理配置文件

```bash
rollup --config rollup.config.ts --configPlugin @rollup/plugin-typescript
```

这表示：

- `--config rollup.config.ts`：使用 `TypeScript` 文件作为配置文件
- `--configPlugin @rollup/plugin-typescript`：用 `TypeScript` 插件先把 `.ts` 文件转成 `JavaScript`，再给 `Rollup` 使用

::: warning 注意
`@rollup/plugin-typescript`会读取并使用 `tsconfig.json`中的配置,所以你在`tsconfig.json`中把`rollup.config.ts`文件包含进来

```json
{
  "include": ["src/**/*", "rollup.config.ts"]
}
```

:::
::: tip 语法简写
该选项支持与 `--plugin` 选项相同的语法，即你可以多次指定该选项，你可以省略 `@rollup/plugin-` 前缀，只写 `typescript`，同时你可以通过 `={...}` 指定插件选项

```bash
# 完整写法
rollup --config rollup.config.ts --configPlugin @rollup/plugin-typescript

# 简化写法（自动补全 @rollup/plugin- 前缀）
rollup --config rollup.config.ts --configPlugin typescript

# 带选项的写法
rollup --config rollup.config.ts --configPlugin typescript={compilerOptions:{}}
```

:::

### 指定环境变量`--environment <values>`

`--environment`选项允许你通过 `process.env`向 `Rollup` 配置文件传递自定义环境变量。

```bash
rollup -c --environment INCLUDE_DEPS,BUILD:production
```

可以多次使用 `--environment` 选项，后设置的变量会覆盖之前的定义：

```bash
rollup -c --environment BUILD:production --environment BUILD:development
```

在 `package.json` 中的实际应用

```json
{
  "scripts": {
    "build": "rollup -c --environment INCLUDE_DEPS,BUILD:production"
  }
}
```

### 失败时结束构建--failAfterWarnings

构建完成后，如果出现任何警告，则退出构建并显示错误。

### 过滤日志--filterLogs `<filter>`

`--filterLogs`选项允许您基于自定义条件筛选 `Rollup` 的日志输出，只显示您关心的日志信息。

::: code-group

```bash [基础键值对过滤]
# 只显示 code 为 'EVAL' 的日志
rollup -c --filterLogs code:EVAL

# 只显示包含特定消息的日志
rollup -c --filterLogs message:"This is the message"
```

```bash [排除特定日志（否定过滤）​]
# 显示除循环依赖警告外的所有日志
rollup -c --filterLogs "!code:CIRCULAR_DEPENDENCY"
```

```bash [​多条件过滤]
# 显示 code 为 FOO 或 BAR，或者消息包含指定文本的日志
rollup -c --filterLogs "code:FOO,message:This is the message" --filterLogs code:BAR
```

:::

::: tip code 的含义
`code`是 `Rollu`p 内部给每条日志分配的唯一标识符，用于区分不同类型的构建消息。当 `Rollup` 在构建过程中遇到不同情况时，会使用特定的 `code` 来标记日志。
:::
下面是高级过滤语法：

::: code-group

```bash [通配符匹配]
# 显示 code 以 _ERROR 结尾的日志
# 或消息中包含 "error" 的日志
rollup -c --filterLogs "code:*_ERROR,message:*error*"
```

```bash [多条件交集（AND 逻辑）​]
# 只显示同时满足两个条件的日志
rollup -c --filterLogs "code:CIRCULAR_DEPENDENCY&ids:*main.js*"
```

```bash [​嵌套属性支持]
# 过滤嵌套属性 log.foo.bar
rollup -c --filterLogs "foo.bar:value"
```

:::

### 强制退出--forceExit

完成后强制退出进程。在某些情况下，插件或其依赖可能无法正确清理并阻止 CLI 进程退出。根本原因可能很难诊断，而此标志提供了一个应急方案，直到可以识别和解决它。
请注意，这可能会破坏某些工作流程并且并不总是正常工作。

### 指定插件-p `<plugin>`

使用指定的插件。这里有几种指定插件的方法：
::: code-group

```bash [通过相对路径]
# 该文件应该导出一个返回插件对象的函数。
rollup -i input.js -f es -p ./my-plugin.js
```

```bash [通过 npm 包名]
# 通过安装在本地或全局 node_modules 文件夹中的插件的名称
rollup -i input.js -f es -p @rollup/plugin-node-resolve
# 如果插件名称不是以 rollup-plugin- 或 @rollup/plugin- 开头，Rollup 将自动尝试添加这些前缀
rollup -i input.js -f es -p node-resolve
```

```bash [通过内联实现]
rollup -i input.js -f es -p '{transform: (c, i) => `/* ${JSON.stringify(i)} */\n${c}`}'
```

:::
如果你想加载多个插件，你可以重复该选项或提供以逗号分隔的名称列表：

```bash
rollup -i input.js -f es -p node-resolve -p commonjs,json
```

默认情况下，将不带参数调用插件函数来创建插件。但是，你也可以传递自定义参数：

```bash
rollup -i input.js -f es -p 'terser={output: {beautify: true, indent_level: 2}}'
```

### 消除警告--silent

不要将警告打印到控制台。如果你的配置文件包含 `onLog` 或 `onwarn` 处理程序，则仍会调用该处理程序。对于带有 `onLog` 钩子的插件也是如此。为了防止这种情况，请另外使用 `logLevel` 选项或传递 `--logLevel silent`。

### 监听文件变化-w

当磁盘上的源文件发生更改时，重新构建打包包。在监听模式下，`Rollup` 会设置环境变量 `ROLLUP_WATCH="true"`，其他进程可以检测到这个变量。

监听事件钩子:
`--watch.onStart <cmd>`: 在监听器启动时 ​（但在第一次构建之前）执行命令。
`--watch.onBundleStart <cmd>`: 在每次构建开始前执行命令。
`--watch.onBundleEnd <cmd>`: 在每次构建成功结束后执行命令。
`--watch.onEnd <cmd>`: 在监听器停止运行 ​（例如，通过 `Ctrl+C` 退出）时执行命令。
`--watch.onError <cmd>`: 在构建过程中发生错误时执行命令。

```bash
rollup -c --watch --watch.onEnd="node ./afterBuildScript.js"
```

## 与 JavaScript API 的差异

`Rollup`支持通过编写`JS`代码来进行配置，这种方式可以理解为编程式的配置方式。

1. 配置文件方式：`RollUp` 来帮你加载配置文件进行打包（声明式）
2. `JavaScript API`方式：使用 `node` 运行代码来完成打包（编程式）

比如下面

```js
// build.js
import rollup from 'rollup';

const inputOptions = { input: 'src/main.js' };
const outputOptions = { file: 'dist/bundle.js', format: 'es' };

const bundle = await rollup.rollup(inputOptions);
await bundle.write(outputOptions);
```
