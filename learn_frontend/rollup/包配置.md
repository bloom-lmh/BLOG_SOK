# 包配置

在使用`rollup`来打包包时，通常需要`package.json`来进行配合使用

## 模块入口

一般来说会使用打包工具将一个库会打包为多种格式，以适应不同的环境，比如

- 打包为`esm`格式：这个格式用于在现代浏览器和 Node.js 环境中使用
- 打包为`cjs`格式：这个格式用于在 Node.js 环境中使用
- 打包为`umd`格式：这个格式用于在浏览器环境中使用

那么，对于打包后的包，我们需要在`package.json`中配置基于不同环境的入口

### main/module

`main` 和 `module` 字段都是用于指定包的入口文件的，但是它们的用法有些不同

- `main` 字段用于指定包的默认入口文件，通常是 `CJS` 格式
- `module` 字段用于指定包的 `ESM` 格式入口文件，通常是 `ESM` 格式

```json
{
  "main": "./dist/index.cjs.js",
  "module": "./dist/index.esm.js"
}
```

::: warning 他们的缺点

1. `main` 只能指定一个入口（通常是 `CJS`）
2. `module` 是非标准字段，行为不统一
3. 用户可能意外导入内部文件（如 `require('mylib/src/utils')`），导致破坏性变更
4. 无法根据环境（`ESM vs CJS`、`Node vs Browser`）返回不同文件
   :::

### exports

`exports` 是现代 `package.json` 中用于精确控制模块入口的官方标准字段。目的取代或增强传统的 `main`、`module`等字段，提供更安全、灵活、环境感知的模块解析规则

1. 单入口（替代 `main`）

```json
{
  "exports": "./dist/index.js"
}
// 等价于：
{
  "main": "./dist/index.js"
}
// 但是他比`main`更加严格，禁止访问包内其他未声明的文件
```

2. 条件导出

```json
"exports": {
    ".": {
      // 当用户写 `import ... from 'mylib'` → 加载 `index.esm.js`
      "import": "./dist/index.esm.js",
      // 当用户写 `require('mylib')` → 加载 `index.cjs.js`
      "require": "./dist/index.cjs.js",
      // `default` 是兜底（兼容旧环境）
      "default": "./dist/index.cjs.js"
    }
  }
```

3. 子路径导出

```json
{
  "exports": {
    ".": {
      "import": "./dist/index.esm.js",
      "require": "./dist/index.cjs.js"
    },
    "./button": {
      "import": "./dist/button.esm.js",
      "require": "./dist/button.cjs.js"
    },
    "./utils/*": "./dist/utils/*.js"
  }
}
```

::: tip exports 的封闭性
一旦使用 `exports`，包就变成封闭的用户只能导入 `exports` 中显式声明的路径
:::
