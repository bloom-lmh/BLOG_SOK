# 输出配置选项

[[toc]]

## 基础配置

### 单文件输出--output.file

要写入的文件。如果适用的话，还将用于生成源映射。仅当生成的块不超过 `1` 个时才可使用。

### 目录输出--output.dir

放置所有生成块的目录。如果生成多个块，则需要此选项。否则，可以使用 `file` 选项来代替。
使用场景如下：

1. 你的项目有多个入口点 ​（`input: { a: 'src/a.js', b: 'src/b.js' }`）。
2. 你的项目使用了代码分割，比如动态导入（`import('./module.js')`），这会导致 Rollup 自动生成多个“块”（`chunk`）文件。

### 输出格式--output.format

指定生成的包的格式。以下之一：

1. `amd` - 异步模块定义，与 `RequireJS` 等模块加载器一起使用
2. `cjs` - `CommonJS`，适用于 `Node` 和其他打包器（别名：commonjs）
3. `es` - 将打包包保留为 `ES` 模块文件，适合其他打包程序并作为 `<script type=module>` 标签包含在现代浏览器中（别名：`esm、module`）
4. `iife` - 自执行函数，适合作为 `<script>` 标签包含在内。（如果你想为你的应用创建打包包，你可能需要使用它。）。"生活" 代表“立即调用 函数表达式”
5. `umd` - 通用模块定义，可作为 `amd、cjs` 和 `iife` 合一使用
6. `system` - `SystemJS` 加载器的原生格式（别名：`systemjs`）

### 指定外部指定的依赖 --output.globals

指定 `umd/iife` 打包包中外部导入所需的 `id: variableName` 对。例如，在这样的情况下

```js
import $ from 'jquery';
```

我们想告诉 `Rollup jquery`是外部的，`jquery` 模块 `ID` 等于全局 `$` 变量：

```js
// rollup.config.js
export default {
  // ...
  external: ['jquery'],
  output: {
    format: 'iife',
    name: 'MyBundle',
    globals: {
      jquery: '$',
    },
  },
};

/*
var MyBundle = (function ($) {
  // code goes here
}($));
*/
```

::: tip 理解 globals 映射
想象一下，你的源代码和浏览器是两个说不同语言的人。

1. 源代码（说“模块语”）​​：你的代码是用现代 `JavaScript` 模块语法写的，它这样说：“我需要 `jquery`这个模块。”

```js
import $ from 'jquery'; // 源代码的“语言”
```

2. ​ 浏览器环境（说“全局变量语”）​​：当你通过 `<script>`标签直接把 `jQuery` 引入 `HTML` 时，`jQuery` 会向浏览器窗口（`window对象`）上挂载一个全局变量 `$`。浏览器只认识这个全局变量。它期待你的代码这样说：“我需要 `window.$`这个全局变量。”。

```html
<script src="https://code.jquery.com/jquery.js"></script>
<script src="your-bundle.js"></script>
<!-- 浏览器里现在有了 window.$ 这个变量 -->
```

现在，`Rollup` 的角色就是一个“翻译官”。它的任务是把你的“模块语”源代码，翻译成浏览器能直接理解的“全局变量语”脚本。`​globals`选项，就是你给 `Rollup` 这个“翻译官”的“词典”！

转换前（源代码）：

```js
import $ from 'jquery';
// ... 你的业务代码，使用 $
```

​ 转换后（打包生成的 `iife/umd` 文件）：

```js
var MyBundle = (function ($) {
  // 这里！jquery 模块被替换成了全局变量 $ 作为参数传入
  // ... 你的业务代码，使用 $
})($); // 这里！把外部的全局变量 $ 传进去
```

从本质来说：就是因为浏览器不会去 `node_modules`下寻找包，所以我们才需要 `external`和 `globals`这个组合，手动建立一个“接线图”，告诉打包工具如何将模块化的导入语句“转译”成对浏览器全局变量的引用。​
:::

或者，提供一个函数将外部模块 ID 转换为全局变量名称。
当作为命令行参数给出时，它应该是逗号分隔的 `id:variableName` 对列表：

```bash
rollup -i src/main.js ... -g jquery:$,underscore:_
```

要告诉 Rollup 本地文件应该替换为全局变量，请使用绝对 id：

```bash
// rollup.config.js
import { fileURLToPath } from 'node:url';
const externalId = fileURLToPath(
	new URL(
		'src/some-local-file-that-should-not-be-bundled.js',
		import.meta.url
	)
);

export default {
	//...,
	external: [externalId],
	output: {
		format: 'iife',
		name: 'MyBundle',
		globals: {
			[externalId]: 'globalVariable'
		}
	}
};
```

### 输出文件名--output.name

对于导出格式为 `iife/umd` 的包是必需的，在这种情况下，它是代表你的包的全局变量名称。同一页面上的其他脚本可以使用此变量名称来访问打包包的导出。

```js
// rollup.config.js
export default {
  // ...
  output: {
    file: 'bundle.js',
    format: 'iife',
    name: 'MyBundle',
  },
};

// var MyBundle = (function () {...
```

支持命名空间，即你的名称可以包含点。生成的包将包含命名空间所需的设置。

```js
rollup -n "a.b.c"

/* ->
this.a = this.a || {};
this.a.b = this.a.b || {};
this.a.b.c = ...
*/
```

### 使用插件--output.plugins

```js
// rollup.config.js
import terser from '@rollup/plugin-terser';

export default {
  input: 'main.js',
  output: [
    {
      file: 'bundle.js',
      format: 'es',
    },
    {
      file: 'bundle.min.js',
      format: 'es',
      plugins: [terser()],
    },
  ],
};
```

## 高级配置

### 控制打包后生成的文件命名规则--output.entryFileNames

​ 作用 ​：控制打包后生成的文件命名规则。
默认情况下，`Rollup` 会生成 `index-[hash].js`这样的文件名。通过这个配置，你可以自定义命名规则，例如为入口文件和代码分割产生的块（`chunk`）设置不同的命名格式，这对于管理缓存和自动化部署非常有用。
示例 ​：

```js
output: {
  entryFileNames: '[name]-[hash].js', // 入口文件命名
  chunkFileNames: 'chunks/[name]-[hash].js', // 代码分割块命名，并放入 chunks 目录
}
```

### 控制静态资源--output.assetFileNames

​ 作用 ​：控制静态资源（如图片、CSS 文件）在打包后的命名和位置。
​ 为什么常用 ​：如果你的项目引入了图片或 `CSS`，`Rollup` 会将它们作为资源文件处理。这个选项让你能像管理 JS 文件一样管理这些资源文件的输出路径和名称。

### 源码映射--output.sourcemap

作用 ​：生成源码映射文件，方便调试。能将压缩合并后的代码映射回原始源代码。

​ 常用值 ​：

1. `true`：生成独立的 `.js.map`文件。
2. `'inline'`：将源码映射作为 `Data URL` 内联在 JS 文件中。
3. `'hidden'`：生成 `.map`文件，但浏览器开发者工具不会自动加载，除非手动指定。

使用场景 ​：​ 几乎所有项目的开发环境都会开启。生产环境通常关闭以保护源码和减小体积。

### 控制如何生成代码--output.generatedCode

作用 ​：非常精细地控制 `Rollup` 如何生成代码（例如，是否使用箭头函数、`const` 声明等）。
​ 使用场景 ​：需要确保输出代码与特定老旧环境兼容时的“最后手段”。大多数情况下，使用 `@rollup/plugin-babel`是更好的选择。

### 代码压缩--​output.compact

作用 ​：压缩输出代码，删除换行和空格。
使用场景 ​：当你需要尽可能减小文件体积，但又不想使用专门的压缩工具（如 `Terser`）时。注意，这会降低代码可读性。

### 输出信息--output.banner/output.footer

作用 ​：在所有生成的块（`chunk`）的顶部（`banner`）或底部（`footer`）添加一段文本，比如版权信息、注释等。
使用场景 ​：在发布库时，在文件顶部添加库的许可证信息。

### 路径别名--output.paths

​ 作用 ​：为外部依赖（`external`）提供自定义的映射路径。
​ 使用场景 ​：当你希望通过 CDN 引入外部库时，这个配置极其有用。
​ 示例 ​：将 `import react from 'react'`替换为 CDN 链接。

```js
// rollup.config.js
export default {
  external: ['react'], // 不打包react
  output: {
    format: 'umd',
    paths: {
      // 映射 'react' 模块ID 到 一个全局变量或URL
      react: 'https://cdn.jsdelivr.net/npm/react/umd/react.production.min.js',
    },
  },
};
```

### 优化入口文件的导出签名--preserveEntrySignatures

作用 ​：控制 Rollup 是否优化入口文件的导出签名。

常用值 ​：

- `'exports-only'`（默认）：如果入口文件没有导出任何内容，则打包后的文件也不会导出。
- `'strict'`：确保入口文件的导出签名与源码完全一致。
- `'allow-extension'`：允许添加导出，但不允许删除。

使用场景 ​：在开发库（Library）​​ 时非常重要，可以确保你的库的 API 导出是稳定和可预测的。对于应用开发，通常用默认值即可。

### 手动代码分割--output.manualChunks

作用 ​：​ 手动代码分割。让你可以自定义如何将代码拆分成不同的块（chunk）。
使用场景 ​：

1. 将所有的第三方库（如 `react, lodash`）打包到一个单独的 `vendor.js`文件中，利用浏览器缓存。
2. 将一些庞大的、非首屏必需的模块（如富文本编辑器、图表库）单独打包，实现按需加载。

### 保留模块的原始文件结构 --output.preserveModules

1. ​ 作用 ​：保留模块的原始文件结构，而不是将它们合并或拆分。
   ​2. 使用场景 ​：主要用于库开发。当你希望使用者可以按需导入你库中的特定文件时（例如 `import { Button } from 'your-lib/components'`），就需要使用这个选项。
