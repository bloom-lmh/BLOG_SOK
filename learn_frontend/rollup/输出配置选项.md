# 输出配置选项

[[toc]]

## 单文件输出--output.file

要写入的文件。如果适用的话，还将用于生成源映射。仅当生成的块不超过 `1` 个时才可使用。

## 输出目录--output.dir

该选项用于指定所有生成的 `chunk` 被放置在哪个目录中。如果生成一个以上的 `chunk`，那么这个选项是必需的。否则，可以使用 `file` 选项来代替

## 输出格式--output.format

该选项用于指定生成的 `bundle` 的格式。满足以下其中之一：

1. `amd` - 异步模块定义，与 `RequireJS` 等模块加载器一起使用
2. `cjs` - `CommonJS`，适用于 `Node` 和其他打包器（别名：commonjs）
3. `es` - 将打包包保留为 `ES` 模块文件，适合其他打包程序并作为 `<script type=module>` 标签包含在现代浏览器中（别名：`esm、module`）
4. `iife` - 自执行函数，适合作为 `<script>` 标签包含在内。（如果你想为你的应用创建打包包，你可能需要使用它。）。"生活" 代表“立即调用 函数表达式”
5. `umd` - 通用模块定义，可作为 `amd、cjs` 和 `iife` 合一使用
6. `system` - `SystemJS` 加载器的原生格式（别名：`systemjs`）

::: warning 注意
iife`和`umd`格式的包不支持代码分割，所以不要在它们的入口文件中使用动态导入等代码分割策略。
:::

更多细节查看[核心概念-多种格式的打包方式](./核心概念.md#多种格式的打包方式)

## 指定模块 ID 和全局变量映射 output.globals

> 一句话概述：在打包为`iife/umd`格式时，告诉 `Rollup` 通过`external`排除的依赖对应的全局变量名是什么。这样在浏览器使用该包时才能正确识别依赖名。

### 作用

当配置了 `globals` 选项后，你的库在打包为`umd / iife` 格式的`bundle`时，会将模块 `ID` 替换为全局变量。比如我们来看一个案例：

1. 源码（`src/index.js`）如下:

```js
// 用到了 `react` 和 `react-dom` 库
import React from 'react';
import { render } from 'react-dom';

export function init() {
  render(<div>Hello</div>, document.getElementById('app'));
}
```

2. 指定 `globals`：`rollup`会将模块 ID 对应的全局变量传入立即执行函数。

::: code-group

```js {10-11} [Rollup 配置]
// rollup.config.js
export default {
  input: 'src/index.js',
  external: ['react', 'react-dom'], // ← 排除这两个依赖
  output: {
    file: 'dist/bundle.iife.js',
    format: 'iife',
    name: 'MyApp',
    globals: {
      react: 'React', // ← 告诉 Rollup：'react' 对应全局变量 React
      'react-dom': 'ReactDOM', // ← 'react-dom' 对应 ReactDOM
    },
  },
};
```

```js {9} [打包后]
var MyApp = (function (React, ReactDOM) {
  'use strict';

  function init() {
    ReactDOM.render(React.createElement('div', null, 'Hello'), document.getElementById('app'));
  }

  return { init: init };
})(React, ReactDOM); // ← 从全局作用域取 React 和 ReactDOM
```

:::

3. 不指定`globals`：那么 `Rollup` 会通过模块 ID 自己推断全局变量名（一般来说就是变为首字母小写并采用驼峰命名法，比如`react-dom`变为`reactDom`）。

```js {9}
var MyApp = (function (React, ReactDOM) {
  'use strict';

  function init() {
    ReactDOM.render(React.createElement('div', null, 'Hello'), document.getElementById('app'));
  }

  return { init: init };
})(react, reactDOM); // rollup推断全局变量为react和reactDOM，但实际上它们对应的是React和ReactDOM
```

这样就会带来问题，即便你同样通过`script`标签引入了`react`和`react-dom`，但由于他们的全局变量名为`React`和`ReactDOM`，这时候就会导致找不到全局变量而报错。

::: tip 理解
当你的库打包为 `iife` 或 `umd` 格式时就只能在浏览器以`<script>`标签的形式引入，并通过全局变量的方式来进行使用，而你的库依赖的库（如 `react`）也需要通过`<script>`标签的形式引入并依赖于的它提供的全局变量`React`。然而如果你没有在`globals`配置 `react: 'React'`的映射，那么你的库就会去寻找名为`react`的全局变量，但实际上`react`库对应的全局变量叫`React`，这时候就会导致找不到全局变量而报错。所以你需要告诉 `Rollup` 全局变量的映射。
:::

### 与 external 搭配使用

这个选项需要和`external`一起使用，因为`external`告诉`Rollup`哪些依赖是外部的，而`globals`告诉`Rollup`这些外部依赖在浏览器变量是什么。

## 输出文件名--output.name

> 一句话概述：打包为`iife/umd`格式的包，在浏览器中使用时的挂载在 `windows` 对象上的全局变量名。

对于导出格式为 `iife/umd` 的包是必需的，在这种情况下，它是代表你的包的全局变量名称。同一页面上的其他脚本可以使用此变量名称来访问打包包的导出。

```js
// rollup.config.js
export default {
  // ...
  output: {
    file: 'bundle.js',
    format: 'iife',
    name: 'MyBundle',
  },
};

// var MyBundle = (function () {...
```

支持命名空间，即你的名称可以包含点。生成的包将包含命名空间所需的设置。

```js
rollup -n "a.b.c"

/* ->
this.a = this.a || {};
this.a.b = this.a.b || {};
this.a.b.c = ...
*/
```

## 使用插件--output.plugins

```js
// rollup.config.js
import terser from '@rollup/plugin-terser';

export default {
  input: 'main.js',
  output: [
    {
      file: 'bundle.js',
      format: 'es',
    },
    {
      file: 'bundle.min.js',
      format: 'es',
      plugins: [terser()],
    },
  ],
};
```

## 控制静态资源文件名称--output.assetFileNames

作用 ​：控制静态资源（如图片、CSS 文件）在打包后的命名和位置。如果你的项目引入了图片或 `CSS`，`Rollup` 会将它们作为资源文件处理。这个选项让你能像管理 JS 文件一样管理这些资源文件的输出路径和名称。
默认：`assets/[name]-[hash][extname]`

::: tip name、hash、extname

这些都叫做占位符，实际打包会替换掉它们。

```markdown
| 占位符      | 示例       | 说明                         |
| ----------- | ---------- | ---------------------------- |
| `[name]`    | `logo`     | 文件原姓名（不含扩展名）     |
| `[ext]`     | `png`      | 扩展名（无点）               |
| `[extname]` | `.png`     | 扩展名（带点）               |
| `[hash]`    | `a1b2c3d4` | 内容哈希（默认 base64 编码） |
| `[hash:8]`  | `a1b2c3d4` | 指定哈希长度为 8 位          |
```

:::
传递函数：当你需要根据资源类型、名称或内容动态决定输出路径时，就用函数：

```js
output: {
  assetFileNames: assetInfo => {
    if (assetInfo.name?.endsWith('.png') || assetInfo.name?.endsWith('.jpg')) {
      return 'images/[name]-[hash][extname]';
    }
    if (assetInfo.name?.endsWith('.woff2')) {
      return 'fonts/[name][extname]';
    }
    return 'assets/[name]-[hash][extname]';
  };
}
```

这个函数接受的参数类型为：

```typescript
interface PreRenderedAsset {
  names: string[];
  originalFileNames: string[];
  source: string | Uint8Array;
  type: 'asset';
}
```

| 属性                | 类型                   | 说明                                                                                                                                          |
| ------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `names`             | `string[]`             | 引用该静态资源的 chunk 名称列表。例如，如果某个 JS chunk 中 import 了一张图片，那么这个 chunk 的名字会出现在这里。                            |
| `originalFileNames` | `string[]`             | 该资源在源代码中的原始文件路径数组。如果有多个地方引用同一个资源（或资源被合并），可能会有多个路径。通常是绝对路径或相对于项目根目录的路径。  |
| `source`            | `string \| Uint8Array` | 资源的原始内容。文本类资源（如 CSS、SVG）通常是 string，二进制资源（如 PNG、字体）则是 Uint8Array。注意：在某些插件处理后，内容可能已被转换。 |
| `type`              | `'asset'`              | 固定值，标识这是一个静态资源（区别于 chunk 或 entry）。                                                                                       |

## 控制打包后生成的文件命名规则--output.entryFileNames

作用 ​：控制打包后生成的文件命名规则。
默认情况下，`Rollup` 会生成 `index-[hash].js`这样的文件名。通过这个配置，你可以自定义命名规则，例如为入口文件和代码分割产生的块（`chunk`）设置不同的命名格式，这对于管理缓存和自动化部署非常有用。
示例 ​：

```js
output: {
  entryFileNames: '[name]-[hash].js', // 入口文件命名
  chunkFileNames: 'chunks/[name]-[hash].js', // 代码分割块命名，并放入 chunks 目录
}
```

## 源码映射--output.sourcemap

作用 ​：生成源码映射文件，方便调试。能将压缩合并后的代码映射回原始源代码。

​ 常用值 ​：

1. `true`：生成独立的 `.js.map`文件。
2. `'inline'`：将源码映射作为 `Data URL` 内联在 JS 文件中。
3. `'hidden'`：生成 `.map`文件，但浏览器开发者工具不会自动加载，除非手动指定。

使用场景 ​：​ 几乎所有项目的开发环境都会开启。生产环境通常关闭以保护源码和减小体积。

## 控制如何生成代码--output.generatedCode

作用 ​：非常精细地控制 `Rollup` 如何生成代码（例如，是否使用箭头函数、`const` 声明等）。
​ 使用场景 ​：需要确保输出代码与特定老旧环境兼容时的“最后手段”。大多数情况下，使用 `@rollup/plugin-babel`是更好的选择。

## 代码压缩--​output.compact

作用 ​：压缩输出代码，删除换行和空格。
使用场景 ​：当你需要尽可能减小文件体积，但又不想使用专门的压缩工具（如 `Terser`）时。注意，这会降低代码可读性。

## 输出信息--output.banner/output.footer

作用 ​：在所有生成的块（`chunk`）的顶部（`banner`）或底部（`footer`）添加一段文本，比如版权信息、注释等。
使用场景 ​：在发布库时，在文件顶部添加库的许可证信息。

## 路径别名--output.paths

​ 作用 ​：为外部依赖（`external`）提供自定义的映射路径。
​ 使用场景 ​：当你希望通过 CDN 引入外部库时，这个配置极其有用。
​ 示例 ​：将 `import react from 'react'`替换为 CDN 链接。

```js
// rollup.config.js
export default {
  external: ['react'], // 不打包react
  output: {
    format: 'umd',
    paths: {
      // 映射 'react' 模块ID 到 一个全局变量或URL
      react: 'https://cdn.jsdelivr.net/npm/react/umd/react.production.min.js',
    },
  },
};
```

## 优化入口文件的导出签名--preserveEntrySignatures

作用 ​：控制 Rollup 是否优化入口文件的导出签名。

常用值 ​：

- `'exports-only'`（默认）：如果入口文件没有导出任何内容，则打包后的文件也不会导出。
- `'strict'`：确保入口文件的导出签名与源码完全一致。
- `'allow-extension'`：允许添加导出，但不允许删除。

使用场景 ​：在开发库（Library）​​ 时非常重要，可以确保你的库的 API 导出是稳定和可预测的。对于应用开发，通常用默认值即可。

## 手动代码分割--output.manualChunks

作用 ​：​ 手动代码分割。让你可以自定义如何将代码拆分成不同的块（chunk）。
使用场景 ​：

1. 将所有的第三方库（如 `react, lodash`）打包到一个单独的 `vendor.js`文件中，利用浏览器缓存。
2. 将一些庞大的、非首屏必需的模块（如富文本编辑器、图表库）单独打包，实现按需加载。

## 保留模块的原始文件结构 --output.preserveModules

1. ​ 作用 ​：保留模块的原始文件结构，而不是将它们合并或拆分。
   ​2. 使用场景 ​：主要用于库开发。当你希望使用者可以按需导入你库中的特定文件时（例如 `import { Button } from 'your-lib/components'`），就需要使用这个选项。
