# 输入配置选项

[[toc]]

## 介绍

### 基本概念

输入选项主要是去控制打包源代码时的行为，比如指定入口点、哪些依赖不打包进`bundle`等

### 输入配置选项

下面会展示完整的输入配置选项。

```js
const inputOptions = {
  // 核心选项
  // 要排除的外部模块，如果你这么做了，那么这些模块就不会被打包进最终的 bundle
  external,
  // 打包时的入口文件，可以是单个文件，也可以是多个文件
  input,
  // 插件列表，可以用来辅助打包过程
  plugins,

  // 进阶选项
  cache,
  logLevel,
  makeAbsoluteExternalsRelative,
  maxParallelFileOps,
  onLog,
  onwarn,
  preserveEntrySignatures,
  strictDeprecations,

  // danger zone
  context,
  moduleContext,
  preserveSymlinks,
  shimMissingExports,
  treeshake,

  // experimental
  experimentalCacheExpiry,
  experimentalLogSideEffects,
  perf,
  fs,
};
```

## 外部模块-external

> 一句话概述就是，告诉 Rollup 哪些模块不要打包进最终的 bundle ，而是让用户来提供，用户提供依赖的两种方式：
>
> 1.  非浏览器（采用 esm 或 cjs 包时）：通过对等依赖提示 npm 下载
> 2.  浏览器（采用 iife 或 umd 包时）：script 标签引入依赖

### 什么是 external？

`external` 的作用就是告诉 `Rollup` 哪些模块不要打包进最终 `bundle`，仅仅保留原始 `import/require` 语句，让它们在运行时由外部提供。比如

1. 浏览器环境中通过 `CDN`引入依赖
2. 第三方库，如由用户自己安装
3. 内置依赖，如 `node` 内置模块，由`node`环境提供

> 比如我的库中用到了 `React`、`React-dom`，但我并不想把它们打包进最终的 `bundle`，而是让它们在运行时由用户自己安装。这时候就可以用 `external` 配置项。用户下载了我的库后，只需要安装 `React`、`React-dom` 这两个依赖，就可以正常使用。
> 同样如果他们是在浏览器通过`script`标签引入我的库，则同样使用`script`标签引入`React`和`React-dom`依赖也行。

### external 的好处

使用 `external` 有以下好处：

1. 减少打包体积：由于 `external` 告诉 `Rollup` 不要打包进最终 `bundle`，所以可以减少最终 `bundle` 的体积。
2. 避免依赖版本冲突：你的库打包了 `react@18`，而用户安装了 `react@17`，就会导致依赖版本冲突。

### external 支持的写法

1. 字符串数组：必须和`import`语句中的模块名完全一致

```js
external: ['react', 'react-dom'];
```

2. 正则表达式：可以匹配到符合条件的模块名从而进行批量匹配

```js
// 1. /^lodash/ → 将 lodash、lodash-es 等模块排除在外
// 2. 将所有来自 node_modules 的模块排除在外
external: [/^lodash/, /node_modules/];
```

::: warning 注意
使用正则 `/node_modules/` 前，必须用 `@rollup/plugin-node-resolve`插件,这是因为默认情况下，`import 'react'` 的模块 `ID` 就是 `'react'`（字符串），用了 `node-resolve` 插件后，它会被解析成类似 `/project/node_modules/react/index.js` 的绝对路径，这时 `/node_modules/` 正则才能匹配上
:::

3. 函数：可以自定义匹配规则，实现更细粒度的控制

```js
external(id, parentId, isResolved) {
  // id: 当前模块的 ID（如 'react' 或 '/abs/path/to/file.js'）
  // parentId: 引入它的父模块路径
  // isResolved: 是否已被插件解析为绝对路径

  if (id === 'react') return true;
  if (id.includes('node_modules')) return true;
  return false;
}
```

4. 绝对路径：排除本地文件，如果不希望本地某个文件被打包进最终 `bundle`，可以用绝对路径的方式排除、

```js
import { fileURLToPath } from 'node:url';

const __filename = fileURLToPath(import.meta.url);
const externalFile = path.resolve(path.dirname(__filename), 'src/utils.js');

export default {
  external: [externalFile],
};
```

### 与 globals 配合使用

当你打包时，使用了 `iife` 或 `umd` 格式，并且设置了 `external`字段排除了某些库（如 `react`）时，就需要显示的指定这些库的`ID`与该库对应的`iife/umd`模块的全局变量的映射关系。比如：

```js
export default {
  external: ['react'],
  output: {
    format: 'iife',
    name: 'MyLib',
    globals: {
      // 告诉 Rollup react 对应的全局变量叫 React
      react: 'React',
    },
  },
};
```

这样我们在前面通过`script`标签引入的`React`库，就可以直接使用我们的库了
具体原因参见[输出配置选项-globals](./输出配置选项.md)

### 与对等依赖配合使用

当我们使用 `external` 排除某些依赖时，我们可能还需要使用 `peerDependencies` 来声明对等依赖。这样用户才知道该依赖是必须安装的，否则会导致运行时错误。比如：

```js
// package.json
{
  "name": "my-lib",
  "version": "1.0.0",
  "peerDependencies": {
    "react": "^16.8.0"
  }
}

// rollup.config.js
export default {
  external: ['react'],
  output: {
    format: 'esm',
    dir: 'dist',
  },
};
```

关于对等依赖请参见[包配置](./包配置)

## 入口-input

> 一句话概述：rollup 分析的起点，可以是单入口，也可以是多入口，多入口一定产生多个 chunks。

### 什么是入口

`input`选项指定了 `Rollup` 构建时应该从哪些文件开始分析依赖图（`dependency graph`），这些入口文件最终会被打包成一个或多个输出文件（`chunks`）。

::: warning 注意
同时我们要注意，入口并不一定是顶层的文件，它也可以被其他文件导入。它只是被`input`声明的开始分析依赖图的起点
:::

### 选项值

该选项支持三种类型的值，依据单入口和多入口而不同：

1. 单个入口：字符串形式

```js
input: 'src/main.js';
```

2. 多个入口

::: code-group

```js [数组形式]
input: ['src/a.js', 'src/b.js'];
```

```js [对象形式]
input: {
  app: 'src/main.js',
  'utils/math': 'src/math.js'
}
```

::: warning 多入口注意点
当采用多入口时，`Rollup` 会一定会生成多个 `chunk`。
:::

### 与 entryFileNames 配合使用

`output` 配置项中的 `entryFileNames` 选项可以用来指定入口文件输出文件的模式。

- `[format]`：输出（`output`）选项中定义的格式（`format`），例如 `es` 或 `cjs`。
- `[hash]`：仅基于最终生成的入口 `chunk` 内容的哈希值，其中包括 `renderChunk` 中的转换部分和其依赖文件哈希值。你也可以通过例如 `[hash:10]` 设置一个特定的哈希值长度。默认情况下，它会生成一个 `base-64` 的哈希值。如果你需要减少字符集的大小，可以查看 `output.hashCharacters`。
- `[name]`：入口文件的文件名（不包含扩展名），除非当入口文件为对象时，才用来定义不同的名称。

::: tip 关于对象形式和数组形式的 name
当采用多入口时

1. 若该选项的值为对象形式时，则对象的属性名将作为文件名中的 `[name]`。若对象的属性名含有 `/` 字符，则以用来划分文件到子目录
2. 对于数组形式，数组的值将作为入口文件名。

:::

更多请参见[输出配置选项-entryFileNames](./输出配置选项.md)

### 动态生成 input

当你需要动态的控制打包输出的目录结构，可以使用`glob`库来动态生成`input`配置项。比如我们可以让生成的 `bundle` 文件的目录结构和源文件目录结构保持一致：

```js
import { globSync } from 'glob';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

export default {
  input: Object.fromEntries(
    globSync('src/**/*.js').map(file => [
      // 移除 'src/' 前缀和 .js 后缀，得到相对路径作为 name
      path.relative('src', file.replace(/\.js$/, '')),
      // 转为绝对路径
      fileURLToPath(new URL(file, import.meta.url)),
    ]),
  ),
  output: {
    dir: 'dist',
    format: 'es',
    entryFileNames: '[name].js', // 保持原路径结构
  },
};
```

## 自定义日志处理-onlog

> 一句话概述：onLog 让你接管 Rollup 的日志系统：可以过滤、升级、美化或抑制任何构建过程中的提示、警告和调试信息，实现更灵活的构建体验。

### 作用

作用：当 Rollup 要输出一条日志（比如警告、提示）时，会先调用这个函数。你可以通过这个函数来自定义日志的输出方式。

### 参数说明

```js
onLog(level, log, defaultHandler);
```

| 参数           | 类型                          | 说明                                             |
| -------------- | ----------------------------- | ------------------------------------------------ |
| level          | `'warn' \| 'info' \| 'debug'` | 日志级别                                         |
| log            | `RollupLog` 对象              | 包含具体日志内容和上下文（如文件位置、错误码等） |
| defaultHandler | 函数                          | Rollup 默认的日志处理方式（通常是打印到控制台）  |

### `RollupLog` 对象

```js
// 所有可能的属性，实际包含哪些属性取决于具体的日志内容
interface RollupLog {
  /**
   * 绑定信息（例如模块绑定名），可选
   */
  binding?: string;

  /**
   * 错误原因（通常是嵌套的 Error 对象），可选
   */
  cause?: Error;

  /**
   * 错误或警告的代码（用于分类识别），可选
   */
  code?: string;

  /**
   * 导出该模块的文件路径（在 reexport 场景中使用），可选
   */
  exporter?: string;

  /**
   * 错误发生时的调用栈帧信息（字符串格式），
   * CLI 始终会打印此字段
   */
  frame?: string;

  /**
   * 触发该日志的插件钩子名称（如 'resolveId', 'transform' 等），可选
   */
  hook?: string;

  /**
   * 涉及的模块 ID（通常是文件路径或虚拟 ID），
   * CLI 始终会打印此字段
   */
  id?: string;

  /**
   * 涉及的多个模块 ID 列表，可选
   */
  ids?: string[];

  /**
   * 错误位置信息（列、行号，以及可选的文件路径），
   * 只要存在 id 字段，CLI 就始终会打印 loc
   */
  loc?: {
    column: number, // 列号（从 0 或 1 开始，依上下文而定）
    file?: string, // 文件路径（可选）
    line: number, // 行号
  };

  /**
   * 实际的日志消息内容，
   * CLI 始终会打印此字段
   */
  message: string;

  /**
   * 元数据字段，插件可在此附加自定义属性，
   * 不会被 CLI 自动打印
   */
  meta?: any;

  /**
   * 相关的名称列表（例如导出名、变量名等），可选
   */
  names?: string[];

  /**
   * 生成此日志的插件名称（由 Rollup 自动添加），
   * 仅在警告（warning）日志中被 CLI 打印
   */
  plugin?: string;

  /**
   * 插件提供的错误/警告代码（由 Rollup 自动添加），
   * 通常与 code 字段配合使用，可选
   */
  pluginCode?: string;

  /**
   * 错误在源码中的字符位置偏移（从 0 开始），可选
   */
  pos?: number;

  /**
   * 重新导出（re-export）该模块的文件路径，可选
   */
  reexporter?: string;

  /**
   * 完整的堆栈跟踪信息（stack trace），
   * CLI 始终会打印此字段
   */
  stack?: string;

  /**
   * 提供更多上下文信息的 URL（例如文档链接），可选
   */
  url?: string;
}
```

CLI（命令行）默认会自动打印 message、id、loc、frame、stack、url 等关键字段。

### defaultHandler 怎么用？

它的签名是：

```js
(level: 'warn' | 'info' | 'debug' | 'error', log: string | RollupLog) => void
```

1. 如果你不调用它，日志不会输出到控制台。
2. 如果你调用它，使用 Rollup 默认格式打印。
3. 如果你传 'error' 作为 level 会把日志变成一个抛出的 Error，导致构建失败！

### 常见用法示例

1. 忽略特定警告

```js
onLog(level, log, handler) {
  if (log.code === 'CIRCULAR_DEPENDENCY') {
    return; // 不调用 handler，静默忽略
  }
  handler(level, log); // 其他日志照常打印
}
```

2. 把所有警告变成错误（严格模式）

```js
onLog(level, log, handler) {
  if (level === 'warn') {
    handler('error', log); // 转为错误，构建中断
  } else {
    handler(level, log);
  }
}
```

3. 自定义日志格式（带文件位置）

```js
onLog(level, { loc, frame, message }) {
  if (loc) {
    console.warn(`${loc.file} (${loc.line}:${loc.column}) ${message}`);
    if (frame) console.warn(frame);
  } else {
    console.warn(message);
  }
  // 注意：这里没调用 defaultHandler，所以 Rollup 默认格式不会出现
}
```

## 自定义警告信息-onwarn

一个函数，用于拦截警告信息。它与 onLog 非常相似，但只接收警告。如果调用默认处理程序，日志将被处理为警告。如果提供了 onLog 和 onwarn 处理程序，只有当 onLog 调用其默认处理程序时，onwarn 处理程序才会被调用，且 level 为 warn。
