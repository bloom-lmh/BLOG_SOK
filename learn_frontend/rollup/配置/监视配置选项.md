# 监视

[[toc]]

## 基本介绍

### 完整的选项配置

一个完整的 rollup 选项是一个如下的对象:

```js
let inputOptions = {
  input: 'src/main.js',
  plugins: [
    //...
  ],
};
let rollupOptions = {
  // 输入相关选项
  ...inputOptions,
  // 输出相关选项
  output: {
    file: 'dist/bundle.js',
    format: 'cjs',
    name: 'MyLib',
  },
  // 监控相关选项
  watch: {
    clearScreen: true,
    exclude: 'node_modules/**',
    include: 'src/**',
  },
};
```

也就是说有三个部分构成：

1. 输入选项
2. 输出选项
3. 监控选项

### 监控选项

现在我们就来学习下监控选项配置

```js
interface WatcherOptions {
  /**
   * 它决定了 Rollup 是否允许你的源代码文件夹（输入）放在打包输出的文件夹（输出）里面
   */
  allowInputInsideOutputPath?: boolean;
  /**
   * 当文件发生变化后多少毫秒后才进行打包。其实就是有些类似于防抖
   */
  buildDelay?: number;
  /**
   * rollup底层采用了chokidar来进行文件监视，该选项用于指定要传递给chokidar实例的相关配置，具体看chokidar
   */
  chokidar?: ChokidarOptions;
  /**
   * 触发重建时是否清除屏幕
   */
  clearScreen?: boolean;
  /**
   * 要排除的不进行监视的文件
   */
  exclude?: string | RegExp | (string | RegExp)[];
  /**
   * 指定要监视的文件
   */
  include?: string | RegExp | (string | RegExp)[];
  /**
   * 跳过输出，也就是构建后的文件不会被写入硬盘。比如开发服务器可以直接从内存中读取然后提供给浏览器
   */
  skipWrite?: boolean;
  /**
   *
   */
  onInvalidate?: (id: string) => void;
}
```

该选项用于指定观察模式（watch mode）的选项，所谓观察模式，就是监听你的源代码，当源代码发生变化的时候，重新自动的进行打包。而这些选项就是用来更加精细化控制观察模式的。

## 触发重建时清屏-clearScreen

触发重建时是否清除屏幕。

## 延迟构建-buildDelay

> 一句话概述：其实就是防抖

默认情况下，Rollup 一旦监听到文件变化，会立即触发重新构建。虽然在底层依赖 `chokidar` 中其实配置了一个很小的反跳超时，但逻辑上我们通常视为“立即构建”。这会导致构建进程卡顿、CPU 占用飙升。所以可以设置这个选项，当文件发生变化后，延迟一段时间后再进行构建。

## 排除一些被监视的文件 -exclude

防止文件被监视：

```js
// rollup.config.js
export default {
  // ...
  watch: {
    exclude: 'node_modules/**',
  },
};
```

## 包含要监视的文件-include

将文件监视限制为某些文件。请注意，这仅过滤模块图，但不允许添加额外的监视文件：

```js
// rollup.config.js
export default {
  // ...
  watch: {
    include: 'src/**',
  },
};
```

## 跳过输出-write

触发重建时是否跳过 `bundle.write()` 步骤。其实就是在内存中重新构建，但是不进行`bundle`文件的输出，它有以下作用：

1. 结合开发服务器（Dev Server）使用：服务器直接从内存中读取打包好的内容提供给浏览器，而不是去读硬盘上的文件。内存读取速度及其快可以节省构建时间
2. 仅做语法检查：有时候你只想利用 Rollup 的构建流程来检查代码是否有错误

## 是否允许输入路径成为输出路径的子路径 -allowInputInsideOutputPath

这个配置项主要用于文件监听（watch）模式下，控制构建工具是否允许你的源代码目录（输入路径） 被包含在构建产物目录（输出路径） 里面，核心是为了避免出现 “循环监听 / 无限构建” 的问题。
