# 输入配置选项

[[toc]]

## 外部模块-external

### 什么是外部模块

`external` 选项告诉 `Rollup` 打包时要忽略哪些模块，这些模块应该在最终的 `bundle` 中引用，而不是被打包进去。
::: tip 理解
简单来说，`external`选项用于告诉 `Rollup`：“请不要将这些模块打包到最终的输出文件里，而是在运行时从外部获取它们。”
举个例子 ​：假设你的项目使用了 `jQuery` 库。你有两种选择：

1. 打包进去 ​：让 `Rollup` 把 `jQuery` 的代码和你的业务代码合并到一个 `.js`文件中。这样文件会很大。
2. 设置为外部依赖 ​：告诉 `Rollup` `jQuery` 是 `external`的。这样，打包后的文件会保留 `import $ from 'jquery'`这样的语句，而 `jQuery` 本身则通过传统的 `<script>`标签在 `HTML` 中引入。

:::

### 意义

第二种方法就是 `external`的典型应用场景。它常用于处理：

1. ​ 大型第三方库 ​（如 `React`, `Vue`, `Lodash`）
2. ​ 浏览器环境自带的全局变量 ​（如 `import { Promise } from 'es6-promise'`，但期望使用浏览器的原生 `Promise`）
3. ​ 在其它地方（如 CDN）被提供的库 ​
4. 你希望单独存在、不被合并的本地文件

### 如何使用

`external`非常灵活，可以通过多种方式来指定哪些模块是外部的

#### 字符串和正则表达式

1. 字符串 ​：精确匹配模块名,最常见的方式是在 `Rollup` 配置文件（`rollup.config.js`）的 `external`数组中列出模块`ID`或使用正则表达式匹配。

```js
// rollup.config.js
export default {
  external: ['react', 'react-dom', 'lodash'],
  // ... 其他配置
};
```

::: warning 注意
字符串必须与 import 语句中写的完全一致。例如 `import react from 'react'`对应 `'react'`；`import './style.css'`对应 `'./style.css'`
:::

2. 正则表达式 ​：匹配符合某种模式的所有模块。

```js
// rollup.config.js
export default {
  external: [/node_modules/, /\.css$/], // 排除所有 node_modules 下的模块和所有 .css 文件
  // ... 其他配置
};
```

3. 绝对路径 ​：也可以指定具体的文件路径。

```js
// 通过 Node.js 的 URL 和 fileURLToPath 解析出一个本地文件的绝对路径，并将其设为外部。
external: [fileURLToPath(new URL('src/some-local-file-that-should-not-be-bundled.js', import.meta.url))];
```

#### 函数形式

如果需要更精细的控制，可以提供一个函数。这个函数接收三个参数：

1. `id`：当前被处理的模块的 ID。
2. `parentId`：导入当前模块的父模块的 ID。
3. `isResolved`：一个布尔值，表示 `id` 是否已经被插件（如 `@rollup/plugin-node-resolve`）解析过。

函数需要返回 `true`（表示是外部模块）或 `false`（表示不是）

比如：只将来自特定目录的特定模块设为外部。

```js
// rollup.config.js
export default {
  external(id, parentId, isResolved) {
    // 如果模块ID是 'jquery'，或者是来自 'node_modules' 的 'lodash'，则设为外部
    return id === 'jquery' || (parentId && parentId.includes('node_modules') && id === 'lodash');
  },
  // ... 其他配置
};
```

#### 命令行用法

在命令行中，可以使用 `-e`或 `--external`标志，后跟一个用逗号分隔的模块 ID 列表。

```bash
rollup -i src/main.js -f es -o dist/bundle.js -e jquery,lodash
```

### 高级特性

#### 处理相对路径导入

这是一个非常智能的特性。如果你将一个相对路径 ​（如 `'./utils/helper.js'`）标记为 `external`，`Rollup` 会进行以下操作：

1. 内部解析 ​：在打包过程中，`Rollup` 会先将这个相对路径解析成绝对路径，这样它就能识别出 `'./utils/helper.js'`和 `'../src/utils/helper.js'`实际上指向的是同一个文件。
2. 导入合并 ​：将所有指向同一文件的导入合并。
3. 输出还原 ​：在最终写入输出文件时，`Rollup` 会聪明地将绝对路径再转换回相对于输出文件的正确相对路径。

比如：

1. `main.js`导入了 `'../external.js'`
2. `nested.js`导入了 `'../../external.js'`

虽然写法不同，但它们都指向同一个外部文件。在输出时，`Rollup` 合并了这两个导入，并统一使用一个相对于输出文件的正确路径 `'../external.js'`。

#### 与 IIFE/UMD 格式和 output.globals 的配合

当你打包成 `​IIFE`​（立即执行函数）或 `​UMD`​（通用模块定义）格式，并在 HTML 中通过 `<script>`标签引入时，浏览器需要知道这些“外部”模块对应的全局变量名。
例如，`jQuery` 通常通过 `<script>`标签引入，并在全局创建了 `$`和 `jQuery`变量。你需要使用 `output.globals`选项来建立映射：

```js
// rollup.config.js
export default {
  input: 'src/index.js',
  external: ['jquery'], // 告诉 Rollup jquery 是外部的
  output: {
    file: 'dist/bundle.js',
    format: 'iife',
    globals: {
      jquery: '$', // 告诉 Rollup：模块名 'jquery' 对应全局变量 `$`
    },
  },
};
```

打包后，代码中的 `import $ from 'jquery'`会被替换为对全局变量 `$`的引用。

#### 使用插件进行解析

如果你想用 `/node_modules/`这样的正则表达式来排除 `node_modules`里的模块，你通常需要先使用 `​@rollup/plugin-node-resolve`​ 插件。

1. 默认情况下，`Rollup` 只能处理相对路径（`./， ../`）和绝对路径（`/`）的导入。对于 `import react from 'react'`这种“裸导入”，它不知道去哪里找。
2. `@rollup/plugin-node-resolve`插件的作用就是告诉 `Rollup` 如何根据 `node_modules`的规则去查找 `'react'`这个模块。
3. 只有先通过这个插件“解析”出 `'react'`对应的真实文件路径（如 `/project/node_modules/react/index.js`），你再用 `/node_modules/`正则表达式去匹配它，才会生效。

### 两种打包方式的区别

#### 打包为浏览器支持的 IIFE 或 UMD 格式

这种格式适用于浏览器环境，并且可以直接在浏览器中运行。但是创建 `iife` 或 `umd` 包时，你需要提供全局变量名称以通过 `output.globals` 选项替换外部导入

1. 用户需要"手动下载"​​：用户必须在 HTML 中通过 `<script>`标签先引入 `React`，再引入您的库。

2. 配置示例

```js
// rollup.config.js
export default {
  input: 'src/index.js',
  external: ['react', 'react-dom'], // 外部化 React
  output: {
    file: 'dist/my-lib.js',
    format: 'umd', // 或 'iife'
    name: 'MyLib', // 您的库的全局变量名
    globals: {
      react: 'React', // 关键：告诉 Rollup，"react" 对应全局变量 `React`
      'react-dom': 'ReactDOM',
    },
  },
};
```

3. 用户的使用方式 ​：

```html
<!-- 用户在他的 HTML 中 -->
<!-- 1. 手动引入 React（从 CDN 或本地文件） -->
<script src="https://unpkg.com/react@18/umd/react.production.min.js"></script>
<script src="https://unpkg.com/react-dom@18/umd/react-dom.production.min.js"></script>
<!-- 2. 然后引入你的库 -->
<script src="path/to/your/my-lib.js"></script>
```

#### 打包成 ESM 或 CJS 格式

这是更常见的库开发模式。

1. 用户通过 NPM 安装 ​：用户通过 `npm install your-lib react react-dom` 安装所有依赖。
2. 用户的构建工具负责处理 ​：当用户构建自己的项目时，他们的构建工具（如 `Webpack、Vite`）会分析依赖图，将您的库和 `React` 一起正确打包。
3. 配置示例 ​：

```js
// rollup.config.js
export default {
  input: 'src/index.js',
  external: ['react', 'react-dom'], // 仅外部化，不配置 globals
  output: [
    {
      file: 'dist/my-lib.esm.js',
      format: 'es', // ES 模块格式
    },
    {
      file: 'dist/my-lib.cjs.js',
      format: 'cjs', // CommonJS 格式
    },
  ],
};
```

## 入口点-input

### 什么是入口点

`input` 选项指定了 `Rollup` 应该从哪里开始打包。它可以是一个文件名，也可以是一个数组或对象。

### 打包单个文件

```js
export default {
  input: 'src/main.js', // 就写一个文件路径
  output: { ... }
};
```

### 打包多个文件

1. 让 Rollup 自动起名

```js
export default {
  input: ['src/a.js', 'src/b.js'], // 一个文件路径的数组
  output: { ... }
};
```

2. 手动指定文件名：对象的属性会替换`[name]`占位符

```js
// rollup.config.js
export default {
  // ...
  input: {
    a: 'src/main-a.js',
    'b/index': 'src/main-b.js',
  },
  output: {
    // ...
    entryFileNames: 'entry-[name].js',
  },
};
```

::: tip 指定目录
请注意，使用对象形式时可以通过在名称中添加 `/` 将入口点放入不同的子文件夹中。上面面将生成至少两个名为 `entry-a.js` 和 `entry-b/index.js` 的条目块，即文件 `index.js` 放置在文件夹 `entry-b` 中
:::

### 使用命令行接口

使用命令行接口时，可以通过多次使用该选项来提供多个输入。当作为第一个选项提供时，相当于不使用 `--input` 前缀

```bash
rollup --format es --input src/entry1.js --input src/entry2.js
# is equivalent to
rollup src/entry1.js src/entry2.js --format es
```

可以通过将 `=` 添加到提供的值来命名块：

```bash
rollup main=src/entry1.js other=src/entry2.js --format es
```

可以使用引号指定包含空格的文件名：

```bash
rollup "main entry"="src/entry 1.js" "src/other entry.js" --format es
```

### 高级用法

> 需求：​ 我有一个包含很多 JS 文件的文件夹（比如一个工具函数库），我想把里面每个文件都单独打包，并且保持原来的文件夹结构。​

```js
import { globSync } from 'glob';
import path from 'node:path';
import { fileURLToPath } from 'node:url';

export default {
  // 把刚才那一堆 [名字， 路径]的数组，变回图1里说的那种“对象”形式
  input: Object.fromEntries(
    // 引入一个叫 glob的包，它能帮我们根据规则（比如 src/**/*.js）一次性找到所有匹配的文件。结果是一个文件路径的数组，比如 ['src/a.js', 'src/utils/b.js', ...]。
    globSync('src/**/*.js')
      // 对找到的每个文件路径进行处理，把它变成 [打包后的名字, 源文件的绝对路径]这样的数组。
      .map(file => [
        // 从完整路径中提取出“打包后的名字”。例如，src/utils/b.js会变成 utils/b。
        path.relative('src', file.slice(0, file.length - path.extname(file).length)),
        // 源文件的绝对路径
        fileURLToPath(new URL(file, import.meta.url)),
      ]),
  ),
  output: {
    format: 'es',
    dir: 'dist',
  },
};
```

最终效果 ​：运行后，`src`目录下每个 JS 文件，都会在 `dist`目录下生成一个对应的 JS 文件，并且文件夹结构一模一样。
