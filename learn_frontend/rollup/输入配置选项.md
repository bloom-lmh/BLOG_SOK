## 外部模块-external

> 一句话概述就是，告诉 Rollup 哪些模块不要打包进最终的 bundle ，而是让用户来提供，用户提供依赖的两种方式：
>
> 1.  非浏览器（采用 esm 或 cjs 包时）：通过对等依赖提示 npm 下载
> 2.  浏览器（采用 iife 或 umd 包时）：script 标签引入依赖

### 什么是 external？

`external` 的作用就是告诉 `Rollup` 哪些模块不要打包进最终 `bundle`，仅仅保留原始 `import/require` 语句，让它们在运行时由外部提供。比如

1. 浏览器环境中通过 `CDN`引入依赖
2. 第三方库，如由用户自己安装
3. 内置依赖，如 `node` 内置模块，由`node`环境提供

> 比如我的库中用到了 `React`、`React-dom`，但我并不想把它们打包进最终的 `bundle`，而是让它们在运行时由用户自己安装。这时候就可以用 `external` 配置项。用户下载了我的库后，只需要安装 `React`、`React-dom` 这两个依赖，就可以正常使用。
> 同样如果他们是在浏览器通过`script`标签引入我的库，则同样使用`script`标签引入`React`和`React-dom`依赖也行。

### external 的好处

使用 `external` 有以下好处：

1. 减少打包体积：由于 `external` 告诉 `Rollup` 不要打包进最终 `bundle`，所以可以减少最终 `bundle` 的体积。
2. 避免依赖版本冲突：你的库打包了 `react@18`，而用户安装了 `react@17`，就会导致依赖版本冲突。

### external 支持的写法

1. 字符串数组：必须和`import`语句中的模块名完全一致

```js
external: ['react', 'react-dom'];
```

2. 正则表达式：可以匹配到符合条件的模块名从而进行批量匹配

```js
// 1. /^lodash/ → 将 lodash、lodash-es 等模块排除在外
// 2. 将所有来自 node_modules 的模块排除在外
external: [/^lodash/, /node_modules/];
```

::: warning 注意
使用正则 `/node_modules/` 前，必须用 `@rollup/plugin-node-resolve`插件,这是因为默认情况下，`import 'react'` 的模块 `ID` 就是 `'react'`（字符串），用了 `node-resolve` 插件后，它会被解析成类似 `/project/node_modules/react/index.js` 的绝对路径，这时 `/node_modules/` 正则才能匹配上
:::

3. 函数：可以自定义匹配规则，实现更细粒度的控制

```js
external(id, parentId, isResolved) {
  // id: 当前模块的 ID（如 'react' 或 '/abs/path/to/file.js'）
  // parentId: 引入它的父模块路径
  // isResolved: 是否已被插件解析为绝对路径

  if (id === 'react') return true;
  if (id.includes('node_modules')) return true;
  return false;
}
```

4. 绝对路径：排除本地文件，如果不希望本地某个文件被打包进最终 `bundle`，可以用绝对路径的方式排除、

```js
import { fileURLToPath } from 'node:url';

const __filename = fileURLToPath(import.meta.url);
const externalFile = path.resolve(path.dirname(__filename), 'src/utils.js');

export default {
  external: [externalFile],
};
```

### 与 globals 配合使用

当你打包时，使用了 `iife` 或 `umd` 格式，并且设置了 `external`字段排除了某些库（如 `react`）时，就需要显示的指定这些库的`ID`与该库对应的`iife/umd`模块的全局变量的映射关系。比如：

```js
export default {
  external: ['react'],
  output: {
    format: 'iife',
    name: 'MyLib',
    globals: {
      // 告诉 Rollup react 对应的全局变量叫 React
      react: 'React',
    },
  },
};
```

这样我们在前面通过`script`标签引入的`React`库，就可以直接使用我们的库了
具体原因参见[输出配置选项-globals](./输出配置选项.md)

### 与对等依赖配合使用

当我们使用 `external` 排除某些依赖时，我们可能还需要使用 `peerDependencies` 来声明对等依赖。这样用户才知道该依赖是必须安装的，否则会导致运行时错误。比如：

```js
// package.json
{
  "name": "my-lib",
  "version": "1.0.0",
  "peerDependencies": {
    "react": "^16.8.0"
  }
}

// rollup.config.js
export default {
  external: ['react'],
  output: {
    format: 'esm',
    dir: 'dist',
  },
};
```

关于对等依赖请参见[包配置](./包配置)
