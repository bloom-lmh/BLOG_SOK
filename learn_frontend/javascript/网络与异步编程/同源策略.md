# 同源策略

## 什么是同源策略

> 一句话概述：同源策略指的是对 `JavaScript` 代码能够访问和操作什么 Web 内容的一整套限制。文档包含的脚本才能够访问文档

脚本只能读取与包含它的文档同源的 `Window` 和 `Document` 对象的属性。文档的源就是文档 `URL` 的协议、主机和端口，从不同服务器加载的文档是不同源的， 从相同主机的不同端口加载的文档也是不同源的。而且，对于通过 `http:`协议加载的文档与通过 `https:`协议加载的文档来说，即便它们来自同一台服务器，也是不同源的。
有一点非常重要，就是应该知道脚本自身的源与同源策略不相关，相关的是包含脚本的文档的源。比如，假设主机 `A` 上有一个脚本，而主机 `B` 上的一个网页（使用`<script>`元素的 `src` 属性）包含了这个脚本。则该脚本的源是主机 `B`,且该脚本对包含它的文档具有完全访问权。如果文档中嵌入的`<iframe>`包含另一个来自主机 B 的文档，则该脚本同样拥有对这个文档的完全访问权。但是，如果顶级文档包含另一个`<iframe>`,其中显示的文档来自主机 C （或者甚至来自主机 A）,则同源策略就会起作用，并阻止该脚本访问这个嵌入的文档。
同源策略也会应用到脚本发起的 HTTP 请求。`JavaScript` 代码可以向托管其包含文档的服务器发送任意 `http` 请求，但不能与其他服务器通信（除非那些服务器开启了后面介绍的 CORS）。
解决同源策略带来的不便

- 脚本可以通过把 `document.domain` 设置为一个域名后缀来修改自己的源
- 使用跨源资源共享(`Cross-Origin Resource Sharing, CORS`)技术,它允许服务器决定对哪些源提供服务。CORS 扩展了 HTTP,增加了一个新的 0rigin:请求头和一个新的 `Access-Control-Allow-Origin` 响应头。服务器可以使用这个头部明确列出对哪些源提供服务，或者使用通配符表示可以接收任何网站的请求。浏览器会根据这些 CORS 头部的有无决定是否放松同源限制。
