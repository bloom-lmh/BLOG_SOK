# 注解

> 一句话定位：就是给类、方法、字段添加元信息，编译和运行的时候能读取它们和TS的装饰器一致

## 基础篇

### 1. 注解是什么：先厘清「注释」和「注解」

注解（Annotation）是 Java 5 引入的一种**元数据**——给类、方法、字段等代码元素「贴标签」，本身不改变代码逻辑，但可以在编译期或运行期被读取、处理。它解决的是「如何把配置、约束、行为描述附着在代码上」的问题，是现代 Java 开发（Spring、MyBatis、Lombok）的基石。

注解注释两个词一字之差，本质完全不同：

|            | 注释（Comment）                  | 注解（Annotation）                      |
| ---------- | -------------------------------- | --------------------------------------- |
| 写法       | `//`、`/* */`                    | `@Xxx`                                  |
| 作用       | 给人看的说明，编译时**直接丢弃** | 给程序/工具看的数据，**可保留到运行期** |
| 能否被读取 | 不能                             | 能（反射、注解处理器）                  |

注解的本质：**一种特殊的接口（interface），只是多了 `@` 符号**。它不做事，只是「贴在代码上的一张标签」，等着别人来读这张标签。

### 2. 内置注解（JDK 自带的）

| 注解                       | 作用                                               | 保留到           |
| -------------------------- | -------------------------------------------------- | ---------------- |
| `@Override`                | 标记「这是重写父类方法」，编译器校验是否真的重写   | SOURCE（编译期） |
| `@Deprecated`              | 标记「已废弃，别用」，调用时编译器警告             | RUNTIME          |
| `@SuppressWarnings("...")` | 压制编译器警告                                     | SOURCE           |
| `@FunctionalInterface`     | 标记「函数式接口」，编译器校验是否只有一个抽象方法 | RUNTIME          |
| `@SafeVarargs`             | 抑制泛型可变参数的警告                             | RUNTIME          |

`@Override` 是理解「注解有什么价值」最好的例子：它**不改任何逻辑**，但加了它，编译器就会帮你检查——方法签名写错了、没真正重写，直接编译报错，而不是运行期才发现。

### 3. 定义一个最简单的注解

```java
// 定义一个注解，格式 = interface 前面加 @
public @interface MyAnnotation {
    // 注解的「成员」其实是方法：属性名()
    String value();        // 有默认值可不填
    int count() default 1; // 有默认值，使用时可不写
}
```

使用：

```java
@MyAnnotation(value = "hello", count = 3)
public class Demo { }
```

关键认知：**注解里的成员本质是「抽象方法」**（`String value();`），使用注解时 `value = "hello"` 是在给这个「方法」传返回值——所以注解成员**不能有参数、不能有方法体**，只能是无参的抽象方法。

## 高级篇

### 4. 元注解：注解的注解（自定义注解必学）

元注解用来「修饰注解本身」，回答「这个注解能贴在哪、保留多久」等问题。共 5 个：

#### 4.1 `@Target`：这个注解能贴在哪些元素上

```java
@Target(ElementType.METHOD)          // 只能贴在方法上
@Target({ElementType.TYPE, ElementType.FIELD})   // 能贴在类和字段上
```

`ElementType` 常用取值：

| 取值              | 能贴的位置           |
| ----------------- | -------------------- |
| `TYPE`            | 类、接口、枚举       |
| `FIELD`           | 字段                 |
| `METHOD`          | 方法                 |
| `PARAMETER`       | 方法参数             |
| `CONSTRUCTOR`     | 构造器               |
| `ANNOTATION_TYPE` | 注解（给注解加注解） |

#### 4.2 `@Retention`：这个注解保留到哪个阶段（核心）

```java
@Retention(RetentionPolicy.RUNTIME)   // 保留到运行期，反射能读
@Retention(RetentionPolicy.SOURCE)    // 只在源码，编译就丢
@Retention(RetentionPolicy.CLASS)     // 保留到 class 文件，但运行期不可见（默认）
```

三种策略的对比：

| RetentionPolicy | 保留阶段                      | 能否反射读 | 典型例子                              |
| --------------- | ----------------------------- | ---------- | ------------------------------------- |
| `SOURCE`        | 源码 → 编译时丢弃             | 否         | `@Override`、`@SuppressWarnings`      |
| `CLASS`         | 编译进 class 文件，运行期丢弃 | 否         | Lombok 的注解（编译期处理器用）       |
| `RUNTIME`       | 一直保留到运行期              | 能         | `@Deprecated`、Spring 的 `@Autowired` |

::: tip 💡 面试题：`@Retention` 的三种策略有什么区别？
**一句话**：`SOURCE` 编译时丢弃（`@Override`），`CLASS` 保留到字节码但运行期不可见（Lombok 注解，给编译期处理器用），`RUNTIME` 全程保留、运行期反射可读（Spring 的 `@Autowired`，Spring 启动时靠反射扫它做注入）。选哪种看「谁在什么时候读这个注解」。
:::

#### 4.3 其他三个元注解

| 元注解        | 作用                                 |
| ------------- | ------------------------------------ |
| `@Documented` | 让这个注解出现在 javadoc 文档里      |
| `@Inherited`  | 子类能继承父类上的注解（只对类生效） |
| `@Repeatable` | 同一个注解可以在同一位置重复标注多次 |

### 5. 自定义注解完整步骤

以「标记一个接口需要登录鉴权」为例，五步：

```java
// ① 定义注解
@Target(ElementType.METHOD)          // 贴在方法上
@Retention(RetentionPolicy.RUNTIME)  // 运行期要用反射读
public @interface RequireLogin {
    String value() default "";       // 可携带一个说明
}

// ② 使用注解
@RequireLogin("需要登录")
public Result<Order> getOrder(Long id) { ... }

// ③ 读取注解（反射）
Method method = controller.getClass().getMethod("getOrder", Long.class);
if (method.isAnnotationPresent(RequireLogin.class)) {
    RequireLogin rl = method.getAnnotation(RequireLogin.class);
    System.out.println(rl.value());   // "需要登录"
}
```

注解成员的定义规则（面试细节）：

1. **成员是抽象方法**：`String value();`，不能有参数、不能有方法体。
2. **类型受限**：只能是基本类型、String、Class、枚举、注解，以及这些类型的数组。
3. **`value` 是特殊成员**：如果只有 `value` 一个成员，使用时可以省略名字，直接 `@RequireLogin("需要登录")`。
4. **默认值用 `default`**：`int count() default 1;`，有默认值的使用时可省略。

### 6. 项目里注解的应用（Spring 是怎么靠注解工作的）

理解了注解，就能理解 Spring 全家桶的「魔法」：

```java
@RestController          // 标记这是 Controller，Spring 扫描到就注册成 Bean
@RequestMapping("/api/user")
public class UserController {

    @Autowired           // 标记要注入，Spring 靠反射读它做依赖注入
    private UserService userService;

    @GetMapping("/{id}")  // 标记 GET 请求 + 路径
    public Result<User> get(@PathVariable Long id) { ... }
}
```

这些注解**本身啥也不做**，真正干活的是 **Spring 容器**——它在启动时用反射扫描所有 `@RestController`、`@Autowired` 等注解，然后完成 Bean 注册、依赖注入、路由映射。这就是「注解驱动开发」的本质：**注解声明意图，框架反射执行**。

## 原理篇

### 7. 注解的生命周期与三种读取方式

注解从「写上」到「生效」，取决于它在哪个阶段被谁读取：

```
源码 @Xxx
   │
   ▼ 编译（SOURCE 注解在此被丢弃）
字节码 .class（CLASS 注解保留到这里，运行期丢弃）
   │
   ▼ 运行（RUNTIME 注解一路保留，可反射读）
JVM 运行时
```

三种读取注解的方式：

| 方式                 | 时机             | 代表                         |
| -------------------- | ---------------- | ---------------------------- |
| **编译期注解处理器** | 编译时（改 AST） | Lombok、MapStruct            |
| **反射**             | 运行期           | Spring（扫 `@Component` 等） |
| **框架运行期框架**   | 运行期           | MyBatis、Spring AOP          |

### 8. 编译期注解处理器（JSR 269）：Lombok 的原理

Lombok 的 `@Data` 为什么能「自动生成 getter/setter」？因为它用了**编译期注解处理器**：

```
.java（带 @Data）
   │
   ▼ javac 编译时
注解处理器 Processor 被调用 → 读 AST（抽象语法树）→ 往类里插入 getter/setter 节点
   │
   ▼
.class（getter/setter 已真实存在）
```

这就是 Lombok 篇讲的「黑魔法」——它不是在运行期反射生成代码，而是在**编译期直接改语法树**，所以生成的代码在 `.class` 里真实存在、运行时零开销。详见 [Lombok](/learn_backend/java/工具/Lombok)。

### 9. 反射读取注解的底层

运行期读注解，本质是 `Class` / `Method` / `Field` 这些反射对象上挂了一张「注解表」：

```java
// getAnnotation 的底层：从 Method 对象的注解元数据里查
RequireLogin rl = method.getAnnotation(RequireLogin.class);

// 判断有没有这个注解
boolean has = method.isAnnotationPresent(RequireLogin.class);
```

性能注意：**反射读注解有开销**（JDK 早期实现有性能问题），所以框架（Spring）会在启动时扫描一次、把结果缓存起来，而不是每次请求都反射读。这就是「Spring 启动慢、运行快」的部分原因。

### 10. 注解不能做什么（局限）

面试常问「注解的局限」，答这几点：

1. **不能有逻辑**——注解只是元数据，不能写 if/else，逻辑要靠读取方实现。
2. **成员类型受限**——只能是常量表达式（基本类型、String、Class、枚举、注解），不能是对象。
3. **继承性有限**——`@Inherited` 只对类生效，方法/字段上的注解不被继承。
4. **不能动态修改**——注解值在编译期就固定，运行期改不了（和反射不同）。

## 面试常问

- **Q：注解和注释的区别？** 注释给人看、编译丢弃；注解给程序读、可保留到运行期，本质是元数据。

- **Q：`@Retention` 三种策略？** SOURCE（编译丢弃）、CLASS（字节码保留、运行不可见）、RUNTIME（全程保留、反射可读）。选哪种看「谁在何时读」。

- **Q：`@Target` 是干什么的？** 限定注解能贴在哪些元素（类/方法/字段/参数…）。

- **Q：自定义注解的步骤？** ① `public @interface Xxx` 定义 ② 加元注解（Target/Retention）③ 定义成员（抽象方法）④ 使用 ⑤ 反射/处理器读取。

- **Q：注解的成员为什么是「方法」？** 注解本质是特殊接口，成员是无参抽象方法，使用 `value="x"` 是给方法传返回值。

- **Q：Spring 是怎么靠注解工作的？** 注解声明意图（`@RestController`/`@Autowired`），Spring 启动时反射扫描这些注解，完成 Bean 注册、依赖注入、路由映射。注解本身不做事，框架反射执行。

- **Q：Lombok 的原理？** 编译期注解处理器（JSR 269），在 javac 编译时读 AST 并插入方法节点，生成代码在字节码里真实存在，运行时零开销。

- **Q：注解的局限？** 不能有逻辑、成员类型受限、继承性有限、运行期不能动态改。
