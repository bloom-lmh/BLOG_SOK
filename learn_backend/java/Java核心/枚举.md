# 枚举

> 一句话定位：枚举（`enum`）是 Java 5 引入的一种**特殊的类**，用来定义「取值固定、个数有限」的常量集合。它解决了「用 `int` / `String` 常量表示状态」带来的类型不安全、可读性差、无命名空间、无法携带附加信息等问题，是状态码、类型、策略等「有限枚举值」场景的标准做法。

---

## 基础篇

### 1. 为什么需要枚举：从 int 常量的痛点说起

没有枚举的年代，表示「订单状态」只能用 int 常量：

```java
public class OrderStatus {
    public static final int UNPAID = 0;      // 未支付
    public static final int PAID = 1;         // 已支付
    public static final int CANCELLED = 2;    // 已取消
}

// 使用时的问题：
int status = OrderStatus.PAID;
if (status == OrderStatus.UNPAID) { ... }     // ① 类型不安全：status 是 int，可以随便传个 999
setStatus(999);                                // ② 编译器不拦，运行期才发现是非法状态
System.out.println(status);                    // ③ 打印出来是 1，看不懂是啥意思
```

枚举解决这三大痛点：

```java
public enum OrderStatus {
    UNPAID, PAID, CANCELLED;
}

OrderStatus status = OrderStatus.PAID;
setStatus(OrderStatus.PAID);                   // ① 类型安全：只能传 OrderStatus，传 999 编译报错
System.out.println(status);                    // ② 打印 PAID，可读
```

### 2. 枚举本质：一个「特殊的类」

关键认知：**枚举就是一个类，它只有固定数量的实例**。上面那个 `OrderStatus`，等价于：

```java
public final class OrderStatus extends Enum<OrderStatus> {
    public static final OrderStatus UNPAID = new OrderStatus();
    public static final OrderStatus PAID = new OrderStatus();
    public static final OrderStatus CANCELLED = new OrderStatus();
    // 构造器私有，外部不能 new
    private OrderStatus() {}
}
```

所以枚举有这些特性（都是「类」带来的）：

| 特性 | 说明 |
|---|---|
| 天然单例 | 每个枚举常量全程只有一个实例 |
| 不能 new | 构造器隐式 `private`，外部无法创建新实例 |
| 继承 `Enum` | 所有枚举隐式继承 `java.lang.Enum`，所以**不能再继承别的类**（但可实现接口） |
| 可带字段/方法/构造器 | 和普通类一样，只是实例固定 |

### 3. 带字段的枚举（本项目 `ErrorCode` 的写法）

简单枚举只有名字，带字段的枚举让每个常量**携带数据**。以 course-mall 的 `ErrorCode` 为例：

```java
public enum ErrorCode {
    SUCCESS(200, "success"),
    PARAM_ERROR(400, "参数错误"),
    UNAUTHORIZED(401, "未登录"),
    FORBIDDEN(403, "无权限"),
    NOT_FOUND(404, "资源不存在"),
    SYSTEM_ERROR(500, "系统繁忙，请稍后再试");

    private final Integer code;      // 状态码
    private final String message;    // 提示语

    // 构造器：创建每个枚举常量时调用
    // 注意：枚举构造器隐式 private，不能写 public
    ErrorCode(Integer code, String message) {
        this.code = code;
        this.message = message;
    }

    public Integer getCode() { return code; }
    public String getMessage() { return message; }
}
```

关键点：

1. **`SUCCESS(200, "success")` 就是在调用构造器**——枚举语法不允许写 `new`，但本质就是 `new ErrorCode(200, "success")`。
2. **构造器不能写 `public`**——枚举构造器必须私有，否则外部就能 `new` 出额外实例，破坏「固定实例」的前提。
3. **每个常量携带自己的数据**，用 getter 读：`ErrorCode.SYSTEM_ERROR.getCode()` → `500`。

::: tip 💡 面试题：为什么错误码用枚举，不用 `int` 常量？
**一句话**：类型安全（方法参数限定 `ErrorCode` 类型，不能传非法 int）、自带命名空间（`ErrorCode.SYSTEM_ERROR` 不会和别的常量冲突）、可携带多个字段（code + message 打包成一个对象）、天然单例。见 [Spring](/learn_backend/java/基础/Spring) 里全局异常处理器的用法。
:::

### 4. 辨析 `final` 的三种用法（易混）

带字段枚举里出现的 `final`，和「继承」无关，别混：

| 用法 | 作用 | 例子 |
|---|---|---|
| `final class` | 这个类**不能被继承** | `final class String` |
| `final` 方法 | 这个方法**不能被子类重写** | `final void foo()` |
| `final` 字段 | 这个变量**只能赋值一次，之后不可改** | `private final Integer code;` |

`private final Integer code;` 是第三种——**`code` 在构造器里赋值后永远固定，谁也不能再改**。枚举常量是单例，字段用 `final` 保证「每个错误码的值创建后就是常量，不可被污染」。

### 5. 枚举常用内置方法

每个枚举自动继承 `Enum` 类的这几个方法：

| 方法 | 作用 | 例子 |
|---|---|---|
| `name()` | 返回常量名字符串 | `OrderStatus.PAID.name()` → `"PAID"` |
| `ordinal()` | 返回声明顺序（从 0 开始） | `UNPAID.ordinal()` → `0` |
| `values()` | 返回所有常量数组 | `OrderStatus.values()` |
| `valueOf(String)` | 按名字找常量 | `OrderStatus.valueOf("PAID")` |
| `compareTo()` | 按 ordinal 比较 | `UNPAID.compareTo(PAID)` → 负数 |

```java
for (OrderStatus s : OrderStatus.values()) {
    System.out.println(s.name() + " -> " + s.ordinal());
}
// UNPAID -> 0
// PAID -> 1
// CANCELLED -> 2
```

::: tip 💡 面试题：`values()` 方法哪来的？源码里看不到啊？
**一句话**：`values()` 和 `valueOf(String)` 不是 `Enum` 类的方法，而是**编译器在编译每个枚举时自动生成**的静态方法——你把 `.class` 反编译就能看到。`Enum` 类本身只有 `name()`、`ordinal()` 等。所以 `values()` 是「编译期语法糖」，不是继承来的。
:::

### 6. 枚举在 switch 中的用法

```java
switch (status) {
    case UNPAID:   // 枚举的 case 直接写常量名，不用写 OrderStatus.UNPAID
        System.out.println("未支付");
        break;
    case PAID:
        System.out.println("已支付");
        break;
    default:
        System.out.println("其他");
}
```

switch 底层其实是把枚举的 `ordinal()` 做分支匹配，所以 switch 里枚举 case 是**有序、有限**的。

## 高级篇

### 7. 枚举实现接口

枚举不能继承类（已经继承了 `Enum`），但**可以实现接口**：

```java
interface Payable {
    void pay();
}

public enum PayType implements Payable {
    ALIPAY {
        @Override
        public void pay() { System.out.println("支付宝支付"); }
    },
    WECHAT {
        @Override
        public void pay() { System.out.println("微信支付"); }
    };
}
```

### 8. 枚举定义抽象方法：策略模式的枚举实现

枚举常量可以各自实现抽象方法，天然实现「策略模式」——这是「用枚举消除 if-else」的经典技巧：

```java
public enum Operation {
    ADD {
        @Override
        public int apply(int a, int b) { return a + b; }
    },
    SUBTRACT {
        @Override
        public int apply(int a, int b) { return a - b; }
    };

    public abstract int apply(int a, int b);   // 抽象方法，每个常量必须实现
}

// 用的时候：
int result = Operation.ADD.apply(3, 5);   // 8，不用写 if-else 分发
```

### 9. 枚举实现单例（《Effective Java》推荐写法）

```java
public enum Singleton {
    INSTANCE;

    public void doSomething() { ... }
}

// 使用
Singleton.INSTANCE.doSomething();
```

为什么推荐：枚举天然线程安全（`static final` 由 JVM 保证初始化一次）、**天然防反射**（`newInstance` 抛异常）、**天然防反序列化破坏**（`readResolve` 机制）。这是最简洁的单例实现，面试常考。

### 10. EnumSet 与 EnumMap：专为枚举优化的集合

```java
// EnumSet：底层是位向量，比 HashSet 快、省内存
EnumSet<OrderStatus> set = EnumSet.of(OrderStatus.PAID, OrderStatus.CANCELLED);

// EnumMap：key 必须是枚举，底层用数组，比 HashMap 快
EnumMap<OrderStatus, String> map = new EnumMap<>(OrderStatus.class);
map.put(OrderStatus.PAID, "已支付");
```

## 原理篇

### 11. 枚举的字节码本质

反编译一个简单枚举，能看到编译器做了什么：

```java
// 源码
public enum OrderStatus { UNPAID, PAID, CANCELLED; }

// 编译后等价于（反编译结果）：
public final class OrderStatus extends Enum<OrderStatus> {
    public static final OrderStatus UNPAID;
    public static final OrderStatus PAID;
    public static final OrderStatus CANCELLED;
    private static final OrderStatus[] $VALUES;

    static {
        UNPAID = new OrderStatus("UNPAID", 0);
        PAID = new OrderStatus("PAID", 1);
        CANCELLED = new OrderStatus("CANCELLED", 2);
        $VALUES = new OrderStatus[]{UNPAID, PAID, CANCELLED};
    }

    private OrderStatus(String name, int ordinal) {   // 编译器补了两个参数：名字 + 序号
        super(name, ordinal);
    }

    public static OrderStatus[] values() {             // 编译器生成
        return $VALUES.clone();
    }

    public static OrderStatus valueOf(String name) {   // 编译器生成
        return Enum.valueOf(OrderStatus.class, name);
    }
}
```

三个关键结论：

1. **枚举是 `final class`**——不可被继承。
2. **常量是 `static final` 字段**——类加载时初始化，天然线程安全 + 单例。
3. **`values()` / `valueOf()` 是编译器生成的**，不是 `Enum` 类的继承方法。

### 12. 为什么枚举能防「反射破坏单例」

普通单例（懒汉式）能被反射 `setAccessible(true)` 突破私有构造器，但枚举不行：

```java
Constructor<Singleton> c = Singleton.class.getDeclaredConstructor();
c.setAccessible(true);
Singleton s = c.newInstance();   // 对普通单例：成功创建新实例，破坏单例
                                  // 对枚举：抛 IllegalArgumentException
                                  // 因为 Enum 类的 newInstance 源码里写了：
                                  // if ((clazz.getModifiers() & Modifier.ENUM) != 0)
                                  //     throw new IllegalArgumentException("Cannot reflectively create enum objects");
```

### 13. 为什么枚举能防「反序列化破坏单例」

反序列化普通对象会绕过构造器新建实例，破坏单例；枚举的序列化特殊处理：

- 枚举序列化时**只写名字**（`name`），不写字段值；
- 反序列化时用 `Enum.valueOf(clazz, name)` 拿到**已存在的那个常量**，而不是 new 一个。

所以反序列化后拿到的是**同一个实例**，单例不被破坏。

## 面试常问

- **Q：枚举的本质？** 一种特殊的 `final class`，隐式继承 `Enum`，实例固定（`static final` 常量），构造器私有。

- **Q：带字段枚举的 `SUCCESS(200, "success")` 是什么？** 调用构造器创建常量，只是枚举语法不写 `new`。

- **Q：`private final Integer code` 里的 final 什么意思？** 字段赋值后不可变（不是「不可继承」——那个是 `final class`）。枚举字段用 final 保证常量不可污染。

- **Q：`values()` 方法哪来的？** 编译器自动生成的静态方法，不是 `Enum` 继承的。

- **Q：枚举 vs int 常量？** 类型安全、可读、命名空间、可带字段、单例。int 常量会传错值、看不懂、无类型约束。

- **Q：枚举怎么实现单例？为什么安全？** `enum Singleton { INSTANCE }`，天然线程安全（类加载初始化）+ 防反射 + 防反序列化。

- **Q：枚举能不能继承类？能不能实现接口？** 不能继承（已继承 Enum），可以多实现接口。

- **Q：EnumSet/EnumMap 为什么快？** 底层是位向量/数组，按 ordinal 定位，无哈希计算。
