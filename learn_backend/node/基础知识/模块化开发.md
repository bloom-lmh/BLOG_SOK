# 模块化开发

## 非模块化开发的问题

![非模块化开发的问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251215195011799.png)

### 依赖关系问题

由于`js`代码的解析是至上而下的所以调用函数必须出现在函数定义之后，这导致文件依赖关系不好管理，例如：`a.js`中定义了一个`upper`函数，`b.js`想要调用`a.js`中的`upper`方法，若`b.js`在`a.js`之前导入，则会出方法未定义错

::: code-group

```js [a.js]
function upper(str) {
  return str.subString(0, 1).toUpperCase() + str.subString(1);
}
```

```html [index.html]
<!-- 调用 b.js a.js -->
<script src="./js/b.js"></script>
<script src="./js/a.js"></script>
<script>
  // 调用upper方法,会出现错误
  upper();
</script>
```

:::

![依赖关系问题](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251215195334071.png)

### 命名空间问题

由于对`js`文件的引用是至上而下的，所以相同函数名的函数会覆盖，只执行最后一个，这导致命名空间不好管理
::: code-group

```js [a.js]
function test() {
  console.log('aaa');
}
```

```js [b.js]
function test() {
  console.log('bbb');
}
```

```js [c.js]
function test() {
  console.log('ccc');
}
```

```html [index.html]
<!-- 调用a.js b.js c.js -->
<script src="./js/a.js"></script>
<script src="./js/b.js"></script>
<script src="./js/c.js"></script>
<script>
  // 调用test方法,执行结果为ccc
  test();
</script>
```

:::

### 代码组织问题

若想定义一个私有方法就在`a.js`中使用，通常的做法是使用下划线加方法名来表示这是一个私有方法，但这仅仅是一个不成文的规定。外面文件依然可以访问，这就导致了代码的封装性不好

```js
function _init() {
  console.log('我是私有方法');
}
```

## CommonJS 模块化规范

`CommonJs`是一个规范即指导方针，`NodeJs`和`Webpack`对其规范进行了部分的具体的实现

![CommonJS 模块化规范](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251215195712387.png)

我们可以把公共的功能抽离成为一个单独的 `js` 文件 作为一个模块，默认情况下面这个模块里面的方法或者属性，外面是没法访问的。如果要让外部可以访问模块里面的方法或者属性，就必须在模块里面通过`exports` 或者 `module.exports` 暴露属性或者方法。

### 对象式导出

```js
function test() {
  console.log('aaa');
}

function upper(str) {
  return str.substring(0, 1).toUpperCase() + str.substring(1);
}

function _init() {
  console.log('我是私有方法');
}
module.exports = {
  test,
  upper,
};
```

使用`require`进行导入

```js
const moduleA = require('./js/a');
console.log(moduleA);
moduleA.test();
```

### 逐个导出

```js
function test() {
  console.log('ccc1');
}
function test2() {
  console.log('ccc2');
}
exports.t1 = test1;
exports.t2 = test2;
```

使用`require`进行导入

```js
const moduleC = require('./js/c');
moduleC.t1();
moduleC.t2();
```

## ES 模块化规范

### ES 模块化的配置

`ES`模块化规范和`CommonJs`规范不一样，`nodejs` 两个都支持，但是需要在`package`中进行配置在`package.json`添加`type`选择`module`选项

![ES 模块化的配置](https://image-bucket-1307756649.cos.ap-chengdu.myqcloud.com/image/20251215201057602.png)

### 导出默认模块

```js
const moduleA = {
  getName() {
    console.log('获取名字');
  },
};
export default moduleA;
```

使用`import`进行导入

```js
import moduleA from './module/moduleA.js';
console.log(moduleA);
```

### 命名导出

```js
const moduleB = {
  getName() {
    console.log('获取名字');
  },
};

export { moduleB };
```

使用`import`进行导入

```js
import { moduleB } from './module/moduleB.js';
console.log(moduleB.getName());
```

## require 导入原理

这里我们介绍一下 `require` 导入自定义模块的基本流程:

1. 将相对路径转为绝对路径，定位目标文件
2. 缓存检测
3. 读取目标文件代码
4. 包裹为一个函数并执行（自执行函数）。通过 `arguments.callee.toString()` 查看自执行函数
5. 缓存模块的值
6. 返回 `module.exports` 的值

```js
const fs = require('fs');
const path = require('path');
const vm = require('vm');

const caches = {};

function myRequire(filePath) {
  // 1. 转为绝对路径（简单处理，不处理后缀）
  let absolutePath = path.resolve(__dirname, filePath);
  if (!absolutePath.endsWith('.js')) {
    absolutePath += '.js';
  }

  // 2. 缓存检查
  if (caches[absolutePath]) {
    return caches[absolutePath];
  }

  // 3. 读取文件
  let code;
  try {
    code = fs.readFileSync(absolutePath, 'utf8');
  } catch (err) {
    throw new Error(`Cannot find module '${filePath}'`);
  }

  // 4. 包裹并执行
  const module = { exports: {} };
  const __filename = absolutePath;
  const __dirname = path.dirname(absolutePath);

  const wrapper = `(function(exports, require, module, __filename, __dirname) {
${code}
})`;

  const compiledWrapper = vm.runInThisContext(wrapper, {
    filename: absolutePath,
  });

  compiledWrapper.call(
    module.exports,
    module.exports,
    myRequire, // 递归支持
    module,
    __filename,
    __dirname,
  );

  // 5. 缓存
  caches[absolutePath] = module.exports;

  // 6. 返回
  return module.exports;
}
```

`require` 使用的一些注意事项：

1. 对于自己创建的模块，导入时路径建议写相对路径，且不能省略`./` 和`../`
2. `js` 和 `json` 文件导入时可以不用写后缀，c/c++编写的 node 扩展文件也可以不写后缀
3. 如果导入其他类型的文件，会以 `js` 文件进行处理
4. 如果导入的路径是个文件夹，则会首先检测该文件夹下 `package.json` 文件中 `main` 属性对应的文件，如果存在则导入，反之如果文件不存在会报错。如果 `main` 属性不存在，或者 `package.json` 不存在，则会尝试导入文件夹下的 `index.js` 和 `index.json` ，如果还是没找到，就会报错
5. 导入 `node.js` 内置模块时，直接 `require` 模块的名字即可，无需加`./` 和`../`
