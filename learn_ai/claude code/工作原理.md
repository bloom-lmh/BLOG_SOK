# Claude Code 如何工作

## 1. Claude Code 到底是什么

Claude Code 不是单纯的聊天机器人，而是一个运行在终端里的代理助手。

它的特点是：

- 能理解你的代码库
- 能调用工具读取、搜索、编辑文件
- 能执行命令、运行测试、使用 Git
- 能根据执行结果继续调整下一步动作

所以它本质上不是“回答问题”，而是“围绕任务持续行动”。

## 2. 核心工作方式：代理循环

Claude Code 处理任务时，一般会不断循环这三步：

1. 收集上下文
2. 采取行动
3. 验证结果

比如你说“修复失败的测试”，它通常会这样做：

1. 先运行测试，看看哪里失败
2. 再读取报错和相关代码
3. 修改文件
4. 重新运行测试确认是否修好

如果第一次没修好，它会继续重复这个循环，直到完成任务或你中途打断它。

## 3. 模型和工具分别负责什么

Claude Code 可以理解成两部分一起工作：

### 模型

模型负责“思考”和“推理”，比如：

- 理解你的需求
- 分析代码结构
- 决定下一步做什么

### 工具

工具负责“动手”，比如：

- 读文件
- 改代码
- 搜索内容
- 运行 shell 命令
- 查文档和网页

一句话理解：

> 模型负责想，工具负责做。

## 4. Claude Code 能访问什么

当你在某个目录里启动 Claude Code 时，它通常可以访问：

- 当前项目及子目录
- 终端里能执行的命令
- Git 状态
- `CLAUDE.md`
- 自动内存
- 你配置的 MCP、skills、subagents 等扩展

这也是为什么它比普通代码补全工具更强，因为它看到的是“整个项目”，而不是只看当前文件。

## 5. 会话是什么

会话可以理解成一段持续的工作上下文。

它保存的不只是聊天记录，还包括：

- 你的提问
- Claude 的回复
- 使用过的工具
- 工具返回的结果

所以会话的本质是：

> 一份任务上下文历史，而不是一份代码版本历史。

## 6. 会话的几个关键点

### 新会话默认独立

每次新开会话，默认都是新的上下文窗口，不会自动继承之前的完整聊天记录。

### 可以恢复会话

如果你想接着之前的任务继续做，可以恢复原来的会话。

这相当于：

- 继续原来的上下文
- 继续原来的任务链路

### 可以分叉会话

如果你想基于当前讨论尝试另一种思路，可以 fork 一个新会话。

这相当于：

- 保留已有上下文
- 从当前节点分出另一条思路

要注意的是，fork 分叉的是“对话和上下文”，不是 Git 分支。

## 7. 会话和 Git 的关系

这里很容易混淆，必须分清：

- 会话：管理上下文
- Git branch：管理代码历史
- Git worktree：管理独立目录

### 切换 Git 分支时会发生什么

Claude 会看到当前分支上的文件内容变化，但会话历史本身不会消失。

也就是说：

- 你切到了新分支
- Claude 看到的是新分支文件
- 但它仍然记得之前会话里聊过什么

### 为什么并行改代码容易乱

因为多个会话如果都指向同一个目录，它们看到的是同一套文件。

所以：

- 研究问题时，可以只用会话分叉
- 真正并行改代码时，最好配合 Git branch 和 worktree

## 8. 上下文窗口是什么

上下文窗口就是 Claude 当前“脑子里装着的内容”。

它一般包括：

- 当前对话历史
- 文件内容
- 命令输出
- `CLAUDE.md`
- 自动内存
- 已加载的 skills
- 系统提示

上下文不是无限的。内容太多时，Claude 会自动压缩和总结旧内容。

这意味着：

- 越早说过的话，越可能被压缩掉
- 长会话里不要把关键规则只放在聊天里
- 持久规则更适合写进 `CLAUDE.md`

## 9. 为什么 skills 和 subagents 有帮助

### skills

skills 是按需加载的知识或工作流模板。

作用：

- 不必把所有说明都塞进当前上下文
- 需要时再加载

### subagents

subagent 有自己独立的新上下文。

作用：

- 可以把子任务交给独立代理去做
- 不会把主会话上下文越撑越大
- 完成后只返回摘要

所以：

- `fork session` 更像分叉当前思路
- `subagent` 更像派一个新助手做子任务

## 10. 检查点和权限

Claude Code 还有两个很重要的安全机制：

### 检查点

在编辑文件前，Claude 会先保存快照。

这样如果改坏了，可以回退。

### 权限

Claude 不是所有操作都会直接执行，不同权限模式会决定：

- 是否先询问再编辑
- 是否先询问再执行命令
- 是否只能只读分析

所以它是“可控的代理”，不是完全无约束地乱跑。

## 11. 怎么更高效地使用 Claude Code

### 把它当成协作式代理，而不是搜索框

你不需要一开始就写完美提示，可以边做边修正。

### 初始要求尽量具体

说清楚：

- 哪个模块有问题
- 你怀疑哪里出错
- 要不要先写测试
- 最后要怎么验证

越具体，Claude 第一次走偏的概率越低。

### 给它验证标准

比如：

- 测试用例
- 预期输出
- 截图
- 页面效果要求

Claude 在“有明确验证方式”时表现会更稳定。

### 复杂任务先探索，再实现

对复杂需求，先让它分析代码并做计划，再开始改代码，通常效果更好。

## 12. 最实用的理解方式

你可以把 Claude Code 想成一个“会思考、会动手、会验证的终端代理”。

记住这四句就够了：

1. Claude Code 不是只会聊天，它会实际执行任务
2. 它通过“收集上下文 -> 行动 -> 验证”循环工作
3. 会话管理的是上下文，不是代码版本
4. 真正并行改代码时，要配合 Git branch 和 worktree
