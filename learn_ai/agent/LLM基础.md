# LLM基础

一句话定位：LLM（Large Language Model，大语言模型）是一种基于海量文本训练、通过「预测下一个词」学会语言规律与知识的神经网络模型，解决「让机器理解并生成人类语言」的问题，是所有 AI Agent、RAG、Function Calling 等上层能力的「大脑」底座。

---

## 基础篇

### 什么是大语言模型（LLM）

**背景**：在 LLM 之前，机器处理自然语言靠的是「人工设计特征 + 规则 + 小模型」。比如做情感分类，要人为定义「好、喜欢、赞」是正类词，再统计词频丢进一个浅层模型。这套做法天花板极低——同义词换一种说法就失效，跨领域就得重写规则。

2017 年 Google 提出 **Transformer** 架构后，人们发现：只要把模型做大、喂的语料够多，模型就会「涌现」出理解语言、推理、甚至写代码的能力。这就是「大语言模型」的由来——**大**指参数量大、训练数据量大、算力消耗大。

**定义**：LLM 是一类基于 Transformer 的神经网络模型，核心任务只有一个——**给定前面所有 token，预测下一个 token 的概率分布**。它没有「理解」的魔法，一切能力都源自这个看似简单的「下一个词预测」任务在超大语料上的不断重复。

```
一句话理解 LLM：

  输入（前文）                        输出（概率分布）
  ──────────────────────────────      ─────────────────────────
  "今天天气真"                  →      "好"   0.72
                                      "不错" 0.18
                                      "冷"   0.05
                                      ...    ...
  → 选概率最高的（或按概率采样）"好"，拼到末尾，再预测下一个。
```

**特性/规则**：

1. **自回归生成**：一次只吐一个 token，吐出来的 token 会拼回输入，作为预测下一个 token 的依据，如此循环。
2. **无状态**：模型本身不保存任何对话记忆，每次调用都是「从零开始看上下文」。所谓「记得刚才说的话」，是把历史对话重新拼进 prompt 再喂给它。
3. **概率性输出**：同样的问题，两次回答可能不一样——因为生成时带随机采样。
4. **知识内化在权重里**：训练结束后，知识以「参数」的形式冻结在模型权重中，推理时不再查数据库，知识截止日期就是训练数据截止日期。

**示例**：下面用伪代码展示 LLM 最核心的「下一词预测 + 自回归」循环：

```python
# 为什么用 while 循环：模型一次只生成一个 token，要不断把新 token 拼回去继续生成，
# 直到出现结束符或达到最大长度为止。
def generate(prompt, model, max_len=50):
    tokens = tokenize(prompt)                 # 1. 把文本切成 token id
    for _ in range(max_len):
        logits = model(tokens)                # 2. 前向传播，得到每个词的"分数"
        next_id = sample(logits[-1])          # 3. 只看"最后一个位置"的分数，采样出下一个词
        tokens.append(next_id)                # 4. 拼到末尾（这就是"自回归"）
        if next_id == EOS_TOKEN:              # 5. 遇到结束符就停
            break
    return detokenize(tokens)                 # 6. 转回人类可读文本
```

**小结**：LLM = Transformer 架构 + 海量语料 + 下一词预测训练 + 自回归生成。抓住这条主线，后面 Agent、RAG、Function Calling 都是在这个「下一个词预测器」外面包的各种工程化包装。

### 从传统 NLP 到 LLM：范式的根本转变

理解 LLM 的价值，最好的方式是对比它和传统 NLP 的差异。这不是「模型更大」的线性升级，而是**方法论**的彻底换轨：

| 维度 | 传统 NLP（预 Transformer） | 大语言模型（LLM） |
| --- | --- | --- |
| 训练方式 | 每个任务单独训练一个模型 | 一个模型通吃所有任务 |
| 特征工程 | 人工设计特征（词频、词性、句法树） | 无需人工特征，端到端学 |
| 任务适配 | 分类器、序列标注器各来一套 | 把所有任务都「翻译」成文本生成 |
| 数据需求 | 每个任务要大量标注数据 | 预训练用无标注文本，微调只需少量示例 |
| 知识来源 | 只记住训练集里的规律 | 内化了训练语料中的世界知识 |
| 泛化能力 | 换领域就崩 | 举一反三，能处理没见过的任务 |

::: tip 💡 面试题：LLM 相比传统 NLP 的范式转变是什么？
从「每个任务训一个专用模型」变成「一个通用模型 + 提示词」完成任意任务。核心是 Transformer 的涌现能力让「下一个词预测」这个通用任务也能逼出推理、翻译、总结等能力，于是所有 NLP 任务被统一成「文本进、文本出」。
:::

这个转变带来两个工程红利：

1. **任务统一化**：翻译、摘要、分类、问答……全都变成「prompt 进、completion 出」，业务侧只需调同一个 API。
2. **上下文学习（In-Context Learning）**：不需要重新训练，只要在 prompt 里塞几个示例（few-shot），模型就能学会新任务。这是后面 [RAG](/learn_ai/agent/RAG) 和 [Function Calling](/learn_ai/agent/Function Calling) 能成立的前提。

### Token 与分词器（Tokenizer）

**背景**：模型不认识文字，只认识数字。要把文本喂给模型，第一步是「分词」——把一段文本切成一串基本单元，每个单元叫一个 **token**，再映射成一个整数 id。

**定义**：Tokenizer（分词器）负责「文本 ↔ token id」的互转。这是理解 LLM 成本、上下文窗口、中英文差异的钥匙。

**特性/规则**：

1. **token 不等于词**：一个 token 可能是完整单词、半个单词、一个汉字、一个标点。英文里高频词一个词一个 token，低频词会被拆成子词（subword）。
2. **中英文差异巨大**：英文一个词约 1~2 个 token；中文一个汉字约 1~2 个 token，通常「1 个汉字 ≈ 1 个 token」或更少。所以同样语义的中文通常比英文 token 数更少。
3. **主流算法是 BPE（Byte Pair Encoding）**：把语料中最常见的字符对反复合并成新子词，既覆盖生僻词，又控制词表大小。
4. **计费按 token**：API 计费、上下文长度限制，全都以 token 为单位。

**示例**：用 OpenAI 的 tiktoken 感受一下 token 是怎么切的：

```python
import tiktoken

# 为什么用 tiktoken：它是 OpenAI 官方的分词器，和 GPT 系列模型一一对应，
# 用错编码（encoding）会导致 token 数算错、成本预估错。
enc = tiktoken.get_encoding("cl100k_base")   # GPT-3.5/GPT-4 系列使用的编码

text_en = "Large language models are amazing."
text_zh = "大语言模型非常强大。"

print("英文 token 数：", len(enc.encode(text_en)))   # 约 7
print("中文 token 数：", len(enc.encode(text_zh)))   # 约 7（汉字基本 1~2 个 token/字）
print("英文切分：", [enc.decode([t]) for t in enc.encode(text_en)])
# 输出类似：['Large', ' language', ' models', ' are', ' amazing', '.']
```

**小结**：token 是 LLM 的「原子单位」，上下文长度、计费、速度全部由它度量。工程上判断一段 prompt 会不会超限，先算 token 数。

### 上下文窗口（Context Window）

**背景**：模型一次调用能「看到」的 token 总量是有限制的，这个上限就叫**上下文窗口**。

**定义**：上下文窗口 = 单次请求中「输入 token + 输出 token」的最大容量。超出部分会被截断（truncate）或直接报错。

**特性/规则**：

1. **输入 + 输出共享同一个窗口**：你 prompt 写得越长，留给模型回答的空间就越小。
2. **窗口一直在变大**：从 GPT-2 的 1024，到 GPT-3 的 2048/4096，再到 Claude 的 100K/200K、Gemini 的 1M、2M，是各家卷的主要指标之一。
3. **窗口大 ≠ 注意力好用**：窗口再大，模型对「中间内容」的注意力仍会衰减，这就是著名的「Lost in the Middle（中间迷失）」现象——把关键信息放在开头或结尾，模型抓得更准。
4. **成本随长度非线性上升**：Transformer 自注意力的计算量与序列长度呈平方关系，超长上下文推理又慢又贵。

```
上下文窗口分配示意（假设窗口 = 4096 token）：

  ┌──────────────────────────────────────────────┐
  │  系统提示词 (system)         ~200 token      │
  │  历史对话 / 检索到的资料      ~3000 token     │
  │  本轮用户问题                ~200 token      │
  │  ─────────────────────────────────────────── │
  │  剩余给模型输出的空间          ~696 token      │
  └──────────────────────────────────────────────┘
```

::: tip 💡 面试题：上下文窗口越大约好吗？有什么坑？
不是。窗口大能放更多资料，但有两个代价：一是推理成本和时间随长度平方增长（注意力机制），二是模型对中间信息的利用率下降（Lost in the Middle）。所以工程上要做「上下文压缩、检索、摘要」，而不是无限加窗口。
:::

### 采样参数：temperature、top-k、top-p

**背景**：模型输出的不是「确定的一个词」，而是「所有词的概率分布」。怎么从这个分布里挑出下一个词，直接决定了回答是「稳定保守」还是「天马行空」。

**定义**：采样（Sampling）是从模型输出的概率分布中选取下一个 token 的策略。三个核心参数控制采样行为。

#### temperature（温度）

控制概率分布的「陡峭/平缓」程度。取值范围 `[0, 2]`，越低越确定，越高越随机。

```
原始 logits → 除以 temperature → softmax 归一化 → 得到概率

  temperature → 0  ：概率被极度拉开，几乎总是选最大那个（≈ 贪心）
  temperature = 1  ：保持原始分布
  temperature → 高 ：分布被抹平，冷门词也有机会被选中（更有创造性）
```

#### top-k

只保留概率最高的 k 个候选，其余直接清零。k 越小越保守。

#### top-p（nucleus sampling，核采样）

按概率从高到低累加，直到累计概率达到阈值 p，只在这个「最小候选集」里采样。相比 top-k，top-p 能根据分布的陡峭程度自适应候选数量。

**示例**：用一段伪代码把三个参数的联合作用讲清楚：

```python
import numpy as np

def sample_next_token(logits, temperature=1.0, top_k=0, top_p=1.0):
    # 为什么先除 temperature：控制分布的尖锐程度，是"创造性"的总开关。
    logits = logits / temperature

    # 为什么做 top-k：把长尾的低概率词直接砍掉，避免选出乱七八糟的词。
    if top_k > 0:
        kth = sorted(logits, reverse=True)[top_k - 1]
        logits = [l if l >= kth else -np.inf for l in logits]

    # 为什么做 top-p：候选集大小随分布自适应，比固定 top-k 更灵活。
    probs = softmax(logits)
    sorted_idx = np.argsort(-probs)
    cum = 0.0
    for i in sorted_idx:
        cum += probs[i]
        if cum > top_p:
            probs[i] = 0.0
    probs = probs / probs.sum()

    return np.random.choice(len(probs), p=probs)
```

**参数选型对照表**：

| 参数 | 取值 | 效果 | 使用场景 |
| --- | --- | --- | --- |
| temperature | 0 / 很低（0~0.3） | 输出稳定、几乎可复现 | 代码生成、事实问答、翻译 |
| temperature | 0.7~1.0 | 平衡 | 日常对话、通用写作 |
| temperature | 1.2~1.5 | 有创造性、脑洞大 | 创意写作、头脑风暴、起名 |
| top_p | 0.1 | 只留最可能的极小集合 | 需要极度保守的抽取任务 |
| top_p | 0.9 | 常用默认值 | 大多数生成场景 |
| top_k | 10~50 | 固定候选数 | 需要硬约束候选数量时 |

::: tip 💡 面试题：temperature 和 top-p 的区别？
temperature 是在「归一化之前」改变 logits 的尺度，从根上控制分布陡峭程度；top-p 是在「得到概率之后」裁剪候选集。两者作用阶段不同，实践中通常只调其一：要稳定就把 temperature 调低，要创造就调高 temperature 或放宽 top-p。一般不建议同时大动两个。
:::

## 高级篇

### 自回归解码：模型到底怎么「写」出答案

**背景**：很多人以为模型是「一次性想好整段再输出」，其实完全相反——它像打字机，一个字一个字往外蹦，每蹦一个字都要回头看一眼刚才写了什么。

**定义**：自回归解码（Autoregressive Decoding）是指模型逐个 token 生成序列，且每个新 token 都依赖于之前已生成的所有 token。

**完整流程**：

```
第 1 步：输入 "中国的首都是" → 模型算一遍 → 输出 "北"
第 2 步：输入 "中国的首都是北" → 模型再算一遍 → 输出 "京"
第 3 步：输入 "中国的首都是北京" → 模型再算一遍 → 输出 <EOS> → 停止

关键点：每一步都要把"全部历史"重新算一遍，这就是为什么生成是串行的、慢。
```

**特性/规则**：

1. **串行依赖，无法并行生成**：因为下一个 token 依赖上一个，所以生成速度是「一个 token 接一个 token」，这是 LLM 慢的根源。
2. **错误会滚雪球**：前面生成错了一个字，后面会基于错误继续编，所以才有「越编越离谱」。
3. **提前终止靠特殊 token**：模型输出 `<EOS>`（end of sequence）表示「说完了」。

**示例**：完整可运行的解码循环（用 Hugging Face transformers）：

```python
from transformers import AutoTokenizer, AutoModelForCausalLM

# 为什么加载时用本地缓存：模型很大（几 GB 到几十 GB），
# 加载到 GPU 显存后直接复用，避免重复下载。
tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")

inputs = tokenizer("中国的首都是", return_tensors="pt")
outputs = model.generate(
    **inputs,
    max_new_tokens=10,       # 最多新生成 10 个 token，防止跑飞
    do_sample=False,         # 关闭采样 = 贪心解码，输出确定
)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))
# → 中国的首都是北京
```

**小结**：自回归解码是理解 LLM 性能、幻觉、流式输出（见 [流式输出](/learn_ai/agent/流式输出)）的底层钥匙。生成慢、成本高、会滚雪球，全都源于「一次一个、回头再看」。

### 提示词工程（Prompt Engineering）

**背景**：LLM 是「通用模型」，同一个模型能不能干好你的活，很大程度上取决于你怎么问。提示词就是「给模型的说明书」。

**定义**：Prompt Engineering 是通过设计输入文本（提示词），引导 LLM 输出符合预期的结构化、高质量结果的方法论。

**核心套路**：

| 技巧 | 做法 | 示例 | 解决什么问题 |
| --- | --- | --- | --- |
| 角色设定 | 给模型一个身份 | 「你是一位资深 Java 架构师」 | 让回答贴合专业语境 |
| 明确任务 | 说清要做什么、不要做什么 | 「请用三句话总结，不要展开」 | 输出跑偏 |
| 结构化输出 | 指定格式 | 「用 JSON 返回，字段是 name 和 age」 | 机器解析结果 |
| 思维链 CoT | 要求先想再答 | 「一步一步推理，先分析再给结论」 | 复杂推理正确率 |
| 少样本 few-shot | 给几个例子 | 「例：输入X→输出Y」 | 新任务格式对齐 |
| 约束条件 | 限定范围/字数/语气 | 「100 字以内，面向小学生」 | 控制粒度 |

**示例**：一个完整的结构化提示词模板：

```python
system_prompt = """你是一位严谨的技术文档审校员。
任务：审校用户提交的文档，找出错别字、逻辑错误和表述不清之处。
输出要求：
1. 严格按 JSON 数组返回，每个元素含 line（行号）、issue（问题）、suggestion（建议）；
2. 没有问题则返回空数组 []；
3. 不要输出任何 JSON 之外的文字。"""

user_input = "大语言模型可以用于文本生成、机器翻译等多种人物。"

# 为什么 system 和 user 分开传：system 定"人设和规则"，
# user 放"具体任务"，这是 OpenAI/主流框架约定俗成的消息结构。
messages = [
    {"role": "system", "content": system_prompt},
    {"role": "user", "content": user_input},
]

# 期望模型返回：
# [{"line": 1, "issue": "错别字：'人物' 应为 '任务'", "suggestion": "机器翻译等多种任务"}]
```

::: tip 💡 面试题：什么是 CoT（思维链）？为什么有效？
CoT（Chain-of-Thought）是让模型「把推理过程一步步写出来」再给答案，而不是直接跳到最后结论。它有效是因为自回归模型每生成一个 token 都是「基于前面已生成的内容」，把中间推理步骤显式写出来，等于给了模型更多「思考的草稿空间」，大幅提升数学、逻辑等复杂任务正确率。
:::

### 系统提示词与消息角色（Messages）

**背景**：现代对话模型不再接受「一大段纯文本」，而是接受结构化的**消息列表**。理解消息角色，是调用任何聊天 API 的前提。

**定义**：一次对话由多条消息（Message）组成，每条消息带一个 `role`，主流有三种：

| role | 含义 | 作用 |
| --- | --- | --- |
| `system` | 系统提示词 | 设定人设、规则、输出格式，优先级最高，通常放最前面 |
| `user` | 用户消息 | 用户的问题或输入 |
| `assistant` | 助手消息 | 模型之前的回答，用于拼历史，实现「多轮对话」 |

**特性/规则**：

1. **多轮对话 = 把历史消息全部重新发一次**。模型无状态，第 N 轮请求要带上前面所有 user/assistant 消息。
2. **system 消息是「软约束」**：模型会尽量遵守，但不是硬性的安全开关，依然可能被绕开（这是「提示词注入」攻击的根源）。
3. **有些开源模型（如 Qwen、Llama）没有专门 system 角色**，框架会自动把 system 内容并进首条 user 消息。

**示例**：用 OpenAI SDK 走一遍标准多轮对话：

```python
from openai import OpenAI

client = OpenAI(api_key="sk-xxx")   # 替换成你的 key

messages = [
    {"role": "system", "content": "你是一个言简意赅的助手。"},
    {"role": "user", "content": "1+1 等于几？"},
    {"role": "assistant", "content": "2"},
    {"role": "user", "content": "那乘以 3 呢？"},   # 为什么把上一轮回答也带上：模型无状态，不带它就不知道"1+1=2"
]

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=messages,
    temperature=0.2,          # 低温度，保证稳定
)
print(resp.choices[0].message.content)
```

### 上下文学习与少样本（Few-shot / In-Context Learning）

**背景**：传统模型要适应新任务必须「重新训练」；LLM 却可以不改任何参数，只看 prompt 里的几个例子就会做新任务。这是 LLM 最具颠覆性的能力之一。

**定义**：上下文学习（In-Context Learning）指模型仅通过在 prompt 中观察示例，就能在推理时临时「学会」新任务，无需更新权重。

| 类别 | 做法 | 适用 |
| --- | --- | --- |
| Zero-shot | 不给示例，直接下指令 | 通用任务 |
| One-shot | 给 1 个示例 | 有明确格式要求时 |
| Few-shot | 给 3~8 个示例 | 格式复杂、领域性强、模型偏弱时 |

**示例**：给一个「电影评论情感分类」的 few-shot prompt：

```
请判断以下影评的情感倾向（正面/负面）。

示例：
评论：这部电影的节奏拖沓，看到一半就睡着了。 → 负面
评论：特效炸裂，剧情反转出人意料，强烈推荐！ → 正面

现在请判断：
评论：演员演技在线，但编剧水平不敢恭维。
```

**为什么有效**：模型在预训练时见过海量「模式」，few-shot 示例相当于「激活」了它脑中已有的对应模式，而不是真的「学习」了新知识。

::: tip 💡 面试题：few-shot 是「让模型学会了新知识」吗？
不是。few-shot 只是通过示例「激活」模型已有的能力，推理时并没有更新任何权重。真正把新知识「写进」模型，需要微调（Fine-tuning）。区分这个点，面试能讲清 RAG、few-shot、微调三者的本质区别——few-shot 和 RAG 都「不改模型」，微调才「改模型」。
:::

### LLM 三大核心能力

面试常把「LLM 有什么能力」问得很散，归纳成三块就清晰了：

| 能力 | 含义 | 依赖什么 | 对应增强手段 |
| --- | --- | --- | --- |
| 知识（Knowledge） | 记住事实、概念、常识 | 预训练语料 | 知识过期用 [RAG](/learn_ai/agent/RAG) 补 |
| 推理（Reasoning） | 逻辑推导、多步分析、数学 | 模型规模 + CoT | 思维链、o1/R1 推理模型 |
| 指令遵循（Instruction Following） | 听懂并执行你的要求 | 指令微调 + RLHF | 好的 system prompt、结构化输出 |

**一句话记忆**：**知识决定「知道多少」，推理决定「想得多深」，指令遵循决定「听不听话」**。Agent 编排（见 [Agent编排](/learn_ai/agent/Agent编排)）本质就是在编排和放大这三项能力。

from openai import OpenAI

client = OpenAI(api_key="sk-xxx")

for chunk in stream:

## 原理篇

### Transformer 架构总览

**背景**：LLM 的底层几乎都是 Transformer。理解它，是把「黑盒」拆成「白盒」的第一步。

**定义**：Transformer 是一种完全基于**注意力机制**、摒弃了循环（RNN）和卷积（CNN）的序列建模架构，由 **编码器（Encoder）** 和 **解码器（Decoder）** 两部分组成。现代 LLM 基本只用 Decoder 部分（也称 Decoder-only），因为生成任务天然是「从左到右」。

**整体结构**（以 Decoder-only 的 GPT 为例）：

```
输入 token 序列
      │
      ▼
┌─────────────────────────┐
│  Embedding（词嵌入）      │  把 token id → 高维向量
└─────────────────────────┘
      │
      ▼
┌─────────────────────────┐
│  位置编码（Position）      │  给每个词打上"位置"标记（Transformer 无顺序概念）
└─────────────────────────┘
      │
      ▼
   ┌───────────────────────────────┐
   │   Transformer Block × N 层     │   ← 核心，重复堆叠 N 次（如 32 层、96 层）
   │  ┌─────────────────────────┐  │
   │  │ 1. 多头自注意力 (MHA)    │  │
   │  │ 2. 残差连接 + LayerNorm  │  │
   │  │ 3. 前馈网络 (FFN)        │  │
   │  │ 4. 残差连接 + LayerNorm  │  │
   │  └─────────────────────────┘  │
   └───────────────────────────────┘
      │
      ▼
┌─────────────────────────┐
│  Linear + Softmax         │  最后一个位置的输出 → 词表上的概率分布
└─────────────────────────┘
      │
      ▼
  下一个 token 的概率
```

**小结**：抓住三句话——**Embedding 把词变成向量，自注意力让词之间互相「看」出关系，FFN 对每个词做非线性加工**。这三大件堆 N 层，就是 LLM。

### 自注意力机制（Self-Attention）：LLM 的心脏

**背景**：一句话里，词和词之间的关联强度不同。「苹果发布会发布了新手机」里，「苹果」和「手机」强相关，和「发布会」也相关，和「了」几乎无关。自注意力就是让每个词**动态地、按语义**去决定「该关注哪些词、关注多重」。

**定义**：自注意力通过为每个词计算它与所有词（包括自己）的相似度，得到一个「加权和」作为该词的新表示。

**完整流程（Q/K/V 三件套）**：

```
对每个 token 的向量 x，生成三个新向量：
  Q（Query，查询）："我要找什么"
  K（Key，键）    ："我是什么，供别人匹配"
  V（Value，值）  ："我携带的实际内容"

注意力分数 = softmax( Q · Kᵀ / √d_k )   ← 相似度归一化成"权重"
输出      = 注意力分数 · V                ← 按权重把 V 加权求和
```

**逐步拆解**（以 "我爱学习" 为例）：

```
第 1 步：每个词生成 Q、K、V（通过与权重矩阵 Wq、Wk、Wv 相乘）
  我 → Q₁ K₁ V₁
  爱 → Q₂ K₂ V₂
  学 → Q₃ K₃ V₃

第 2 步：计算"我"对所有词（含自己）的注意力分数
  score("我","我") = Q₁·K₁
  score("我","爱") = Q₁·K₂
  score("我","学") = Q₁·K₃

第 3 步：softmax 归一化 → 得到权重 [0.6, 0.3, 0.1]
  表示"我"该 60% 关注自己、30% 关注"爱"、10% 关注"学"

第 4 步：加权求和 → 新的"我"
  新我 = 0.6·V₁ + 0.3·V₂ + 0.1·V₃
```

**为什么要除以 √d_k**：Q·K 点积的值会随维度 d_k 增大而变大，导致 softmax 进入饱和区、梯度消失。除以 √d_k 是「缩放」，让分布更平滑稳定。

**为什么用 Q/K/V 三套而非一套**：Q 和 K 分离，允许「匹配」和「被匹配」用不同的表示空间；V 又独立于前两者，承载真正要传递的信息。这让注意力更灵活。

::: tip 💡 面试题：自注意力里 Q、K、V 分别是什么？为什么不是直接用同一个向量？
Q（查询）决定「我在找什么」，K（键）决定「我能提供什么标签」，V（值）是「我实际传递的内容」。三者分离让模型可以用不同的线性变换学习「谁和谁相关」以及「相关时传什么信息」，表达能力比单一向量强得多。类比：图书馆查书，Q 是你的查询词，K 是书的索引标签，V 是书的内容本身。
:::

### 多头注意力（Multi-Head Attention）

**背景**：单头注意力只能学到「一种关注模式」。但语言里，一个词可能同时关注「主语」「时态」「指代」等多个维度。

**定义**：多头注意力把 Q/K/V 拆成 h 个「头」，每个头在低维子空间里独立做自注意力，最后把所有头的结果拼接起来。

```
Multi-Head = 把维度切成 h 份，各算各的注意力，再拼回

  Q ──切 h 份──► head1: Q₁ K₁ V₁ → 注意力输出 out₁
  K ──切 h 份──► head2: Q₂ K₂ V₂ → 注意力输出 out₂
  V ──切 h 份──► ...                  ...
              ► head_h: Qₕ Kₕ Vₕ → 注意力输出 outₕ

  Concat(out₁, out₂, ..., outₕ) → 过一层 Linear → 最终输出
```

**为什么有效**：不同的头会自动学出不同的关注模式——有的头关注「语法」，有的关注「指代」，有的关注「位置相邻」。这就像多个专家从不同角度审视同一句话，最后汇总。GPT-3 用了 96 个头。

### 位置编码（Positional Encoding）

**背景**：自注意力本身**对顺序无感**——「我爱你」和「你爱我」在注意力计算里，三个词的注意力权重关系是「对称」的，模型分不清谁在前谁在后。

**定义**：位置编码是给每个 token 的向量注入「位置信息」的技术，让模型知道词与词的先后顺序。

**两种主流方案**：

| 方案 | 做法 | 特点 | 代表 |
| --- | --- | --- | --- |
| 绝对位置编码 | 给每个位置一个固定的向量（正弦/余弦，或可学习参数），加到词向量上 | 简单，但超长位置泛化差 | 原版 Transformer、GPT-1/2 |
| RoPE（旋转位置编码） | 通过旋转矩阵把「相对位置」信息编码进 Q/K 的点积里 | 只依赖相对位置，外推长文本能力更强 | GPT-NeoX、LLaMA、Qwen、DeepSeek |

**RoPE 是当前主流**（LLaMA 系几乎全用），核心思想：**不把位置信息加在词向量上，而是通过「旋转」让 Q·K 的点积天然携带两个词的相对位置差**。这也是为什么这些模型能支持超长上下文——相对位置天然可外推。

::: tip 💡 面试题：为什么 Transformer 需要位置编码？
因为自注意力是「词袋」式的——它对所有位置一视同仁，若没有位置信息，「我爱你」和「你爱我」在模型眼里是一样的。位置编码给 token 注入顺序信息，是模型理解语序、语法和语义的基石。现代主流用 RoPE，因为它编码的是相对位置，长文本外推能力更强。
:::

### 前馈网络（FFN）与残差连接、LayerNorm

**背景**：注意力负责「词与词之间的信息交换」，但每个词自身还需要「独立的信息加工」，这个活由前馈网络干。残差和 LayerNorm 则负责「让这么深的网络能训得动」。

#### FFN（前馈网络）

每个 token 的向量经过注意力后，还要过一个「升维→激活→降维」的两层全连接网络：

```
FFN(x) = W₂ · ReLU(W₁·x + b₁) + b₂

  维度变化：d_model → 4·d_model → d_model
  （先扩大 4 倍，激活后再缩回来）
```

为什么要先升维再降维：升维给了网络更大的「特征空间」，让非线性激活函数能学到更复杂的映射，再降维回原尺寸，方便层与层之间衔接。

#### 残差连接（Residual Connection）

每层输出 = 本层计算结果 + 原始输入，即 `x + Sublayer(x)`。作用是给梯度留一条「高速公路」，缓解深层网络的梯度消失，让 96 层甚至上千层网络也能训练。

#### LayerNorm（层归一化）

对每个 token 自己的向量做归一化（减均值、除标准差），让数值稳定，加速收敛。与 BatchNorm 不同，LayerNorm 是对「单个样本内部」归一化，天然适合变长序列。

```
单个 Transformer Block 内部完整数据流：

  x ──► [Multi-Head Attention] ──► 残差(+) ──► LayerNorm ──► [FFN] ──► 残差(+) ──► LayerNorm ──► 输出
         ▲                          │
         └──────── 短接 x ───────────┘（这就是"残差连接"）
```

### 训练三阶段：预训练 → 指令微调 → RLHF

**背景**：ChatGPT 之所以「会聊天、听得懂人话」，不是预训练一蹴而就，而是三步走。理解这三个阶段，能回答面试里最经典的「大模型是怎么训练的」。

```
阶段 1：预训练 (Pre-training)      → 让模型"学会语言和知识"
阶段 2：指令微调 (SFT)             → 让模型"听得懂指令"
阶段 3：RLHF / 偏好对齐            → 让模型"回答得符合人类喜好、更安全"
```

#### 阶段一：预训练（Pre-training）

用互联网海量文本，让模型做「下一词预测」。这个阶段最贵（GPT-3 训一次上千万美元），学到的只是「语言模型」，它只会「续写」，不会「对话」。

- 目标函数：最大化 `P(下一个词 | 前面所有词)`
- 数据：网页、书籍、代码、论文等万亿级 token
- 产物：**基座模型（Base Model）**，如 LLaMA、GPT-3

#### 阶段二：指令微调（SFT，Supervised Fine-Tuning）

人工构造「指令-回答」对（如「把这句话翻译成英文 → xxx」），在基座模型上继续训练。目的是让模型从「续写器」变成「能听懂指令的助手」。

- 数据量不大（几万到几十万条高质量标注）
- 产物：**指令模型（Instruction Model / Chat Model）**，如 LLaMA-Chat、GPT-3.5 早期版本

#### 阶段三：RLHF（Reinforcement Learning from Human Feedback）

让模型对同一问题生成多个回答，人类标注员排序（哪个好哪个差），训练一个「奖励模型」学习人类偏好，再用强化学习（PPO 等）微调模型，让它的输出更符合人类喜好、更安全、更少胡说。

```
RLHF 完整流程：

  ① 模型生成多个回答
  ② 人类对回答排序（偏好数据）
  ③ 训练奖励模型 Reward Model：学会给回答打分
  ④ 用 PPO 强化学习，让主模型朝着"高奖励"方向更新
```

::: tip 💡 面试题：预训练、SFT、RLHF 三者的区别？
预训练是「无监督地学语言」，最贵、数据最大，产出基座模型；SFT 是「有监督地学听话」，用少量指令-回答对让模型听懂指令；RLHF 是「学人类的偏好」，通过人类排序训练奖励模型，再用强化学习让回答更符合人类价值观、更安全。三者的产出物和成本量级完全不同。
:::

### 为什么 LLM 会幻觉（Hallucination）

**背景**：LLM 最被诟病的问题就是「一本正经地胡说八道」——幻觉。

**定义**：幻觉是指模型生成的文本流畅通顺，但内容与事实不符或纯属捏造。

**根本原因**：LLM 的本质是「预测下一个最合理的词」，它优化的是「**说得像不像人话**」，而不是「**说得对不对**」。当它不知道答案时，它不会（也没有机制）说「我不知道」，而是继续按语言规律编一个「看起来合理」的下文。

**具体诱因**：

| 诱因 | 说明 |
| --- | --- |
| 训练目标偏差 | 训练目标是「预测合理」，不是「保证真实」 |
| 知识缺失/过期 | 没学过的知识，只能硬编 |
| 采样随机性 | 温度高时，冷门错误答案也有概率被选中 |
| 错误滚雪球 | 前面错了一个 token，后面基于错误继续编 |
| 缺乏「不知道」的出口 | 模型没有内建的「我不知道」强约束 |

**应对手段**：这正是 [RAG](/learn_ai/agent/RAG) 存在的意义——把真实资料塞进上下文，让模型「照稿念」而不是「自由发挥」。此外还有：降低温度、要求引用出处、加「不知道就说不知道」的 system prompt 等。

### 参数量、算力与显存的关系

**背景**：为什么模型「大」很贵？一个直观的量化，能帮你理解选型和部署成本。

**量化关系**：

| 量 | 估算公式（以 bf16/半精度为例） |
| --- | --- |
| 权重显存 | 参数量 × 2 字节（bf16） |
| 梯度显存 | 参数量 × 2 字节（训练时才需要） |
| 优化器状态 | 参数量 × 8 字节（Adam，训练时才需要） |
| 推理总显存 | ≈ 权重显存 + KV Cache + 激活值 |

**示例**：7B 模型的显存占用：

```
推理（只做前向，不需要梯度）：
  7B × 2 字节 = 14 GB（仅权重，bf16）
  + KV Cache（随上下文长度增长）→ 一般 16GB 显存起步

训练（需要梯度 + Adam 优化器）：
  14 GB（权重） + 14 GB（梯度） + 56 GB（Adam 状态）= 84 GB 起
  → 这就是为什么训练要上百 GB 显存的多卡集群
```

**小结**：**推理看权重显存，训练还要加梯度和优化器状态，大约是推理的 4~6 倍**。这解释了为什么「部署推理」人人都能干，「从头训练」只有大厂能干。工程上通过**量化**（把 bf16 压成 int8/int4）来省显存。

---

### 推理优化：KV Cache 与量化

**背景**：自回归每生成一个 token 都要重算整个序列，其中大量计算是重复的。KV Cache 和量化是两项最核心的推理优化。

#### KV Cache

自注意力里，每个 token 的 K 和 V 只由「它自己」决定，与后面生成的新 token 无关。所以：

```
不做 KV Cache：每生成一个新 token，把所有历史 token 的 K、V 全部重算一遍 → O(n²) 重复浪费

做 KV Cache：把已经算过的 K、V 存起来，新 token 只需算自己的 K、V，
             再和缓存里的旧 K、V 拼起来算注意力 → 只算增量
```

这就是为什么「生成第一个 token 慢（要处理全部输入），后续 token 快（只算增量）」，也是为什么「长上下文推理又慢又占显存」——KV Cache 随长度线性增长。

#### 量化（Quantization）

把模型权重从高精度（fp16/bf16，2 字节）压缩到低精度（int8 1 字节、int4 半字节），牺牲少量精度换取显存和速度的大幅下降。GPTQ、AWQ、GGUF（llama.cpp）是主流方案。

| 精度 | 每参数字节 | 7B 模型权重显存 | 精度损失 |
| --- | --- | --- | --- |
| fp16/bf16 | 2 字节 | 14 GB | 无 |
| int8 | 1 字节 | 7 GB | 极小 |
| int4 | 0.5 字节 | 3.5 GB | 少量 |

## 面试常问

- **Q：LLM 的本质是什么？** 结论：一个「预测下一个 token 概率分布」的神经网络。展开：它没有真正的「理解」，一切能力都源于在海量语料上反复做下一词预测，再通过自回归把预测串成完整文本。

- **Q：token 和词是什么关系？** 结论：token 是模型处理文本的最小单位，一个词可能被拆成多个 token。展开：分词用 BPE 等算法，英文低频词会被拆成子词，中文约一字一 token；上下文长度、计费都以 token 计。

- **Q：temperature、top-k、top-p 三者的作用？** 结论：都是控制采样随机性的参数。展开：temperature 在归一化前缩放 logits 控制分布陡峭度；top-k 固定保留前 k 个候选；top-p 按累计概率动态裁候选集。三者作用阶段和机制不同。

- **Q：多轮对话是怎么实现的？** 结论：模型无状态，靠「每次把完整历史消息重新发给模型」实现。展开：每轮请求都携带前面所有 user/assistant 消息，模型据此「看起来记得」上文；历史过长时需要压缩或裁剪。

- **Q：Transformer 的核心组件有哪些？** 结论：Embedding、位置编码、多头自注意力、FFN、残差连接 + LayerNorm。展开：注意力负责词间交互，FFN 负责每个词的独立加工，残差和归一化保证深层网络可训练。

- **Q：自注意力为什么要 Q、K、V 三套向量？** 结论：Q 表示「找什么」，K 表示「是什么」，V 表示「传什么」，三者分离表达能力更强。展开：通过不同线性变换让匹配和传递各自优化，单套向量无法同时兼顾。

- **Q：预训练、SFT、RLHF 的区别？** 结论：预训练无监督学语言（最贵），SFT 有监督学听话，RLHF 学人类偏好。展开：三阶段产出物分别是基座模型、指令模型、对齐后的聊天模型，成本和数据规模依次递减。

- **Q：幻觉是怎么产生的？怎么缓解？** 结论：模型优化「说得通顺」而非「说得正确」，不知道时也会硬编。展开：缓解靠 RAG 塞真实资料、降低温度、要求引用出处、加「不知道就说不知道」约束。
